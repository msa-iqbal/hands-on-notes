# ECMAScript 2017 (ES8)

ECMAScript 2017, commonly known as ES8, is the eighth edition of the ECMAScript language specification.

It was released in June 2017 and introduced several improvements to JavaScript, particularly in asynchronous programming, object manipulation, string handling, and numerical operations.

One of its most important additions was `async` and `await`, which made asynchronous code easier to write and understand.

# 🗁 What Is ECMAScript 2017?

ECMAScript 2017 continued the yearly release cycle introduced after ES2015.

Instead of introducing a complete language redesign, it added focused improvements to existing JavaScript capabilities.

Important terminology:

* **ECMAScript:** The standardized specification that defines JavaScript.
* **ES8:** The informal name for ECMAScript 2017.
* **ES2017:** The official edition name.
* **TC39:** The committee responsible for evolving ECMAScript.

# 🗁 Major ES2017 Features

| Feature | Description |
| --- | --- |
| Async functions | Allows asynchronous functions to be written using `async` |
| `await` | Waits for a promise to settle inside an async function |
| `Object.values()` | Returns an array of an object's own enumerable string-keyed values |
| `Object.entries()` | Returns an array of an object's own enumerable string-keyed key-value pairs |
| `Object.getOwnPropertyDescriptors()` | Returns property descriptors for an object's own properties |
| `String.prototype.padStart()` | Pads the beginning of a string |
| `String.prototype.padEnd()` | Pads the end of a string |

# 🗁 Async and Await

ES2017 introduced `async` and `await`, providing a more readable syntax for working with promises.

Before async and await, asynchronous operations commonly used promise chains.

Example using promises:

```javascript
function getUser() {
  return fetch("https://jsonplaceholder.typicode.com/users/1")
    .then(response => response.json())
    .then(user => {
      console.log(user);
      return user;
    })
    .catch(error => {
      console.error(error);
    });
}

getUser();
```

Using async and await:

```javascript
async function getUser() {
  try {
    const response = await fetch(
      "https://jsonplaceholder.typicode.com/users/1"
    );

    const user = await response.json();

    console.log(user);

    return user;
  } catch (error) {
    console.error(error);
  }
}

getUser();
```

The second example expresses asynchronous operations in a sequential style.

# 🗁 The async Keyword

The `async` keyword declares an asynchronous function.

An async function always returns a Promise.

Example:

```javascript
async function greet() {
  return "Hello, JavaScript!";
}

const result = greet();

console.log(result);
```

The returned value is automatically wrapped in a fulfilled Promise.

Equivalent promise-based implementation:

```javascript
function greet() {
  return Promise.resolve("Hello, JavaScript!");
}
```

An async function can also explicitly return a Promise.

```javascript
async function getData() {
  return Promise.resolve({
    name: "Alice"
  });
}

getData().then(data => {
  console.log(data);
});
```

# 🗁 The await Keyword

The `await` keyword pauses the execution of its surrounding async function until a promise settles.

If the promise fulfills, `await` evaluates to its fulfillment value.

```javascript
async function getMessage() {
  const message = await Promise.resolve("Hello!");

  console.log(message);
}

getMessage();
```

Output:

```text
Hello!
```

If the promise rejects, `await` throws the rejection reason.

```javascript
async function getData() {
  const result = await Promise.reject(
    new Error("Request failed")
  );

  return result;
}

getData().catch(error => {
  console.error(error.message);
});
```

In ordinary JavaScript scripts and modules, `await` is used inside async functions. Modern JavaScript modules also support top-level await, which was standardized later in ES2022.

# 🗁 Error Handling with Async and Await

Async functions work naturally with `try...catch`.

```javascript
async function fetchUser() {
  try {
    const response = await fetch(
      "https://jsonplaceholder.typicode.com/users/1"
    );

    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    const user = await response.json();

    return user;
  } catch (error) {
    console.error("Failed to fetch user:", error.message);
    throw error;
  }
}

fetchUser().catch(error => {
  console.error("Operation failed:", error.message);
});
```

This approach makes asynchronous error handling similar to synchronous exception handling.

# 🗁 Sequential and Parallel Execution

An important consideration when using `await` is whether asynchronous operations depend on each other.

**Sequential execution**

Each operation waits for the previous operation to complete.

```javascript
async function loadData() {
  const users = await fetchUsers();
  const posts = await fetchPosts();

  return { users, posts };
}
```

If both operations are independent, this introduces unnecessary waiting.

**Parallel execution**

`Promise.all()` allows independent promises to run concurrently.

```javascript
async function loadData() {
  const [users, posts] = await Promise.all([
    fetchUsers(),
    fetchPosts()
  ]);

  return { users, posts };
}
```

Use sequential execution when one operation depends on another. Use concurrent execution when operations are independent.

# 🗁 Object.values()

ES2017 introduced `Object.values()` to retrieve the values of an object's own enumerable string-keyed properties.

Example:

```javascript
const user = {
  name: "Alice",
  age: 25,
  role: "Developer"
};

const values = Object.values(user);

console.log(values);
```

Output:

```javascript
["Alice", 25, "Developer"]
```

**Syntax**

```javascript
Object.values(object);
```

The method returns an array containing the property values.

Example with numeric-like property keys:

```javascript
const numbers = {
  3: "Three",
  1: "One",
  2: "Two"
};

console.log(Object.values(numbers));
```

Output:

```javascript
["One", "Two", "Three"]
```

Integer-index-like string keys are enumerated in ascending numeric order.

# 🗁 Object.entries()

`Object.entries()` returns an array of an object's own enumerable string-keyed key-value pairs.

Example:

```javascript
const user = {
  name: "Alice",
  age: 25,
  role: "Developer"
};

const entries = Object.entries(user);

console.log(entries);
```

Output:

```javascript
[
  ["name", "Alice"],
  ["age", 25],
  ["role", "Developer"]
]
```

**Syntax**

```javascript
Object.entries(object);
```

Each entry is represented as an array containing:

* The property key.
* The property value.

**Using Object.entries() with for...of**

```javascript
const user = {
  name: "Alice",
  age: 25
};

for (const [key, value] of Object.entries(user)) {
  console.log(`${key}: ${value}`);
}
```

**Converting entries back into an object**

```javascript
const user = {
  name: "Alice",
  age: 25
};

const entries = Object.entries(user);

const copy = Object.fromEntries(entries);

console.log(copy);
```

`Object.fromEntries()` was introduced in ES2019, not ES2017.

# 🗁 Object.getOwnPropertyDescriptors()

ES2017 introduced `Object.getOwnPropertyDescriptors()`.

It returns all own property descriptors of an object.

A property descriptor contains metadata describing a property.

For a data property, common descriptor fields include:

* `value`: The property's value.
* `writable`: Whether the value can be changed.
* `enumerable`: Whether the property appears in enumeration operations.
* `configurable`: Whether the property descriptor can be modified or the property can be deleted.

Example:

```javascript
const user = {
  name: "Alice",
  age: 25
};

const descriptors = Object.getOwnPropertyDescriptors(user);

console.log(descriptors);
```

A descriptor for `name` looks like:

```javascript
{
  value: "Alice",
  writable: true,
  enumerable: true,
  configurable: true
}
```

**Using descriptors to copy property behavior**

A normal object spread copies enumerable property values but does not preserve getters, setters, or other property descriptor attributes.

`Object.getOwnPropertyDescriptors()` can help preserve those attributes.

```javascript
const user = {
  firstName: "Alice",

  get fullName() {
    return this.firstName;
  }
};

const copy = Object.defineProperties(
  {},
  Object.getOwnPropertyDescriptors(user)
);

console.log(copy.fullName); // Alice
```

# 🗁 String.prototype.padStart()

`padStart()` pads the beginning of a string until it reaches a specified length.

**Syntax**

```javascript
string.padStart(targetLength, padString);
```

Parameters:

* `targetLength`: The desired string length.
* `padString`: Optional string used for padding. Defaults to a space.

Example:

```javascript
const number = "5";

console.log(number.padStart(3, "0")); // 005
```

More examples:

```javascript
console.log("42".padStart(5, "0"));    // 00042
console.log("JavaScript".padStart(15)); //      JavaScript
console.log("Hello".padStart(8, "*")); // ***Hello
```

If the original string is already equal to or longer than the target length, it remains unchanged.

# 🗁 String.prototype.padEnd()

`padEnd()` pads the end of a string until it reaches a specified length.

**Syntax**

```javascript
string.padEnd(targetLength, padString);
```

Parameters:

* `targetLength`: The desired string length.
* `padString`: Optional string used for padding. Defaults to a space.

Example:

```javascript
const number = "5";

console.log(number.padEnd(3, "0")); // 500
```

More examples:

```javascript
console.log("42".padEnd(5, "0"));    // 42000
console.log("Hello".padEnd(8, "*")); // Hello***
console.log("JavaScript".padEnd(15)); // JavaScript     
```

# 🗁 Trailing Commas in Function Parameters

ES2017 allowed trailing commas in function parameter lists and function calls.

Before ES2017, trailing commas were already supported in array and object literals, but not in function parameter lists and arguments.

Example:

```javascript
function calculate(
  first,
  second,
) {
  return first + second;
}

const result = calculate(
  10,
  20,
);

console.log(result); // 30
```

Trailing commas make it easier to add, remove, or reorder parameters in multiline code.

# 🗁 SharedArrayBuffer

ES2017 introduced `SharedArrayBuffer`, which allows multiple execution contexts, such as workers, to share the same underlying memory.

Unlike ordinary ArrayBuffers, shared memory can be accessed by multiple workers.

Example:

```javascript
const sharedBuffer = new SharedArrayBuffer(16);

const numbers = new Int32Array(sharedBuffer);

numbers[0] = 100;

console.log(numbers[0]); // 100
```

A SharedArrayBuffer does not directly provide synchronization between concurrent operations.

For shared memory coordination, JavaScript provides the `Atomics` object.

Availability of SharedArrayBuffer in browsers depends on security requirements and cross-origin isolation configuration.

# 🗁 Atomics

The `Atomics` object provides atomic operations for shared memory accessed through supported typed arrays.

Atomic operations help prevent certain race conditions when multiple workers access shared memory.

Example:

```javascript
const buffer = new SharedArrayBuffer(4);

const counter = new Int32Array(buffer);

Atomics.store(counter, 0, 10);

Atomics.add(counter, 0, 5);

console.log(Atomics.load(counter, 0)); // 15
```

Common Atomics methods include:

| Method | Purpose |
| --- | --- |
| `Atomics.load()` | Reads a value atomically |
| `Atomics.store()` | Stores a value atomically |
| `Atomics.add()` | Adds a value atomically |
| `Atomics.sub()` | Subtracts a value atomically |
| `Atomics.exchange()` | Replaces a value and returns the previous value |
| `Atomics.compareExchange()` | Replaces a value only when it matches an expected value |
| `Atomics.wait()` | Waits while a shared integer location contains an expected value |
| `Atomics.notify()` | Notifies agents waiting on a shared memory location |

`Atomics.wait()` is not available on the browser main thread. It is intended for appropriate worker contexts.

# 🗁 Practical Example: Combining ES2017 Features

The following example combines async functions, `await`, `Object.entries()`, and `padStart()`.

```javascript
async function getUser() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/users/1"
  );

  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }

  return response.json();
}

async function displayUser() {
  try {
    const user = await getUser();

    const entries = Object.entries({
      ID: user.id,
      Name: user.name,
      Email: user.email
    });

    for (const [key, value] of entries) {
      console.log(`${key.padEnd(8)}: ${value}`);
    }
  } catch (error) {
    console.error(error.message);
  }
}

displayUser();
```

Possible output:

```text
ID      : 1
Name    : Leanne Graham
Email   : Sincere@april.biz
```

Features used:

* `async` and `await` for asynchronous operations.
* `Object.entries()` for converting object properties into key-value pairs.
* `for...of` for iterating over entries.
* `padEnd()` for aligning output.
* `try...catch` for error handling.

# 🗁 ES2017 vs ES2016

| ES2016 | ES2017 |
| --- | --- |
| `Array.prototype.includes()` | Async functions |
| Exponentiation operator (`**`) | `Object.values()` |
| Exponentiation assignment (`**=`) | `Object.entries()` |
| | `Object.getOwnPropertyDescriptors()` |
| | `String.prototype.padStart()` |
| | `String.prototype.padEnd()` |
| | Trailing commas in function parameters |
| | SharedArrayBuffer and Atomics |

ES2016 introduced two focused language features, while ES2017 expanded asynchronous programming and object and string utilities.

# 🗁 Browser and Runtime Compatibility

ES2017 features are supported by modern JavaScript engines.

Older browsers and runtime environments may require compatibility solutions.

Babel can transform async function syntax into older JavaScript patterns, depending on the configured targets and transformations.

Some runtime features, such as `Object.values()`, `Object.entries()`, and string padding methods, may require polyfills in older environments.

SharedArrayBuffer availability also depends on runtime-specific security requirements.

# 🗁 Best Practices

* Use `async` and `await` to make promise-based code easier to read.
* Handle asynchronous errors with `try...catch`.
* Use `Promise.all()` when independent asynchronous operations can run concurrently.
* Avoid unnecessary sequential `await` operations.
* Use `Object.values()` when only property values are needed.
* Use `Object.entries()` when both property names and values are needed.
* Use `Object.getOwnPropertyDescriptors()` when property behavior must be preserved.
* Use `padStart()` and `padEnd()` for string alignment and formatting.
* Use trailing commas in multiline function declarations and calls when appropriate.
* Use Atomics when coordinating access to shared memory.
* Check runtime compatibility when supporting older environments.
