# ECMAScript 2018 (ES9)

ECMAScript 2018, commonly known as ES9, is the ninth edition of the ECMAScript language specification.

It was released in June 2018 and introduced improvements to asynchronous iteration, object manipulation, regular expressions, and promise handling.

ES2018 made JavaScript more expressive, particularly when working with asynchronous data streams, nested objects, and complex text patterns.

# 🗁 What Is ECMAScript 2018?

ECMAScript 2018 continued the annual evolution of JavaScript after ES2017.

Its features focused on improving existing language capabilities rather than introducing a major language redesign.

Important terminology:

* **ECMAScript:** The standardized specification that defines JavaScript.
* **ES9:** The informal name for ECMAScript 2018.
* **ES2018:** The official edition name.
* **TC39:** The committee responsible for evolving ECMAScript.

# 🗁 Object Rest Properties

Object rest properties allow you to collect the remaining properties of an object into a new object.

This feature uses the rest syntax (`...`) in object destructuring.

Example:

```javascript
const user = {
  id: 101,
  name: "Alice",
  email: "alice@example.com",
  role: "Developer"
};

const { id, name, ...remaining } = user;

console.log(id);
console.log(name);
console.log(remaining);
```

Output:

```javascript
101
Alice

{
  email: "alice@example.com",
  role: "Developer"
}
```

The `remaining` object contains all enumerable own properties that were not extracted earlier in the destructuring pattern.

**Practical example:**

Removing sensitive properties before returning user data:

```javascript
function getPublicUser(user) {
  const { password, accessToken, ...publicData } = user;

  return publicData;
}

const user = {
  id: 101,
  name: "Alice",
  email: "alice@example.com",
  password: "secret",
  accessToken: "token123"
};

console.log(getPublicUser(user));
```

Output:

```javascript
{
  id: 101,
  name: "Alice",
  email: "alice@example.com"
}
```

Object rest creates a shallow object. Nested objects and arrays are not deeply cloned.

# 🗁 Object Spread Properties

Object spread properties allow you to copy enumerable own properties from one or more objects into a new object.

The spread syntax (`...`) is placed inside an object literal.

Example:

```javascript
const user = {
  name: "Alice",
  age: 25
};

const updatedUser = {
  ...user,
  role: "Developer"
};

console.log(updatedUser);
```

Output:

```javascript
{
  name: "Alice",
  age: 25,
  role: "Developer"
}
```

**Combining multiple objects:**

```javascript
const personalInfo = {
  name: "Alice",
  age: 25
};

const professionalInfo = {
  role: "Developer",
  experience: 3
};

const user = {
  ...personalInfo,
  ...professionalInfo
};

console.log(user);
```

Output:

```javascript
{
  name: "Alice",
  age: 25,
  role: "Developer",
  experience: 3
}
```

**Overriding properties:**

When multiple objects contain the same property, the value from the last occurrence wins.

```javascript
const defaults = {
  theme: "light",
  language: "en",
  notifications: true
};

const preferences = {
  theme: "dark"
};

const settings = {
  ...defaults,
  ...preferences
};

console.log(settings);
```

Output:

```javascript
{
  theme: "dark",
  language: "en",
  notifications: true
}
```

**Important:** Object spread performs a shallow copy. It does not preserve property descriptors, prototypes, or non-enumerable properties.

# 🗁 Object Rest vs Object Spread

Both features use the `...` syntax, but they serve different purposes.

| Object Rest | Object Spread |
| --- | --- |
| Collects remaining properties | Copies properties into an object |
| Used in destructuring patterns | Used in object literals |
| Creates a new object from remaining properties | Creates or contributes properties to a new object |
| Example: `const { id, ...rest } = user` | Example: `const copy = { ...user }` |

Example:

```javascript
const user = {
  id: 101,
  name: "Alice",
  role: "Developer"
};

// Object rest
const { id, ...details } = user;

// Object spread
const copy = { ...details };

console.log(details);
console.log(copy);
```

# 🗁 Asynchronous Iteration

ES2018 introduced asynchronous iteration through the asynchronous iterable protocol.

An asynchronous iterable produces values over time, where each iteration step can involve an asynchronous operation.

This is useful for:

* Reading data from streams.
* Processing paginated API results.
* Consuming asynchronous data sources.
* Working with generators that yield promises or asynchronously produced values.

JavaScript provides two related protocols:

**Iterable protocol**

An iterable object provides a synchronous iterator through `Symbol.iterator`.

**Async iterable protocol**

An async iterable object provides an asynchronous iterator through `Symbol.asyncIterator`.

An asynchronous iterator returns an object whose `next()` method returns a Promise for an iterator result.

# 🗁 The for await...of Loop

The `for await...of` loop iterates over asynchronous iterables.

It waits for each iteration result before executing the loop body.

Example:

```javascript
async function processValues() {
  const values = [
    Promise.resolve(10),
    Promise.resolve(20),
    Promise.resolve(30)
  ];

  for await (const value of values) {
    console.log(value);
  }
}

processValues();
```

Output:

```text
10
20
30
```

`for await...of` can consume both asynchronous iterables and synchronous iterables. When used with a synchronous iterable, it also awaits promise values yielded by that iterable.

**Using an asynchronous generator:**

```javascript
async function* generateNumbers() {
  yield 10;
  yield 20;
  yield 30;
}

async function processNumbers() {
  for await (const number of generateNumbers()) {
    console.log(number);
  }
}

processNumbers();
```

Output:

```text
10
20
30
```

The `async function*` syntax declares an asynchronous generator function.

# 🗁 Promise.prototype.finally()

ES2018 introduced `Promise.prototype.finally()`.

The `finally()` method executes a callback after a promise settles, regardless of whether it fulfills or rejects.

It is especially useful for cleanup operations.

Example:

```javascript
fetch("/api/users")
  .then(response => response.json())
  .then(users => {
    console.log(users);
  })
  .catch(error => {
    console.error(error);
  })
  .finally(() => {
    console.log("Request completed");
  });
```

The callback runs after either successful completion or failure.

**Example with loading state:**

```javascript
let isLoading = true;

fetch("/api/users")
  .then(response => response.json())
  .then(users => {
    console.log(users);
  })
  .catch(error => {
    console.error(error);
  })
  .finally(() => {
    isLoading = false;
    console.log("Loading:", isLoading);
  });
```

Important characteristics:

* `finally()` runs whether the promise fulfills or rejects.
* It does not receive the fulfillment value or rejection reason as arguments.
* It returns a new promise.
* If the callback returns normally, the original promise's settlement is preserved.
* If the callback throws or returns a rejected promise, the resulting promise rejects with that error.

# 🗁 RegExp Named Capture Groups

ES2018 introduced named capture groups in regular expressions.

Named capture groups allow you to assign meaningful names to matched portions of text.

The syntax uses `(?<name>...)`.

Example:

```javascript
const date = "2026-11-14";

const pattern = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;

const result = date.match(pattern);

console.log(result.groups.year);
console.log(result.groups.month);
console.log(result.groups.day);
```

Output:

```text
2026
11
14
```

Without named capture groups, developers commonly access captured values using numeric indexes.

```javascript
const pattern = /(\d{4})-(\d{2})-(\d{2})/;

const result = "2026-11-14".match(pattern);

console.log(result[1]); // 2026
console.log(result[2]); // 11
console.log(result[3]); // 14
```

Named groups improve readability and make regular expressions easier to maintain.

# 🗁 RegExp Lookbehind Assertions

Lookbehind assertions allow a regular expression to match a pattern based on what appears immediately before it.

ES2018 introduced two types:

* Positive lookbehind: `(?<=...)`
* Negative lookbehind: `(?<!...)`

**Positive lookbehind**

Matches when the specified pattern exists before the current position.

```javascript
const text = "$100 €200 $300";

const result = text.match(/(?<=\$)\d+/g);

console.log(result);
```

Output:

```javascript
["100", "300"]
```

The expression matches numbers preceded by `$`.

**Negative lookbehind**

Matches when the specified pattern does not exist before the current position.

```javascript
const text = "$100 €200 $300";

const result = text.match(/(?<!\$)\d+/g);

console.log(result);
```

Output:

```javascript
["200"]
```

The expression matches numbers not preceded by `$`.

# 🗁 RegExp Unicode Property Escapes

ES2018 introduced Unicode property escapes for regular expressions.

They allow matching characters based on their Unicode properties instead of relying only on manually written character ranges.

Unicode property escapes use:

* `\p{...}` for matching characters with a specified Unicode property.
* `\P{...}` for matching characters that do not have that property.

The `u` flag is required.

Example: Matching Unicode letters.

```javascript
const text = "Hello こんにちは 123";

const letters = text.match(/\p{Letter}+/gu);

console.log(letters);
```

Output:

```javascript
["Hello", "こんにちは"]
```

Example: Matching numbers.

```javascript
const text = "Room 101, Floor 5";

const numbers = text.match(/\p{Number}+/gu);

console.log(numbers);
```

Output:

```javascript
["101", "5"]
```

Example: Matching characters that are not letters.

```javascript
const text = "Hello123!";

const result = text.match(/\P{Letter}+/gu);

console.log(result);
```

Output:

```javascript
["123!"]
```

Common Unicode properties include:

| Property | Description |
| --- | --- |
| `Letter` | Unicode letters |
| `Number` | Unicode numbers |
| `Decimal_Number` | Decimal digits |
| `White_Space` | Unicode whitespace characters |
| `Punctuation` | Punctuation characters |
| `Script=Greek` | Characters belonging to the Greek script |
| `Script=Latin` | Characters belonging to the Latin script |

Unicode property escapes are particularly useful when processing multilingual text.

# 🗁 RegExp dotAll Flag

Before ES2018, the regular expression dot (`.`) did not match line terminators by default.

ES2018 introduced the `s` flag, also known as the dotAll flag.

With this flag, `.` matches line terminators as well as other characters.

Example without the dotAll flag:

```javascript
const text = "Hello\nWorld";

const result = /Hello.World/.test(text);

console.log(result); // false
```

Example with the dotAll flag:

```javascript
const text = "Hello\nWorld";

const result = /Hello.World/s.test(text);

console.log(result); // true
```

The dotAll flag is useful when matching text that spans multiple lines.

# 🗁 Practical Example: Processing API Data

The following example combines several ES2018 features to process user data.

```javascript
async function getUsers() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/users"
  );

  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }

  return response.json();
}

async function processUsers() {
  try {
    const users = await getUsers();

    const results = users.map(user => {
      const { id, name, email, ...details } = user;

      return {
        id,
        name,
        email,
        ...details
      };
    });

    console.log(results);
  } catch (error) {
    console.error("Failed to load users:", error.message);
  } finally {
    console.log("User processing completed");
  }
}

processUsers();
```

Features used:

* `async` and `await` for asynchronous operations.
* Object rest for collecting remaining properties.
* Object spread for constructing new objects.
* `Promise.prototype.finally()` for cleanup.

# 🗁 Browser and Runtime Compatibility

ES2018 features are supported by modern JavaScript engines.

Older browsers and runtime environments may require transpilation or polyfills.

Important considerations:

* Babel can transform supported syntax such as object rest and spread.
* Promise `finally()` may require a polyfill in older environments.
* Regular expression features need compatible JavaScript engine support.
* Asynchronous iteration requires support for async iterators and generators.
* Unicode property escapes require an engine supporting the `u` flag with Unicode property escapes.

A transpiler cannot always replace every runtime capability automatically. Check the target environment and required polyfills.

# 🗁 Best Practices

* Use object rest to exclude properties when creating derived objects.
* Use object spread to create shallow copies and merge configuration objects.
* Remember that object spread does not perform deep cloning.
* Use `for await...of` when consuming asynchronous iterables.
* Use `Promise.prototype.finally()` for cleanup operations.
* Prefer named capture groups when regular expressions contain multiple meaningful captures.
* Use lookbehind assertions when matching conditions depend on preceding text.
* Use Unicode property escapes for multilingual text processing.
* Use the dotAll flag when a regular expression must match across line boundaries.
* Check compatibility when targeting older JavaScript environments.
