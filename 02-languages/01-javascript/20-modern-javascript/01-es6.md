# ECMAScript 2015 (ES6)

ECMAScript 2015, commonly known as ES6, is a major version of the ECMAScript language specification that introduced significant improvements to JavaScript.

Released in June 2015, ES6 modernized JavaScript by introducing features that made applications easier to develop, organize, maintain, and scale.

Before ES6, JavaScript developers often relied on older patterns for variable declarations, functions, object creation, asynchronous programming, and module organization.

ES6 introduced modern language features that are now fundamental to everyday JavaScript development.

# 🗁 What Is ECMAScript?

ECMAScript is the standardized specification that defines how JavaScript behaves.

JavaScript is an implementation of ECMAScript, with additional host-environment APIs provided by environments such as browsers and Node.js.

Important terminology:

* **ECMAScript:** The language specification.
* **JavaScript:** A programming language implementing ECMAScript.
* **ES6:** The sixth edition of ECMAScript, officially named ECMAScript 2015.
* **TC39:** The committee responsible for evolving the ECMAScript specification.

# 🗁 let and const

Before ES6, `var` was the primary way to declare variables.

ES6 introduced `let` and `const`.

**let**

Declares a block-scoped variable that can be reassigned.

```javascript
let username = "Alice";

username = "Bob";

console.log(username); // Bob
```

**const**

Declares a block-scoped binding that cannot be reassigned.

```javascript
const country = "Bangladesh";

console.log(country);
```

Reassignment is not allowed:

```javascript
const age = 25;

age = 30; // TypeError
```

However, `const` does not make objects or arrays immutable.

```javascript
const user = {
  name: "Alice"
};

user.name = "Bob"; // Allowed

console.log(user.name); // Bob
```

# 🗁 Arrow Functions

Arrow functions provide a shorter syntax for writing function expressions.

Traditional function:

```javascript
function add(a, b) {
  return a + b;
}
```

Arrow function:

```javascript
const add = (a, b) => {
  return a + b;
};
```

For a single expression, an implicit return can be used:

```javascript
const add = (a, b) => a + b;

console.log(add(10, 20)); // 30
```

Single parameters do not require parentheses:

```javascript
const square = number => number * number;

console.log(square(5)); // 25
```

Important characteristics:

* Arrow functions have concise syntax.
* They do not have their own `this`.
* They do not have their own `arguments` object.
* They cannot be used as constructors.
* They do not have a `prototype` property.

Arrow functions are especially useful for callbacks and functions that should retain their surrounding lexical `this`.

# 🗁 Template Literals

Template literals provide an improved way to construct strings.

They use backticks instead of single or double quotes.

**String interpolation**

```javascript
const name = "Alice";
const age = 25;

const message = `My name is ${name} and I am ${age} years old.`;

console.log(message);
```

**Multiline strings**

```javascript
const message = `
  Hello,
  Welcome to JavaScript.
  Enjoy learning!
`;

console.log(message);
```

**Expressions inside strings**

```javascript
const a = 10;
const b = 20;

console.log(`Total: ${a + b}`); // Total: 30
```

# 🗁 Default Parameters

Default parameters allow function parameters to have default values.

```javascript
function greet(name = "Guest") {
  return `Hello, ${name}!`;
}

console.log(greet("Alice")); // Hello, Alice!
console.log(greet());        // Hello, Guest!
```

A default value is used when the argument is omitted or explicitly passed as `undefined`.

```javascript
function calculate(price, tax = 0.1) {
  return price + price * tax;
}

console.log(calculate(100));      // 110
console.log(calculate(100, 0.2)); // 120
```

# 🗁 Rest Parameters

Rest parameters collect multiple remaining function arguments into an array.

The rest parameter uses the `...` syntax.

```javascript
function sum(...numbers) {
  return numbers.reduce((total, number) => total + number, 0);
}

console.log(sum(10, 20, 30)); // 60
```

Rest parameters must be the final parameter in a function definition.

```javascript
function introduce(name, ...hobbies) {
  console.log(name);
  console.log(hobbies);
}

introduce("Alice", "Reading", "Coding", "Traveling");
```

# 🗁 Spread Syntax

Spread syntax expands iterable values into individual elements.

It also supports copying and combining objects.

**Array expansion**

```javascript
const numbers = [10, 20, 30];

console.log(...numbers); // 10 20 30
```

**Combining arrays**

```javascript
const first = [1, 2];
const second = [3, 4];

const combined = [...first, ...second];

console.log(combined); // [1, 2, 3, 4]
```

**Copying arrays**

```javascript
const original = [1, 2, 3];

const copy = [...original];
```

**Combining objects**

```javascript
const user = {
  name: "Alice",
  age: 25
};

const updatedUser = {
  ...user,
  city: "Dhaka"
};

console.log(updatedUser);
```

Spread syntax creates shallow copies, not deep copies.

# 🗁 Destructuring Assignment

Destructuring extracts values from arrays or properties from objects into variables.

**Array destructuring**

```javascript
const colors = ["red", "green", "blue"];

const [first, second, third] = colors;

console.log(first);  // red
console.log(second); // green
console.log(third);  // blue
```

**Skipping elements**

```javascript
const numbers = [10, 20, 30];

const [first, , third] = numbers;

console.log(first); // 10
console.log(third); // 30
```

**Object destructuring**

```javascript
const user = {
  name: "Alice",
  age: 25
};

const { name, age } = user;

console.log(name);
console.log(age);
```

**Renaming variables**

```javascript
const user = {
  name: "Alice"
};

const { name: username } = user;

console.log(username);
```

**Default values**

```javascript
const user = {
  name: "Alice"
};

const { name, role = "Developer" } = user;

console.log(role); // Developer
```

# 🗁 Enhanced Object Literals

ES6 introduced concise syntax for defining object properties and methods.

**Property shorthand**

```javascript
const name = "Alice";
const age = 25;

const user = {
  name,
  age
};
```

This is equivalent to:

```javascript
const user = {
  name: name,
  age: age
};
```

**Method shorthand**

```javascript
const user = {
  name: "Alice",

  greet() {
    return `Hello, ${this.name}`;
  }
};

console.log(user.greet());
```

**Computed property names**

```javascript
const property = "email";

const user = {
  name: "Alice",
  [property]: "alice@example.com"
};

console.log(user.email);
```

# 🗁 Classes

ES6 introduced class syntax for defining objects through constructor functions and prototype-based inheritance.

```javascript
class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  introduce() {
    return `I am ${this.name}, ${this.age} years old.`;
  }
}

const person = new Person("Alice", 25);

console.log(person.introduce());
```

Classes support inheritance through `extends`.

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a sound.`;
  }
}

class Dog extends Animal {
  speak() {
    return `${this.name} barks.`;
  }
}

const dog = new Dog("Max");

console.log(dog.speak()); // Max barks.
```

JavaScript classes use the prototype system internally.

# 🗁 Modules

ES6 introduced native JavaScript modules.

Modules allow developers to split applications into reusable files.

**Exporting**

```javascript
// math.js

export const PI = 3.14159;

export function add(a, b) {
  return a + b;
}
```

**Importing**

```javascript
// app.js

import { PI, add } from "./math.js";

console.log(PI);
console.log(add(10, 20));
```

**Default export**

```javascript
// user.js

export default class User {
  constructor(name) {
    this.name = name;
  }
}
```

Import:

```javascript
import User from "./user.js";

const user = new User("Alice");
```

Native ES modules provide file-level scope and explicit dependency management.

# 🗁 Promises

Promises represent the eventual completion or failure of an asynchronous operation.

A promise has three states:

* `pending`: The operation is still in progress.
* `fulfilled`: The operation completed successfully.
* `rejected`: The operation failed.

Example:

```javascript
const promise = new Promise((resolve, reject) => {
  const success = true;

  if (success) {
    resolve("Operation completed");
  } else {
    reject(new Error("Operation failed"));
  }
});

promise
  .then(result => {
    console.log(result);
  })
  .catch(error => {
    console.error(error.message);
  });
```

Promises help organize asynchronous operations without deeply nested callbacks.

# 🗁 Iterators

An iterator is an object that follows the iterator protocol.

It provides a `next()` method that returns an object containing:

* `value`: The current iteration value.
* `done`: Indicates whether iteration has finished.

Example:

```javascript
const numbers = [10, 20, 30];

const iterator = numbers[Symbol.iterator]();

console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());
```

The final result indicates that iteration has completed.

```javascript
{
  value: undefined,
  done: true
}
```

Arrays, strings, Maps, and Sets provide built-in iterators.

# 🗁 Generators

Generators are special functions that can pause execution and resume later.

They are declared using the `function*` syntax.

The `yield` keyword produces a value and pauses the generator.

```javascript
function* generateNumbers() {
  yield 10;
  yield 20;
  yield 30;
}

const generator = generateNumbers();

console.log(generator.next());
console.log(generator.next());
console.log(generator.next());
console.log(generator.next());
```

Generators implement the iterator protocol and are useful for creating custom sequences and lazy computations.

# 🗁 Symbols

A Symbol is a primitive data type that represents a unique value.

Symbols are often used as object property keys to avoid accidental property-name collisions.

```javascript
const id = Symbol("id");

const user = {
  name: "Alice",
  [id]: 101
};

console.log(user[id]); // 101
```

Even symbols with identical descriptions are unique.

```javascript
const first = Symbol("id");
const second = Symbol("id");

console.log(first === second); // false
```

# 🗁 Map Collection

A Map stores key-value pairs and allows keys of any value type.

```javascript
const userRoles = new Map();

userRoles.set("Alice", "Admin");
userRoles.set("Bob", "Editor");

console.log(userRoles.get("Alice")); // Admin

console.log(userRoles.has("Bob")); // true

console.log(userRoles.size); // 2
```

Unlike ordinary object properties, Map keys can be objects, functions, and other values.

```javascript
const user = { id: 1 };

const permissions = new Map();

permissions.set(user, ["read", "write"]);

console.log(permissions.get(user));
```

# 🗁 Set Collection

A Set stores unique values.

Duplicate values are automatically ignored.

```javascript
const numbers = new Set([1, 2, 2, 3, 3, 4]);

console.log(numbers); // Set(4) { 1, 2, 3, 4 }
```

Adding and checking values:

```javascript
const users = new Set();

users.add("Alice");
users.add("Bob");
users.add("Alice");

console.log(users.size); // 2
console.log(users.has("Alice")); // true
```

Sets are useful for removing duplicate values and managing unique collections.

# 🗁 WeakMap and WeakSet

ES6 introduced WeakMap and WeakSet for specialized object-reference collections.

**WeakMap**

A WeakMap stores key-value pairs where keys must be objects or non-registered symbols that are eligible for weak references.

```javascript
const metadata = new WeakMap();

const user = {
  name: "Alice"
};

metadata.set(user, {
  role: "Admin"
});

console.log(metadata.get(user));
```

WeakMap does not prevent eligible object keys from being garbage-collected.

It is not directly iterable and does not expose a `size` property.

**WeakSet**

A WeakSet stores unique object references.

```javascript
const processedUsers = new WeakSet();

const user = {
  name: "Alice"
};

processedUsers.add(user);

console.log(processedUsers.has(user)); // true
```

WeakSet does not expose iteration methods or a `size` property.

# 🗁 for...of Loop

ES6 introduced the `for...of` loop for iterating over iterable values.

```javascript
const fruits = ["Apple", "Banana", "Orange"];

for (const fruit of fruits) {
  console.log(fruit);
}
```

It works with many built-in iterable values, including:

* Arrays.
* Strings.
* Maps.
* Sets.
* Generators.

Example with a string:

```javascript
for (const character of "JavaScript") {
  console.log(character);
}
```

# 🗁 Binary and Octal Literals

ES6 introduced more readable syntax for binary and octal number literals.

**Binary**

Binary literals use the `0b` prefix.

```javascript
const binary = 0b1010;

console.log(binary); // 10
```

**Octal**

Octal literals use the `0o` prefix.

```javascript
const octal = 0o17;

console.log(octal); // 15
```

Hexadecimal literals use the `0x` prefix and were already supported before ES6.

```javascript
const hexadecimal = 0xff;

console.log(hexadecimal); // 255
```

# 🗁 New Math and Number Features

ES6 introduced additional methods and constants for mathematical operations.

**Number.isFinite()**

Checks whether a value is a finite number without coercing other types.

```javascript
console.log(Number.isFinite(100)); // true
console.log(Number.isFinite(Infinity)); // false
console.log(Number.isFinite("100")); // false
```

**Number.isNaN()**

Checks whether a value is the numeric `NaN` value without coercion.

```javascript
console.log(Number.isNaN(NaN)); // true
console.log(Number.isNaN("hello")); // false
```

**Number.isInteger()**

Checks whether a value is an integer.

```javascript
console.log(Number.isInteger(10)); // true
console.log(Number.isInteger(10.5)); // false
```

**Math.trunc()**

Removes the fractional portion of a number.

```javascript
console.log(Math.trunc(10.9));  // 10
console.log(Math.trunc(-10.9)); // -10
```

# 🗁 Unicode Improvements

ES6 introduced improvements for handling Unicode characters.

Some Unicode characters require more than one UTF-16 code unit.

The `codePointAt()` method retrieves a Unicode code point.

```javascript
const character = "A";

console.log(character.codePointAt(0)); // 65
```

The `String.fromCodePoint()` method creates a string from Unicode code points.

```javascript
const character = String.fromCodePoint(128512);

console.log(character); // 😀
```

The `u` regular expression flag enables Unicode-aware pattern matching.

```javascript
const emoji = /\u{1F600}/u;

console.log(emoji.test("😀")); // true
```

# 🗁 Practical Example: Modern JavaScript Application

The following example combines several ES6 features.

```javascript
const users = [
  {
    id: 1,
    name: "Alice",
    role: "Admin"
  },
  {
    id: 2,
    name: "Bob",
    role: "Developer"
  },
  {
    id: 3,
    name: "Charlie",
    role: "Developer"
  }
];

const developers = users.filter(
  ({ role }) => role === "Developer"
);

const developerNames = developers.map(
  ({ name }) => name
);

const message = `Developers: ${developerNames.join(", ")}`;

console.log(message);
```

Output:

```text
Developers: Bob, Charlie
```

Features used:

* `const` for variable declarations.
* Arrow functions for callbacks.
* Object destructuring for extracting properties.
* Template literals for string interpolation.
* `filter()` for selecting elements.
* `map()` for transforming elements.

# 🗁 Browser and Runtime Compatibility

ES6 features are supported by modern JavaScript engines, including current browsers and Node.js releases.

However, older environments may not support every feature.

Tools such as Babel can transform many modern JavaScript syntax features into code compatible with older JavaScript environments.

For example, an arrow function:

```javascript
const add = (a, b) => a + b;
```

Can be transformed into a traditional function:

```javascript
var add = function (a, b) {
  return a + b;
};
```

Transpilation does not automatically provide every missing runtime API. Some features require polyfills.

# 🗁 Best Practices

* Prefer `const` for bindings that are not reassigned.
* Use `let` when reassignment is necessary.
* Avoid `var` in new code unless a specific compatibility requirement exists.
* Use arrow functions for callbacks when lexical `this` is appropriate.
* Use template literals for interpolation and multiline strings.
* Use destructuring to make data extraction concise.
* Use spread syntax carefully because it creates shallow copies.
* Use classes when their syntax improves object-oriented code organization.
* Use native modules to organize application dependencies.
* Use promises to manage asynchronous operations.
* Use Maps and Sets when their collection semantics are appropriate.
* Understand the difference between `for...in` and `for...of`.
* Check runtime compatibility when targeting older environments.
