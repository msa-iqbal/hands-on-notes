# ECMAScript 2022 (ES13)

ECMAScript 2022, commonly known as ES13, is the thirteenth edition of the ECMAScript language specification.

It was finalized in June 2022 and introduced several improvements to classes, objects, arrays, modules, and asynchronous programming.

ES2022 made JavaScript more expressive by adding class field declarations, private field access checks, top-level await, and new methods for working with arrays and object properties.

# 🗁 What Is ECMAScript 2022?

ECMAScript 2022 continued the annual evolution of JavaScript with features that improve code organization, encapsulation, and developer productivity.

Important terminology:

* **ECMAScript:** The standardized specification that defines JavaScript.
* **ES13:** The informal name for ECMAScript 2022.
* **ES2022:** The official edition name.
* **TC39:** The committee responsible for evolving ECMAScript.

# 🗁 Major ES2022 Features

| Feature | Description |
| --- | --- |
| Class public fields | Allows declaring instance fields directly inside classes |
| Class private fields | Supports private instance and static fields |
| Static class initialization blocks | Allows complex static initialization logic |
| Private field presence checks | Checks whether an object contains a particular private field |
| Top-level await | Allows `await` directly inside JavaScript modules |
| `Object.hasOwn()` | Checks whether an object has a property as its own property |
| `Array.prototype.at()` | Accesses array elements using positive or negative indexes |
| `String.prototype.at()` | Accesses string characters using positive or negative indexes |
| RegExp match indices (`d` flag) | Provides start and end positions of regular expression matches |
| Error cause | Allows an error to preserve the underlying cause of another error |
| Class static initialization | Supports static initialization blocks for class-level setup |

# 🗁 Class Public Fields

ES2022 standardized public class fields, allowing properties to be declared directly inside a class body.

Before this feature, instance properties were commonly initialized inside the constructor.

Example before public class fields:

```javascript
class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }
}
```

Using public class fields:

```javascript
class User {
  name = "Alice";
  age = 25;
}

const user = new User();

console.log(user.name);
console.log(user.age);
```

Output:

```text
Alice
25
```

Public fields can also be initialized through constructor arguments.

```javascript
class User {
  name;
  age;

  constructor(name, age) {
    this.name = name;
    this.age = age;
  }
}

const user = new User("Bob", 30);

console.log(user.name);
console.log(user.age);
```

Public fields belong to individual instances when declared as instance fields.

# 🗁 Class Private Fields

ES2022 standardized private class fields.

Private fields use the `#` prefix and cannot be accessed directly outside the class that declares them.

Example:

```javascript
class BankAccount {
  #balance = 1000;

  getBalance() {
    return this.#balance;
  }
}

const account = new BankAccount();

console.log(account.getBalance());
```

Output:

```text
1000
```

Direct access from outside the class is not allowed:

```javascript
console.log(account.#balance);
```

This produces a syntax error.

Private fields support encapsulation by preventing external code from directly accessing internal state.

**Private fields with constructors:**

```javascript
class BankAccount {
  #balance;

  constructor(initialBalance) {
    this.#balance = initialBalance;
  }

  deposit(amount) {
    if (amount <= 0) {
      throw new Error("Amount must be positive");
    }

    this.#balance += amount;
  }

  getBalance() {
    return this.#balance;
  }
}

const account = new BankAccount(1000);

account.deposit(500);

console.log(account.getBalance());
```

Output:

```text
1500
```

# 🗁 Static Class Fields

Static fields belong to the class itself rather than individual instances.

They are declared using the `static` keyword.

Example:

```javascript
class Application {
  static name = "My Application";
  static version = "1.0.0";
}

console.log(Application.name);
console.log(Application.version);
```

Output:

```text
My Application
1.0.0
```

Static fields are accessed through the class name.

They are not automatically available as instance properties.

```javascript
const app = new Application();

console.log(app.name); // undefined
```

**Static private fields:**

```javascript
class Counter {
  static #count = 0;

  static increment() {
    Counter.#count++;
  }

  static getCount() {
    return Counter.#count;
  }
}

Counter.increment();
Counter.increment();

console.log(Counter.getCount());
```

Output:

```text
2
```

Static private fields are accessible only within the class body.

# 🗁 Static Initialization Blocks

ES2022 introduced static initialization blocks.

They allow developers to execute initialization logic inside a class when the class is initialized.

Static initialization blocks are declared using `static { ... }`.

Example:

```javascript
class Application {
  static version;

  static {
    Application.version = "1.0.0";

    console.log("Application initialized");
  }
}

console.log(Application.version);
```

Output:

```text
Application initialized
1.0.0
```

Static initialization blocks are useful when initialization requires multiple statements or access to private static fields.

**Using private static fields:**

```javascript
class Database {
  static #configuration;

  static {
    const host = "localhost";
    const port = 5432;

    Database.#configuration = {
      host,
      port
    };
  }

  static getConfiguration() {
    return Database.#configuration;
  }
}

console.log(Database.getConfiguration());
```

Output:

```javascript
{
  host: "localhost",
  port: 5432
}
```

Important characteristics:

* Static blocks execute during class initialization.
* They execute in the order in which they appear in the class body.
* They can access private static fields and methods.
* They cannot use `this` as a reference to an instance.
* They are useful for complex static initialization.

# 🗁 Private Field Presence Checks

ES2022 introduced the ability to check whether an object contains a particular private field.

The syntax uses the `#field in object` expression.

Example:

```javascript
class User {
  #name;

  constructor(name) {
    this.#name = name;
  }

  static hasUserName(object) {
    return #name in object;
  }
}

const user = new User("Alice");

console.log(User.hasUserName(user));
console.log(User.hasUserName({}));
```

Output:

```text
true
false
```

This feature is useful for checking whether an object belongs to a class or has a particular private element.

**Example with inheritance:**

```javascript
class Animal {
  #name;

  constructor(name) {
    this.#name = name;
  }

  static isAnimal(object) {
    return #name in object;
  }
}

class Dog extends Animal {}

const dog = new Dog("Buddy");

console.log(Animal.isAnimal(dog));
```

Output:

```text
true
```

The private field is declared by `Animal` and is present in instances created through the derived class.

# 🗁 Top-Level Await

ES2022 standardized top-level await.

It allows developers to use `await` directly inside ECMAScript modules without wrapping it in an async function.

Before top-level await:

```javascript
async function loadConfiguration() {
  const response = await fetch("./config.json");

  const config = await response.json();

  return config;
}

const config = await loadConfiguration();
```

With top-level await:

```javascript
const response = await fetch("./config.json");

const config = await response.json();

console.log(config);
```

Top-level await is available in ECMAScript modules, not ordinary classic scripts.

**Using top-level await with dynamic imports:**

```javascript
const module = await import("./math.js");

console.log(module.add(10, 20));
```

**Using top-level await in a configuration module:**

```javascript
// config.js

const response = await fetch("./config.json");

if (!response.ok) {
  throw new Error("Unable to load configuration");
}

export const config = await response.json();
```

Another module can import the configuration:

```javascript
// app.js

import { config } from "./config.js";

console.log(config);
```

A module containing top-level await becomes asynchronous during module evaluation.

Modules that depend on it must wait for its evaluation to complete.

# 🗁 Object.hasOwn()

ES2022 introduced `Object.hasOwn()`.

It checks whether an object has a specified property as its own property.

**Syntax**

```javascript
Object.hasOwn(object, property);
```

The method returns:

* `true` when the object has the specified own property.
* `false` when the property does not exist as an own property.

Example:

```javascript
const user = {
  name: "Alice",
  age: 25
};

console.log(Object.hasOwn(user, "name"));
console.log(Object.hasOwn(user, "email"));
```

Output:

```text
true
false
```

**Comparing Object.hasOwn() and the in operator:**

```javascript
const user = {
  name: "Alice"
};

console.log("name" in user);
console.log(Object.hasOwn(user, "name"));
```

Both return `true` because `name` is an own property.

However, the `in` operator also checks the prototype chain.

```javascript
const user = {
  name: "Alice"
};

console.log("toString" in user);
console.log(Object.hasOwn(user, "toString"));
```

Output:

```text
true
false
```

`toString` is inherited from the object's prototype rather than being an own property.

**Why Object.hasOwn() is preferred:**

Before ES2022, developers commonly used:

```javascript
Object.prototype.hasOwnProperty.call(user, "name");
```

The newer method is more concise:

```javascript
Object.hasOwn(user, "name");
```

It also works with objects created without a prototype.

```javascript
const user = Object.create(null);

user.name = "Alice";

console.log(Object.hasOwn(user, "name"));
```

Output:

```text
true
```

# 🗁 Array.prototype.at()

ES2022 introduced `Array.prototype.at()`.

It returns the element at a specified index.

Unlike bracket notation, `at()` supports negative indexes to access elements from the end of an array.

**Syntax**

```javascript
array.at(index);
```

Example:

```javascript
const languages = [
  "JavaScript",
  "TypeScript",
  "Python",
  "Java"
];

console.log(languages.at(0));
console.log(languages.at(1));
console.log(languages.at(-1));
console.log(languages.at(-2));
```

Output:

```text
JavaScript
TypeScript
Java
Python
```

**Negative index behavior:**

| Expression | Result |
| --- | --- |
| `array.at(0)` | First element |
| `array.at(1)` | Second element |
| `array.at(-1)` | Last element |
| `array.at(-2)` | Second-to-last element |

**Comparison with bracket notation:**

```javascript
const numbers = [10, 20, 30];

console.log(numbers[numbers.length - 1]);
console.log(numbers.at(-1));
```

Both return:

```text
30
```

If the index is outside the array's valid range, `at()` returns `undefined`.

```javascript
const numbers = [10, 20, 30];

console.log(numbers.at(10));
console.log(numbers.at(-10));
```

Output:

```text
undefined
undefined
```

# 🗁 String.prototype.at()

ES2022 also introduced `String.prototype.at()`.

It returns the character at a specified string index.

Negative indexes count backward from the end of the string.

Example:

```javascript
const language = "JavaScript";

console.log(language.at(0));
console.log(language.at(4));
console.log(language.at(-1));
console.log(language.at(-2));
```

Output:

```text
J
S
t
p
```

**Comparison with bracket notation:**

```javascript
const language = "JavaScript";

console.log(language[language.length - 1]);
console.log(language.at(-1));
```

Both return:

```text
t
```

Like other string indexing operations, `at()` works with UTF-16 code units. It does not always return an entire Unicode character when that character is represented by a surrogate pair.

# 🗁 RegExp Match Indices

ES2022 introduced the `d` flag for regular expressions.

It enables match indices, providing the start and end positions of the full match and its capture groups.

Example:

```javascript
const text = "JavaScript 2022";

const pattern = /(\w+)\s(\d+)/d;

const result = pattern.exec(text);

console.log(result.indices);
```

The result contains index ranges:

```javascript
[
  [0, 15],
  [0, 10],
  [11, 15]
]
```

Each range contains:

* The starting index.
* The ending index, which is exclusive.

**Using named capture groups:**

```javascript
const text = "User: Alice";

const pattern = /User: (?<name>\w+)/d;

const result = pattern.exec(text);

console.log(result.indices.groups.name);
```

Output:

```javascript
[6, 11]
```

This feature is useful when building text editors, parsers, syntax highlighters, and text-processing tools that need exact match positions.

# 🗁 Error Cause

ES2022 introduced the standard `cause` option for the Error constructor.

It allows an error to preserve the underlying reason another operation failed.

This is particularly useful when wrapping low-level errors with more meaningful application-level errors.

Example:

```javascript
try {
  JSON.parse("{ invalid json }");
} catch (error) {
  throw new Error("Unable to load configuration", {
    cause: error
  });
}
```

The new error contains the original error in its `cause` property.

**Accessing the original cause:**

```javascript
try {
  try {
    JSON.parse("{ invalid json }");
  } catch (error) {
    throw new Error("Configuration loading failed", {
      cause: error
    });
  }
} catch (error) {
  console.log(error.message);
  console.log(error.cause.message);
}
```

Output:

```text
Configuration loading failed
Expected property name or '}' in JSON...
```

The exact parser error message depends on the JavaScript engine.

**Using error causes in custom errors:**

```javascript
class DatabaseError extends Error {
  constructor(message, options) {
    super(message, options);

    this.name = "DatabaseError";
  }
}

try {
  throw new Error("Connection refused");
} catch (error) {
  throw new DatabaseError("Database operation failed", {
    cause: error
  });
}
```

Preserving error causes helps maintain the original failure context while providing clearer application-level messages.

# 🗁 Practical Example: Combining ES2022 Features

The following example combines public fields, private fields, static methods, `Object.hasOwn()`, and `Array.prototype.at()`.

```javascript
class UserRepository {
  static #users = [];

  static add(user) {
    if (!Object.hasOwn(user, "id")) {
      throw new Error("User ID is required");
    }

    UserRepository.#users.push(user);
  }

  static getAll() {
    return [...UserRepository.#users];
  }

  static getLatest() {
    return UserRepository.#users.at(-1);
  }
}

class User {
  name;
  #email;

  constructor(name, email) {
    this.name = name;
    this.#email = email;
  }

  getEmail() {
    return this.#email;
  }
}

const user = new User("Alice", "alice@example.com");

UserRepository.add({
  id: 101,
  name: user.name,
  email: user.getEmail()
});

UserRepository.add({
  id: 102,
  name: "Bob",
  email: "bob@example.com"
});

console.log(UserRepository.getAll());
console.log(UserRepository.getLatest());
```

Features used:

* Public class fields for instance properties.
* Private class fields for internal state.
* Static private fields for repository data.
* `Object.hasOwn()` for checking own properties.
* `Array.prototype.at()` for accessing the latest entry.

# 🗁 Browser and Runtime Compatibility

ES2022 features are supported by modern JavaScript engines.

Older browsers and runtime environments may require transpilation or polyfills.

Important considerations:

* Public and private class fields require modern class syntax support.
* Static initialization blocks require runtime support.
* Top-level await requires ECMAScript module support.
* `Object.hasOwn()` may require a polyfill in older environments.
* `Array.prototype.at()` and `String.prototype.at()` may require polyfills.
* RegExp match indices require support for the `d` flag.
* Error causes require support for the Error constructor options.

A transpiler can transform some syntax, but built-in runtime methods still require compatible implementations.

# 🗁 Best Practices

* Use public class fields for straightforward instance initialization.
* Use private fields when internal state should not be accessed directly.
* Use static fields for data shared at the class level.
* Use static initialization blocks when static initialization requires multiple operations.
* Use `Object.hasOwn()` to check own properties safely.
* Use `Array.prototype.at(-1)` when accessing the last array element.
* Use `String.prototype.at()` for concise positive or negative string indexing.
* Use top-level await when module initialization genuinely depends on asynchronous operations.
* Use RegExp match indices when exact text positions are required.
* Preserve original errors with the `cause` option when wrapping exceptions.
