# ECMAScript 2023 (ES14)

ECMAScript 2023, commonly known as ES14, is the fourteenth edition of the ECMAScript language specification.

It was finalized in June 2023 and introduced improvements to array manipulation, immutable data operations, and Unicode-aware string processing.

One of its central themes was providing non-mutating alternatives to existing array methods. These methods make it easier to write predictable code, especially when working with immutable state in frontend applications.

# 🗁 What Is ECMAScript 2023?

ECMAScript 2023 is an annual update to the JavaScript language specification.

Important terminology:

* **ECMAScript:** The standardized specification that defines JavaScript.
* **ES14:** The informal name for ECMAScript 2023.
* **ES2023:** The official edition name.
* **TC39:** The committee responsible for evolving ECMAScript.

# 🗁 Array.prototype.findLast()

ES2023 introduced `Array.prototype.findLast()`.

It searches an array from right to left and returns the last element that satisfies a specified condition.

**Syntax**

```javascript
array.findLast(callback(element, index, array), thisArg);
```

Example:

```javascript
const numbers = [10, 20, 30, 40, 50, 60];

const result = numbers.findLast(number => number > 25);

console.log(result);
```

Output:

```text
60
```

The method starts searching from the last element and stops when it finds a matching element.

**Example with objects:**

```javascript
const users = [
  { id: 1, name: "Alice", active: false },
  { id: 2, name: "Bob", active: true },
  { id: 3, name: "Charlie", active: false },
  { id: 4, name: "David", active: true }
];

const lastActiveUser = users.findLast(user => user.active);

console.log(lastActiveUser);
```

Output:

```javascript
{
  id: 4,
  name: "David",
  active: true
}
```

If no element satisfies the condition, `findLast()` returns `undefined`.

```javascript
const numbers = [10, 20, 30];

console.log(numbers.findLast(number => number > 100));
```

Output:

```text
undefined
```

# 🗁 Array.prototype.findLastIndex()

`Array.prototype.findLastIndex()` searches an array from right to left and returns the index of the last element that satisfies a condition.

**Syntax**

```javascript
array.findLastIndex(callback(element, index, array), thisArg);
```

Example:

```javascript
const numbers = [10, 20, 30, 40, 50, 60];

const index = numbers.findLastIndex(number => number > 25);

console.log(index);
```

Output:

```text
5
```

The element `60` is the last matching element, and its index is `5`.

**Example with objects:**

```javascript
const users = [
  { id: 1, role: "admin" },
  { id: 2, role: "user" },
  { id: 3, role: "admin" },
  { id: 4, role: "user" }
];

const index = users.findLastIndex(user => user.role === "admin");

console.log(index);
```

Output:

```text
2
```

If no element matches, the method returns `-1`.

```javascript
const numbers = [10, 20, 30];

console.log(numbers.findLastIndex(number => number > 100));
```

Output:

```text
-1
```

# 🗁 Array.prototype.toReversed()

ES2023 introduced `Array.prototype.toReversed()`.

It returns a new array containing the elements in reverse order without modifying the original array.

**Syntax**

```javascript
array.toReversed();
```

Example:

```javascript
const numbers = [10, 20, 30, 40];

const reversed = numbers.toReversed();

console.log(reversed);
console.log(numbers);
```

Output:

```text
[40, 30, 20, 10]
[10, 20, 30, 40]
```

**Comparison with reverse():**

The traditional `reverse()` method modifies the original array.

```javascript
const numbers = [10, 20, 30];

const reversed = numbers.reverse();

console.log(reversed);
console.log(numbers);
```

Output:

```text
[30, 20, 10]
[30, 20, 10]
```

Using `toReversed()` avoids this mutation.

```javascript
const numbers = [10, 20, 30];

const reversed = numbers.toReversed();

console.log(reversed);
console.log(numbers);
```

Output:

```text
[30, 20, 10]
[10, 20, 30]
```

This is particularly useful when working with immutable application state.

# 🗁 Array.prototype.toSorted()

ES2023 introduced `Array.prototype.toSorted()`.

It returns a new sorted array without modifying the original array.

**Syntax**

```javascript
array.toSorted(compareFunction);
```

Example:

```javascript
const numbers = [40, 10, 30, 20];

const sorted = numbers.toSorted((a, b) => a - b);

console.log(sorted);
console.log(numbers);
```

Output:

```text
[10, 20, 30, 40]
[40, 10, 30, 20]
```

**Descending order:**

```javascript
const numbers = [40, 10, 30, 20];

const sorted = numbers.toSorted((a, b) => b - a);

console.log(sorted);
```

Output:

```text
[40, 30, 20, 10]
```

**Sorting strings:**

```javascript
const languages = [
  "Python",
  "JavaScript",
  "TypeScript",
  "Java"
];

const sorted = languages.toSorted();

console.log(sorted);
```

Output:

```text
["Java", "JavaScript", "Python", "TypeScript"]
```

**Sorting objects:**

```javascript
const users = [
  { name: "Charlie", age: 30 },
  { name: "Alice", age: 22 },
  { name: "Bob", age: 27 }
];

const sortedUsers = users.toSorted(
  (a, b) => a.age - b.age
);

console.log(sortedUsers);
```

The original `users` array remains unchanged.

# 🗁 Array.prototype.toSpliced()

ES2023 introduced `Array.prototype.toSpliced()`.

It works similarly to `splice()`, but returns a new array instead of modifying the original array.

**Syntax**

```javascript
array.toSpliced(start, deleteCount, item1, item2, ...);
```

Parameters:

* `start`: The index where modification begins.
* `deleteCount`: The number of elements to remove.
* `item1`, `item2`, etc.: Optional elements to insert.

Example:

```javascript
const numbers = [10, 20, 30, 40];

const updated = numbers.toSpliced(1, 1);

console.log(updated);
console.log(numbers);
```

Output:

```text
[10, 30, 40]
[10, 20, 30, 40]
```

The original array remains unchanged.

**Inserting elements:**

```javascript
const numbers = [10, 20, 30];

const updated = numbers.toSpliced(1, 0, 15);

console.log(updated);
```

Output:

```text
[10, 15, 20, 30]
```

**Replacing elements:**

```javascript
const numbers = [10, 20, 30];

const updated = numbers.toSpliced(1, 1, 25);

console.log(updated);
```

Output:

```text
[10, 25, 30]
```

**Removing multiple elements:**

```javascript
const numbers = [10, 20, 30, 40, 50];

const updated = numbers.toSpliced(1, 3);

console.log(updated);
```

Output:

```text
[10, 50]
```

# 🗁 Array.prototype.with()

ES2023 introduced `Array.prototype.with()`.

It returns a new array with the element at a specified index replaced by a new value.

**Syntax**

```javascript
array.with(index, value);
```

Example:

```javascript
const numbers = [10, 20, 30, 40];

const updated = numbers.with(1, 25);

console.log(updated);
console.log(numbers);
```

Output:

```text
[10, 25, 30, 40]
[10, 20, 30, 40]
```

The original array is not modified.

**Using negative indexes:**

```javascript
const numbers = [10, 20, 30, 40];

const updated = numbers.with(-1, 50);

console.log(updated);
```

Output:

```text
[10, 20, 30, 50]
```

A negative index counts backward from the end of the array.

**Index validation:**

Unlike `at()`, `with()` requires the index to identify an existing array position.

```javascript
const numbers = [10, 20, 30];

numbers.with(5, 50);
```

This throws a `RangeError`.

# 🗁 Hashbang Grammar

ES2023 standardized hashbang comments.

A hashbang begins with `#!` and is placed at the very beginning of a JavaScript file.

It tells Unix-like operating systems which interpreter should execute the file.

Example:

```javascript
#!/usr/bin/env node

console.log("Hello from Node.js");
```

This allows the file to be executed directly in compatible environments when it has executable permissions.

For example:

```bash
chmod +x app.js

./app.js
```

The hashbang is commonly used in Node.js command-line tools and executable JavaScript scripts.

Important characteristics:

* It must appear at the beginning of the file.
* It is not an ordinary JavaScript comment.
* It identifies the interpreter used to execute the script.
* It is particularly useful for command-line applications.

# 🗁 WeakMap Symbol Keys

Before ES2023, WeakMap keys had to be objects.

ES2023 expanded the allowed key types to include non-registered symbols.

Example:

```javascript
const metadata = new WeakMap();

const userId = Symbol("userId");

metadata.set(userId, {
  role: "admin"
});

console.log(metadata.get(userId));
```

Output:

```javascript
{
  role: "admin"
}
```

Not every symbol can be used as a WeakMap key.

Registered symbols created through `Symbol.for()` and well-known symbols such as `Symbol.iterator` are not valid WeakMap keys.

Example:

```javascript
const metadata = new WeakMap();

const registeredSymbol = Symbol.for("user");

metadata.set(registeredSymbol, "value");
```

This throws a `TypeError`.

Non-registered symbols are useful when a symbol should serve as a weakly held key without requiring an object wrapper.

# 🗁 Immutable Array Methods

One of the most important improvements in ES2023 is the introduction of non-mutating array methods.

Traditional array methods often modify the original array.

| Mutating method | Non-mutating alternative |
| --- | --- |
| `reverse()` | `toReversed()` |
| `sort()` | `toSorted()` |
| `splice()` | `toSpliced()` |
| Direct index assignment | `with()` |

These alternatives return new arrays while preserving the original array.

**Example:**

```javascript
const products = [
  { id: 1, price: 300 },
  { id: 2, price: 100 },
  { id: 3, price: 200 }
];

const sortedProducts = products.toSorted(
  (a, b) => a.price - b.price
);

const updatedProducts = sortedProducts.with(0, {
  ...sortedProducts[0],
  price: 150
});

console.log(products);
console.log(updatedProducts);
```

The original `products` array remains unchanged.

Note that these methods create shallow copies. Objects contained in the resulting array are not automatically cloned.

# 🗁 Practical Example: Immutable Product Management

The following example combines ES2023 array methods to manage product data without modifying the original collection.

```javascript
const products = [
  { id: 1, name: "Keyboard", price: 80, stock: 10 },
  { id: 2, name: "Mouse", price: 30, stock: 5 },
  { id: 3, name: "Monitor", price: 250, stock: 3 },
  { id: 4, name: "Headphones", price: 60, stock: 8 }
];

// Find the last product with available stock.
const lastAvailableProduct = products.findLast(
  product => product.stock > 0
);

// Find the index of the last expensive product.
const expensiveProductIndex = products.findLastIndex(
  product => product.price > 100
);

// Sort products by price without mutation.
const sortedProducts = products.toSorted(
  (a, b) => a.price - b.price
);

// Create a reversed copy.
const reversedProducts = products.toReversed();

// Replace one product without mutation.
const updatedProducts = products.with(1, {
  ...products[1],
  price: 25
});

// Remove a product without mutation.
const remainingProducts = products.toSpliced(0, 1);

console.log(lastAvailableProduct);
console.log(expensiveProductIndex);
console.log(sortedProducts);
console.log(reversedProducts);
console.log(updatedProducts);
console.log(remainingProducts);

// Original collection remains unchanged.
console.log(products);
```

This approach is useful for state management, data transformations, and applications where predictable updates are important.

# 🗁 Browser and Runtime Compatibility

ES2023 features are supported by modern JavaScript engines.

Older environments may require polyfills or alternative implementations.

Important considerations:

* `findLast()` and `findLastIndex()` require modern array method support.
* `toReversed()`, `toSorted()`, `toSpliced()`, and `with()` require ES2023 array method support.
* Hashbang syntax is useful in compatible command-line environments.
* WeakMap symbol keys require support for the ES2023 key extension.

A transpiler can transform some JavaScript syntax, but it does not automatically provide every missing built-in method.

# 🗁 Best Practices

* Prefer non-mutating array methods when working with immutable application state.
* Use `findLast()` when searching for the last matching element.
* Use `findLastIndex()` when the matching element's position is required.
* Use `toReversed()` instead of `reverse()` when the original array must remain unchanged.
* Use `toSorted()` instead of `sort()` when a new sorted array is needed.
* Use `toSpliced()` for immutable insertion and removal operations.
* Use `with()` for immutable replacement of an array element.
* Remember that these array methods create shallow copies, not deep copies.
* Use hashbang syntax for executable JavaScript command-line scripts.
* Use non-registered symbols as WeakMap keys when symbol-based weak associations are useful.
