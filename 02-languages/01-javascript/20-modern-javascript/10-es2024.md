# ECMAScript 2024 (ES15)

ECMAScript 2024, commonly known as ES15, is the fifteenth edition of the ECMAScript language specification.

It was finalized in June 2024 and introduced improvements to string processing, regular expressions, collections, asynchronous programming, and memory management.

ES2024 focuses on making existing JavaScript capabilities more powerful and consistent, particularly when working with Unicode text, grouping data, and asynchronous operations.

# 🗁 What Is ECMAScript 2024?

ECMAScript 2024 is an annual update to the JavaScript language specification.

Important terminology:

* **ECMAScript:** The standardized specification that defines JavaScript.
* **ES15:** The informal name for ECMAScript 2024.
* **ES2024:** The official edition name.
* **TC39:** The committee responsible for evolving ECMAScript.

# 🗁 Object.groupBy()

ES2024 introduced `Object.groupBy()`.

It groups elements of an iterable into an object based on the value returned by a callback function.

**Syntax**

```javascript
Object.groupBy(items, callback);
```

Parameters:

* `items`: An iterable containing the elements to group.
* `callback`: A function that returns the grouping key for each element.

Example:

```javascript
const products = [
  { name: "Laptop", category: "Electronics" },
  { name: "Phone", category: "Electronics" },
  { name: "Shirt", category: "Clothing" },
  { name: "Jeans", category: "Clothing" }
];

const groupedProducts = Object.groupBy(
  products,
  product => product.category
);

console.log(groupedProducts);
```

Conceptual output:

```javascript
{
  Electronics: [
    { name: "Laptop", category: "Electronics" },
    { name: "Phone", category: "Electronics" }
  ],
  Clothing: [
    { name: "Shirt", category: "Clothing" },
    { name: "Jeans", category: "Clothing" }
  ]
}
```

**Grouping numbers:**

```javascript
const numbers = [1, 2, 3, 4, 5, 6, 7, 8];

const groupedNumbers = Object.groupBy(
  numbers,
  number => number % 2 === 0 ? "even" : "odd"
);

console.log(groupedNumbers);
```

Output:

```javascript
{
  odd: [1, 3, 5, 7],
  even: [2, 4, 6, 8]
}
```

Important characteristics:

* The callback determines the group key.
* Each group contains an array of original elements.
* The result is an object whose group keys are property keys.
* The original iterable is not modified.

`Object.groupBy()` is useful for categorizing records, organizing API responses, and grouping application data.

# 🗁 Map.groupBy()

ES2024 also introduced `Map.groupBy()`.

It works similarly to `Object.groupBy()`, but returns a `Map` instead of an object.

**Syntax**

```javascript
Map.groupBy(items, callback);
```

Example:

```javascript
const employees = [
  { name: "Alice", department: "Engineering" },
  { name: "Bob", department: "Design" },
  { name: "Charlie", department: "Engineering" },
  { name: "David", department: "Marketing" }
];

const groupedEmployees = Map.groupBy(
  employees,
  employee => employee.department
);

console.log(groupedEmployees.get("Engineering"));
```

Output:

```javascript
[
  { name: "Alice", department: "Engineering" },
  { name: "Charlie", department: "Engineering" }
]
```

**Using object keys:**

Unlike object property keys, Map keys can be objects.

```javascript
const engineering = { id: 1, name: "Engineering" };
const design = { id: 2, name: "Design" };

const employees = [
  { name: "Alice", department: engineering },
  { name: "Bob", department: design },
  { name: "Charlie", department: engineering }
];

const grouped = Map.groupBy(
  employees,
  employee => employee.department
);

console.log(grouped.get(engineering));
```

Output:

```javascript
[
  { name: "Alice", department: { id: 1, name: "Engineering" } },
  { name: "Charlie", department: { id: 1, name: "Engineering" } }
]
```

The object keys are compared by identity, not by their property values.

# 🗁 Object.groupBy() vs Map.groupBy()

Both methods group iterable elements, but their results have different characteristics.

| Characteristic | Object.groupBy() | Map.groupBy() |
| --- | --- | --- |
| Return type | Object | Map |
| Group keys | Property keys | Any valid Map key |
| Object keys | Converted to property keys | Preserved as object references |
| Access | `result[key]` | `result.get(key)` |
| Iteration | Object methods | Map methods |
| Group order | Object property ordering rules | Map insertion order |

Use `Object.groupBy()` when group keys are strings or symbols and an object result is convenient.

Use `Map.groupBy()` when group keys may be objects or when Map-specific operations are useful.

# 🗁 Promise.withResolvers()

ES2024 introduced `Promise.withResolvers()`.

It creates a promise and returns an object containing:

* `promise`: The created promise.
* `resolve`: The function that fulfills the promise.
* `reject`: The function that rejects the promise.

**Syntax**

```javascript
Promise.withResolvers();
```

Example:

```javascript
const {
  promise,
  resolve,
  reject
} = Promise.withResolvers();

resolve("Operation completed");

promise.then(result => {
  console.log(result);
});
```

Output:

```text
Operation completed
```

**Using reject:**

```javascript
const {
  promise,
  resolve,
  reject
} = Promise.withResolvers();

reject(new Error("Operation failed"));

promise.catch(error => {
  console.log(error.message);
});
```

Output:

```text
Operation failed
```

**Comparison with the traditional Promise constructor:**

Before ES2024, developers commonly used an external variable to store the resolver.

```javascript
let resolvePromise;

const promise = new Promise(resolve => {
  resolvePromise = resolve;
});

resolvePromise("Completed");

promise.then(console.log);
```

With `Promise.withResolvers()`:

```javascript
const {
  promise,
  resolve
} = Promise.withResolvers();

resolve("Completed");

promise.then(console.log);
```

The newer approach provides the promise and its settlement functions together.

**Practical example: Event-based coordination**

```javascript
function createSignal() {
  const {
    promise,
    resolve
  } = Promise.withResolvers();

  return {
    promise,
    trigger: resolve
  };
}

const signal = createSignal();

signal.promise.then(message => {
  console.log(message);
});

signal.trigger("Signal received");
```

Output:

```text
Signal received
```

This method is useful when promise settlement must be controlled by an event or another operation outside the original Promise executor.

# 🗁 Resizable ArrayBuffer

ES2024 standardized resizable `ArrayBuffer` support.

An ordinary `ArrayBuffer` has a fixed byte length after creation.

A resizable `ArrayBuffer` can change its byte length within a maximum size defined during construction.

**Creating a resizable ArrayBuffer:**

```javascript
const buffer = new ArrayBuffer(8, {
  maxByteLength: 16
});

console.log(buffer.byteLength);
console.log(buffer.maxByteLength);
```

Output:

```text
8
16
```

The initial size is 8 bytes, and the maximum size is 16 bytes.

**Resizing the buffer:**

```javascript
buffer.resize(12);

console.log(buffer.byteLength);
```

Output:

```text
12
```

The buffer can grow or shrink within its allowed range.

```javascript
buffer.resize(4);

console.log(buffer.byteLength);
```

Output:

```text
4
```

Trying to resize beyond the maximum size throws a `RangeError`.

**Checking whether an ArrayBuffer is resizable:**

```javascript
const buffer = new ArrayBuffer(8, {
  maxByteLength: 16
});

console.log(buffer.resizable);
```

Output:

```text
true
```

A fixed-length buffer reports `false`.

```javascript
const fixedBuffer = new ArrayBuffer(8);

console.log(fixedBuffer.resizable);
```

Output:

```text
false
```

Resizable buffers are useful when the required binary data size is not known in advance.

# 🗁 ArrayBuffer.prototype.transfer()

ES2024 introduced `ArrayBuffer.prototype.transfer()`.

It creates a new ArrayBuffer containing the original buffer's data and detaches the original buffer.

**Syntax**

```javascript
arrayBuffer.transfer(newByteLength);
```

The new length is optional. When omitted, the new buffer uses the original buffer's current byte length.

Example:

```javascript
const original = new ArrayBuffer(8);

const view = new Uint8Array(original);

view[0] = 100;
view[1] = 200;

const transferred = original.transfer();

console.log(transferred.byteLength);
console.log(new Uint8Array(transferred));
console.log(original.byteLength);
```

Output:

```text
8
Uint8Array(8) [100, 200, 0, 0, 0, 0, 0, 0]
0
```

After the transfer:

* The new buffer contains the original data.
* The original buffer becomes detached.
* The original buffer can no longer be used normally.

**Transferring with a different size:**

```javascript
const original = new ArrayBuffer(4);

const view = new Uint8Array(original);

view.set([10, 20, 30, 40]);

const transferred = original.transfer(8);

console.log(new Uint8Array(transferred));
```

Output:

```text
Uint8Array(8) [10, 20, 30, 40, 0, 0, 0, 0]
```

If the new buffer is smaller, excess bytes are discarded.

# 🗁 ArrayBuffer.prototype.transferToFixedLength()

ES2024 introduced `transferToFixedLength()`.

It transfers an ArrayBuffer into a new fixed-length ArrayBuffer and detaches the original.

**Syntax**

```javascript
arrayBuffer.transferToFixedLength(newByteLength);
```

Example:

```javascript
const original = new ArrayBuffer(8, {
  maxByteLength: 16
});

const transferred = original.transferToFixedLength(12);

console.log(transferred.byteLength);
console.log(transferred.resizable);
console.log(original.byteLength);
```

Output:

```text
12
false
0
```

The resulting buffer has a fixed length even though the original buffer was resizable.

This is useful when a resizable buffer needs to become a fixed-size buffer before being passed to another operation.

# 🗁 Growable SharedArrayBuffer

ES2024 standardized growable `SharedArrayBuffer` support.

A `SharedArrayBuffer` allows multiple execution contexts, such as workers, to access shared memory.

A growable SharedArrayBuffer can increase its byte length up to a predefined maximum.

Example:

```javascript
const sharedBuffer = new SharedArrayBuffer(8, {
  maxByteLength: 16
});

console.log(sharedBuffer.byteLength);
console.log(sharedBuffer.maxByteLength);
console.log(sharedBuffer.growable);
```

Output:

```text
8
16
true
```

**Growing the buffer:**

```javascript
sharedBuffer.grow(12);

console.log(sharedBuffer.byteLength);
```

Output:

```text
12
```

Unlike a resizable ArrayBuffer, a SharedArrayBuffer can grow but cannot shrink.

This capability is useful for shared-memory applications involving workers and concurrent processing.

# 🗁 RegExp v Flag

ES2024 introduced the `v` flag for regular expressions.

The flag enables advanced Unicode-aware matching features, including Unicode properties of strings and set operations inside character classes.

It is an extension of Unicode-aware regular expression processing.

Example:

```javascript
const pattern = /\p{Emoji}/v;

console.log(pattern.test("😀"));
```

Output:

```text
true
```

**Unicode property matching:**

```javascript
const pattern = /\p{Script=Greek}+/v;

console.log(pattern.test("Καλημέρα"));
```

Output:

```text
true
```

**Character class intersection:**

The `v` flag supports set intersection using `&&`.

```javascript
const pattern = /[\p{Script=Greek}&&\p{Letter}]+/v;

console.log(pattern.test("Καλημέρα"));
console.log(pattern.test("Hello"));
```

Output:

```text
true
false
```

The pattern matches characters that belong to both the Greek script and the Unicode Letter category.

**Character class subtraction:**

The `v` flag also supports set subtraction using `--`.

```javascript
const pattern = /[\p{ASCII}--\p{Decimal_Number}]+/v;

console.log(pattern.test("Hello"));
console.log(pattern.test("123"));
```

Output:

```text
true
false
```

The pattern matches ASCII characters excluding decimal digits.

The `v` flag also changes how certain character classes and Unicode properties of strings are interpreted. It cannot be combined with the `u` flag in the same regular expression.

# 🗁 String.prototype.isWellFormed()

JavaScript strings use UTF-16 encoding.

A Unicode character outside the Basic Multilingual Plane is represented using a surrogate pair.

A string can contain an unpaired surrogate, which is an individual high or low surrogate without its corresponding pair.

ES2024 introduced `String.prototype.isWellFormed()` to check whether a string contains only well-formed UTF-16 sequences.

Example:

```javascript
const valid = "Hello World";
const invalid = "\uD800";

console.log(valid.isWellFormed());
console.log(invalid.isWellFormed());
```

Output:

```text
true
false
```

**Valid surrogate pair:**

```javascript
const emoji = "😀";

console.log(emoji.isWellFormed());
```

Output:

```text
true
```

This method is useful when validating strings before passing them to systems that require well-formed Unicode text.

# 🗁 String.prototype.toWellFormed()

ES2024 introduced `String.prototype.toWellFormed()`.

It returns a new string in which unpaired surrogates are replaced with the Unicode replacement character, U+FFFD.

Example:

```javascript
const invalid = "Hello \uD800 World";

const valid = invalid.toWellFormed();

console.log(valid);
console.log(valid.isWellFormed());
```

Output:

```text
Hello � World
true
```

**Comparison with isWellFormed():**

| Method | Purpose |
|---|---|
| `isWellFormed()` | Checks whether a string contains well-formed UTF-16 |
| `toWellFormed()` | Returns a string with unpaired surrogates replaced |

These methods are useful for preparing text for APIs, network protocols, and other systems that require well-formed Unicode data.

# 🗁 Atomics.waitAsync()

ES2024 introduced `Atomics.waitAsync()`.

It allows asynchronous waiting on a shared memory location without blocking the current thread.

This is useful in applications that coordinate work between multiple workers.

Example:

```javascript
const sharedBuffer = new SharedArrayBuffer(4);

const sharedArray = new Int32Array(sharedBuffer);

const result = Atomics.waitAsync(
  sharedArray,
  0,
  0,
  1000
);

console.log(result.async);
```

Output:

```text
true
```

The result is an object containing:

* `async`: Indicates whether the operation is asynchronous.
* `value`: Either a string result or a promise resolving to the result.

**Waking a waiting operation:**

```javascript
const sharedBuffer = new SharedArrayBuffer(4);

const sharedArray = new Int32Array(sharedBuffer);

const result = Atomics.waitAsync(
  sharedArray,
  0,
  0
);

if (result.async) {
  result.value.then(console.log);
}

Atomics.store(sharedArray, 0, 1);

Atomics.notify(sharedArray, 0);
```

The waiting operation resolves with:

```text
ok
```

Important characteristics:

* It works with shared memory.
* It does not block the current JavaScript thread.
* It returns a promise when waiting is required.
* It can be used to coordinate workers.
* It must operate on supported integer typed-array views over a SharedArrayBuffer.

# 🗁 Practical Example: Grouping Application Data

The following example combines `Object.groupBy()`, `Map.groupBy()`, and `toSorted()` to organize application data.

```javascript
const orders = [
  { id: 101, status: "pending", total: 150 },
  { id: 102, status: "completed", total: 300 },
  { id: 103, status: "pending", total: 200 },
  { id: 104, status: "cancelled", total: 100 },
  { id: 105, status: "completed", total: 250 }
];

// Group orders by status.
const groupedOrders = Object.groupBy(
  orders,
  order => order.status
);

// Sort completed orders by total.
const sortedCompletedOrders = groupedOrders.completed.toSorted(
  (a, b) => b.total - a.total
);

console.log(groupedOrders);
console.log(sortedCompletedOrders);

// Create a promise with external settlement functions.
const {
  promise,
  resolve
} = Promise.withResolvers();

promise.then(result => {
  console.log(result);
});

resolve("Order processing completed");
```

This demonstrates how ES2024 features simplify grouping, sorting, and asynchronous coordination.

# 🗁 Browser and Runtime Compatibility

ES2024 features are supported by modern JavaScript engines, but support can vary across browsers and runtime versions.

Important considerations:

* `Object.groupBy()` and `Map.groupBy()` require modern runtime support.
* `Promise.withResolvers()` requires ES2024 Promise support.
* Resizable and transferable ArrayBuffers require runtime support.
* Growable SharedArrayBuffer support depends on the execution environment.
* The RegExp `v` flag requires Unicode set notation support.
* `isWellFormed()` and `toWellFormed()` require modern string method support.
* `Atomics.waitAsync()` requires support for asynchronous shared-memory waiting.

A transpiler may transform some syntax, but built-in methods and runtime capabilities may still need polyfills or compatible environments.

# 🗁 Best Practices

* Use `Object.groupBy()` when grouping data by string or symbol keys.
* Use `Map.groupBy()` when grouping requires object keys or Map behavior.
* Use `Promise.withResolvers()` when promise settlement must be controlled externally.
* Use resizable buffers when binary data size changes dynamically.
* Use transferable buffers when ownership of an ArrayBuffer needs to move to a new buffer.
* Use `transferToFixedLength()` when a fixed-size buffer is required.
* Use the RegExp `v` flag for advanced Unicode-aware pattern matching.
* Use `isWellFormed()` to validate UTF-16 strings.
* Use `toWellFormed()` to normalize strings containing unpaired surrogates.
* Use `Atomics.waitAsync()` for asynchronous shared-memory coordination.
