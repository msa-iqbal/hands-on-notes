# ECMAScript 2021 (ES12)

ECMAScript 2021, commonly known as ES12, is the twelfth edition of the ECMAScript language specification.

It was released in June 2021 and introduced improvements to strings, promises, logical assignment, numeric separators, and private class elements.

ES2021 focused on making everyday JavaScript operations more concise and improving the language's support for encapsulation and asynchronous programming.

# 🗁 What Is ECMAScript 2021?

ECMAScript 2021 continued the annual evolution of JavaScript with several practical language improvements.

Its features include:

* Logical assignment operators.
* Numeric separators.
* String replacement methods.
* Promise concurrency improvements.
* Private class elements.
* Weak references and finalization mechanisms.

Important terminology:

* **ECMAScript:** The standardized specification that defines JavaScript.
* **ES12:** The informal name for ECMAScript 2021.
* **ES2021:** The official edition name.
* **TC39:** The committee responsible for evolving ECMAScript.

# 🗁 Major ES2021 Features

| Feature | Description |
| --- | --- |
| Logical AND assignment (`&&=`) | Assigns a value when the left operand is truthy |
| Logical OR assignment (`\|\|=`) | Assigns a value when the left operand is falsy |
| Nullish coalescing assignment (`??=`) | Assigns a value when the left operand is nullish |
| Numeric separators (`_`) | Improves readability of large numeric literals |
| `String.prototype.replaceAll()` | Replaces all matching occurrences in a string |
| `Promise.any()` | Fulfills when the first input promise fulfills |
| Private class methods and accessors | Supports private methods and getters/setters |
| `WeakRef` | Provides a weak reference to an object |
| `FinalizationRegistry` | Allows registering cleanup callbacks for garbage-collected objects |

# 🗁 Logical AND Assignment Operator

The logical AND assignment operator (`&&=`) assigns a new value only when the existing value is truthy.

**Syntax**

```javascript
variable &&= value;
```

It is conceptually equivalent to:

```javascript
variable && (variable = value);
```

Example:

```javascript
let username = "Alice";

username &&= "Bob";

console.log(username);
```

Output:

```text
Bob
```

Because `username` is truthy, the assignment occurs.

When the existing value is falsy, the assignment does not happen.

```javascript
let username = "";

username &&= "Bob";

console.log(username);
```

Output:

```text
""
```

Common falsy values include:

* `false`
* `0`
* `-0`
* `0n`
* `""`
* `null`
* `undefined`
* `NaN`

**Practical example:**

```javascript
let user = {
  name: "Alice",
  email: ""
};

user.email &&= "alice@example.com";

console.log(user.email); // ""
```

The assignment does not happen because the original email is an empty string.

# 🗁 Logical OR Assignment Operator

The logical OR assignment operator (`||=`) assigns a new value only when the existing value is falsy.

**Syntax**

```javascript
variable ||= value;
```

It is conceptually equivalent to:

```javascript
variable || (variable = value);
```

Example:

```javascript
let username = "";

username ||= "Guest";

console.log(username);
```

Output:

```text
Guest
```

Because the original value is falsy, the fallback value is assigned.

If the existing value is truthy, it remains unchanged.

```javascript
let username = "Alice";

username ||= "Guest";

console.log(username);
```

Output:

```text
Alice
```

**Practical example:**

```javascript
const settings = {
  theme: "",
  language: "en"
};

settings.theme ||= "light";
settings.language ||= "bn";

console.log(settings);
```

Output:

```javascript
{
  theme: "light",
  language: "en"
}
```

# 🗁 Nullish Coalescing Assignment Operator

The nullish coalescing assignment operator (`??=`) assigns a value only when the existing value is `null` or `undefined`.

**Syntax**

```javascript
variable ??= value;
```

It is conceptually equivalent to:

```javascript
variable ?? (variable = value);
```

Example:

```javascript
let username = null;

username ??= "Guest";

console.log(username);
```

Output:

```text
Guest
```

If the existing value is not nullish, it remains unchanged.

```javascript
let count = 0;

count ??= 100;

console.log(count);
```

Output:

```text
0
```

**Practical example:**

```javascript
const settings = {
  theme: null,
  notifications: false,
  pageSize: 0
};

settings.theme ??= "light";
settings.notifications ??= true;
settings.pageSize ??= 20;

console.log(settings);
```

Output:

```javascript
{
  theme: "light",
  notifications: false,
  pageSize: 0
}
```

Only the `theme` property receives a fallback value.

# 🗁 Logical Assignment Operators Comparison

ES2021 introduced three logical assignment operators.

| Operator | Assignment condition | Example |
| --- | --- | --- |
| `&&=` | Left operand is truthy | `value &&= fallback` |
| `\|\|=` | Left operand is falsy | `value \|\|= fallback` |
| `??=` | Left operand is `null` or `undefined` | `value ??= fallback` |

Example:

```javascript
let first = "Hello";
let second = "";
let third = null;

first &&= "World";
second ||= "JavaScript";
third ??= "ES2021";

console.log(first);  // World
console.log(second); // JavaScript
console.log(third);  // ES2021
```

These operators use short-circuit evaluation. The right-hand expression is evaluated only when an assignment is required.

# 🗁 Numeric Separators

ES2021 introduced numeric separators using the underscore (`_`) character.

Numeric separators improve the readability of large numeric literals.

Example:

```javascript
const population = 1_000_000;

console.log(population);
```

Output:

```text
1000000
```

Without separators, large numbers can be difficult to read.

```javascript
const first = 1000000000;
const second = 1_000_000_000;

console.log(first === second); // true
```

**Using separators in different numeric formats:**

```javascript
const integer = 1_000_000;
const decimal = 123_456.789_123;
const binary = 0b1010_0001;
const hexadecimal = 0xFF_FF;
const bigInteger = 9_007_199_254_740_993n;

console.log(integer);
console.log(decimal);
console.log(binary);
console.log(hexadecimal);
console.log(bigInteger);
```

Numeric separators do not change the actual numeric value.

**Important rules:**

* Separators must appear between digits.
* A separator cannot appear at the beginning or end of a numeric literal.
* A separator cannot be placed directly next to a decimal point.
* Separators cannot be used in the exponent marker position.
* Separators improve readability but do not affect arithmetic.

# 🗁 String.prototype.replaceAll()

ES2021 introduced `String.prototype.replaceAll()`.

It returns a new string in which all occurrences of a specified pattern are replaced.

Unlike `replace()`, it replaces every matching occurrence when using a string search value.

**Syntax**

```javascript
string.replaceAll(searchValue, replaceValue);
```

Example:

```javascript
const message = "JavaScript is great. JavaScript is powerful.";

const result = message.replaceAll("JavaScript", "TypeScript");

console.log(result);
```

Output:

```text
TypeScript is great. TypeScript is powerful.
```

**Comparison with replace():**

```javascript
const message = "apple apple apple";

console.log(message.replace("apple", "orange"));

console.log(message.replaceAll("apple", "orange"));
```

Output:

```text
orange apple apple
orange orange orange
```

**Using regular expressions:**

`replaceAll()` also accepts regular expressions, but a regular expression must have the global (`g`) flag.

```javascript
const message = "Hello 123, Welcome 456";

const result = message.replaceAll(/\d+/g, "#");

console.log(result);
```

Output:

```text
Hello #, Welcome #
```

Using a regular expression without the global flag throws a `TypeError`.

**Practical example:**

```javascript
const template = "Hello {{name}}, welcome to {{platform}}!";

const result = template
  .replaceAll("{{name}}", "Alice")
  .replaceAll("{{platform}}", "JavaScript");

console.log(result);
```

Output:

```text
Hello Alice, welcome to JavaScript!
```

# 🗁 Promise.any()

ES2021 introduced `Promise.any()`.

It accepts an iterable of promises and returns a Promise that fulfills as soon as the first input promise fulfills.

Unlike `Promise.race()`, it ignores rejected promises while waiting for a successful result.

**Syntax**

```javascript
Promise.any(iterable);
```

Example:

```javascript
const promises = [
  Promise.reject("Server 1 failed"),
  Promise.resolve("Server 2 responded"),
  Promise.resolve("Server 3 responded")
];

Promise.any(promises)
  .then(result => {
    console.log(result);
  })
  .catch(error => {
    console.error(error);
  });
```

Output:

```text
Server 2 responded
```

The first fulfilled promise determines the result.

**When every promise rejects:**

If all input promises reject, `Promise.any()` rejects with an `AggregateError`.

```javascript
const promises = [
  Promise.reject("Request 1 failed"),
  Promise.reject("Request 2 failed"),
  Promise.reject("Request 3 failed")
];

Promise.any(promises)
  .then(result => {
    console.log(result);
  })
  .catch(error => {
    console.log(error instanceof AggregateError);
    console.log(error.errors);
  });
```

Output:

```text
true
[
  "Request 1 failed",
  "Request 2 failed",
  "Request 3 failed"
]
```

**Promise concurrency methods comparison:**

| Method | Behavior |
| --- | --- |
| `Promise.all()` | Fulfills when all promises fulfill; rejects when an input rejects |
| `Promise.allSettled()` | Fulfills after every promise settles |
| `Promise.race()` | Settles with the first promise to settle |
| `Promise.any()` | Fulfills with the first fulfilled promise; rejects if all inputs reject |

**Practical example:**

```javascript
async function getAvailableServer() {
  const servers = [
    fetch("https://server-one.example.com/data"),
    fetch("https://server-two.example.com/data"),
    fetch("https://server-three.example.com/data")
  ];

  try {
    const response = await Promise.any(servers);

    console.log("Available server:", response.url);

    return response;
  } catch (error) {
    console.error("All servers failed:", error.errors);
  }
}
```

This example selects the first fulfilled fetch promise. A fulfilled HTTP response does not necessarily indicate a successful HTTP status, so applications should still check `response.ok`.

# 🗁 Private Class Methods and Accessors

ES2021 extended JavaScript private class elements to support private methods, getters, and setters.

Private elements are declared using the `#` prefix.

They can only be accessed from within the class body.

**Private method:**

```javascript
class User {
  #name = "Alice";

  #getName() {
    return this.#name;
  }

  displayName() {
    return this.#getName();
  }
}

const user = new User();

console.log(user.displayName());
```

Output:

```text
Alice
```

Trying to access the private method outside the class results in a syntax error.

```javascript
user.#getName();
```

**Private getter and setter:**

```javascript
class User {
  #name = "Alice";

  get #userName() {
    return this.#name;
  }

  set #userName(value) {
    this.#name = value;
  }

  updateName(value) {
    this.#userName = value;
  }

  displayName() {
    return this.#userName;
  }
}

const user = new User();

user.updateName("Bob");

console.log(user.displayName());
```

Output:

```text
Bob
```

Private getters and setters can be useful for internal data validation and encapsulation.

**Important characteristics:**

* Private methods cannot be accessed directly outside their declaring class.
* Private elements are not ordinary object properties.
* Private elements are not enumerable.
* Private methods can access other private elements of the same class.
* Subclasses cannot directly access private elements declared by their parent class.

# 🗁 WeakRef

ES2021 introduced the `WeakRef` class.

A WeakRef creates a weak reference to an object without preventing that object from being garbage-collected.

Ordinary JavaScript references keep objects reachable.

A weak reference does not, by itself, keep its target alive.

**Creating a WeakRef:**

```javascript
let user = {
  name: "Alice"
};

const userReference = new WeakRef(user);

console.log(userReference.deref());
```

The `deref()` method returns the referenced object if it is still available.

If the object has been garbage-collected, `deref()` returns `undefined`.

Example:

```javascript
const user = {
  name: "Alice"
};

const reference = new WeakRef(user);

const value = reference.deref();

if (value) {
  console.log(value.name);
}
```

Output:

```text
Alice
```

**Important characteristics:**

* WeakRef can only reference objects.
* It does not prevent its target from being garbage-collected.
* The target may disappear at any time after becoming unreachable through strong references.
* Garbage collection timing is not predictable.
* A WeakRef should not be used as the foundation of essential application logic.

WeakRef is useful in specialized memory-sensitive scenarios, such as caches that can tolerate entries disappearing.

# 🗁 FinalizationRegistry

ES2021 introduced `FinalizationRegistry`.

It allows developers to register cleanup callbacks that may run when an object becomes eligible for garbage collection.

**Creating a registry:**

```javascript
const registry = new FinalizationRegistry(value => {
  console.log(`Object finalized: ${value}`);
});
```

**Registering an object:**

```javascript
let user = {
  name: "Alice"
};

registry.register(user, "Alice");

user = null;
```

When the object becomes eligible for garbage collection, the registry may eventually execute the cleanup callback.

The registered value is called the held value.

**Unregistering an object:**

A registration can include an unregister token.

```javascript
const registry = new FinalizationRegistry(value => {
  console.log("Cleanup:", value);
});

const token = {};

let resource = {
  name: "Temporary resource"
};

registry.register(resource, "resource-1", token);

registry.unregister(token);
```

Unregistering removes the associated registration.

**Important characteristics:**

* Cleanup callbacks are not guaranteed to execute.
* Their execution time is unpredictable.
* The registry must not be relied upon for critical resource cleanup.
* The held value must not keep the target object alive indirectly.
* External resources should be released explicitly when deterministic cleanup is required.

For example, use `try...finally`, explicit disposal methods, or supported resource-management APIs for important cleanup operations.

# 🗁 Practical Example: Combining ES2021 Features

The following example combines logical assignment, numeric separators, string replacement, and private class methods.

```javascript
class ShoppingCart {
  #items = [];

  addItem(item) {
    this.#items.push(item);
  }

  #calculateTotal() {
    return this.#items.reduce(
      (total, item) => total + item.price,
      0
    );
  }

  getTotal() {
    return this.#calculateTotal();
  }

  getSummary() {
    return `Total: $${this.getTotal().toLocaleString()}`;
  }
}

const cart = new ShoppingCart();

const defaultDiscount = 0;
defaultDiscount ||= 100;

cart.addItem({
  name: "Laptop",
  price: 1_000
});

cart.addItem({
  name: "Keyboard",
  price: 100
});

const summary = cart.getSummary();

console.log(summary.replaceAll("Total", "Cart Total"));
```

Output:

```text
Cart Total: $1,100
```

Features used:

* Private class fields and methods for encapsulation.
* Numeric separators for readable numeric literals.
* Logical OR assignment for fallback initialization.
* `replaceAll()` for replacing text.

# 🗁 Browser and Runtime Compatibility

ES2021 features are supported by modern JavaScript engines.

Older browsers and runtime environments may require transpilation or polyfills.

Important considerations:

* Logical assignment operators require syntax support or transpilation.
* Numeric separators require parser support.
* `replaceAll()` may require a polyfill in older environments.
* `Promise.any()` may require a polyfill.
* Private class methods require modern class syntax support.
* WeakRef and FinalizationRegistry require native runtime support and cannot be reliably reproduced through ordinary polyfills.

Transpilation can transform some syntax, but garbage-collection-related features depend on runtime capabilities.

# 🗁 Best Practices

* Use `&&=` when assignment should happen only for truthy values.
* Use `||=` when a fallback should be assigned for falsy values.
* Use `??=` when only nullish values should trigger assignment.
* Use numeric separators to improve the readability of large numeric literals.
* Use `replaceAll()` when every matching occurrence should be replaced.
* Use `Promise.any()` when the first successful asynchronous operation is sufficient.
* Use `Promise.allSettled()` when every operation's outcome must be collected.
* Use private methods to keep implementation details inside classes.
* Use WeakRef only when the application can tolerate the referenced object disappearing.
* Never depend on FinalizationRegistry for essential cleanup.
* Prefer deterministic resource management for files, connections, and other external resources.
