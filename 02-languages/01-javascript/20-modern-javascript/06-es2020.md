# ECMAScript 2020 (ES11)

ECMAScript 2020, commonly known as ES11, is the eleventh edition of the ECMAScript language specification.

It was released in June 2020 and introduced several important features, including optional chaining, nullish coalescing, BigInt, dynamic imports, and improvements to promises and modules.

ES2020 made JavaScript more expressive and convenient, particularly when working with optional object properties, large integers, asynchronous operations, and modular applications.

# 🗁 What Is ECMAScript 2020?

ECMAScript 2020 continued the annual evolution of JavaScript by introducing features that improve everyday development workflows.

Some of its additions address common problems developers encounter when accessing nested properties, handling missing values, working with large numbers, and loading modules dynamically.

Important terminology:

* **ECMAScript:** The standardized specification that defines JavaScript.
* **ES11:** The informal name for ECMAScript 2020.
* **ES2020:** The official edition name.
* **TC39:** The committee responsible for evolving ECMAScript.

| Feature | Description |

# 🗁 Optional Chaining

Optional chaining (`?.`) allows you to safely access properties, methods, or array elements when an intermediate value might be `null` or `undefined`.

Before ES2020, developers often used conditional checks to avoid runtime errors.

Example without optional chaining:

```javascript
const user = {
  profile: {
    name: "Alice"
  }
};

const city = user && user.profile && user.profile.city;

console.log(city);
```

Output:

```text
undefined
```

Using optional chaining:

```javascript
const user = {
  profile: {
    name: "Alice"
  }
};

const city = user?.profile?.city;

console.log(city);
```

Output:

```text
undefined
```

If an intermediate value is `null` or `undefined`, the expression short-circuits and returns `undefined`.

**Optional property access**

```javascript
const user = {
  name: "Alice"
};

console.log(user?.name);    // Alice
console.log(user?.email);   // undefined
```

**Optional method calls**

```javascript
const user = {
  name: "Alice"
};

user.getName?.();

console.log("Execution completed");
```

If `getName` does not exist or is nullish, the optional call returns `undefined` instead of throwing an error.

**Optional array access**

```javascript
const users = ["Alice", "Bob"];

console.log(users?.[0]); // Alice
console.log(users?.[5]); // undefined
```

**Optional chaining with function calls**

```javascript
const user = {
  greet() {
    return "Hello!";
  }
};

console.log(user.greet?.()); // Hello!
```

Optional chaining only protects the part of an expression where it is applied. It does not automatically make every subsequent property access safe.

# 🗁 Nullish Coalescing Operator

The nullish coalescing operator (`??`) returns the right-hand value when the left-hand value is `null` or `undefined`.

Otherwise, it returns the left-hand value.

**Syntax**

```javascript
value ?? fallback;
```

Example:

```javascript
const username = null;

const result = username ?? "Guest";

console.log(result);
```

Output:

```text
Guest
```

**Comparison with the logical OR operator**

The logical OR operator (`||`) uses truthiness to determine whether to return the fallback value.

The nullish coalescing operator (`??`) only checks for `null` and `undefined`.

```javascript
const count = 0;

console.log(count || 10); // 10
console.log(count ?? 10); // 0
```

More examples:

```javascript
console.log(null ?? "Default");      // Default
console.log(undefined ?? "Default"); // Default
console.log(0 ?? 100);               // 0
console.log(false ?? true);          // false
console.log("" ?? "Hello");          // ""
```

**Comparison table**

| Value | `value || fallback` | `value ?? fallback` |
|---|---|---|
| `null` | Fallback | Fallback |
| `undefined` | Fallback | Fallback |
| `0` | Fallback | `0` |
| `false` | Fallback | `false` |
| `""` | Fallback | `""` |
| `"Hello"` | `"Hello"` | `"Hello"` |

Use `??` when only missing values should trigger a fallback.

# 🗁 Combining Optional Chaining and Nullish Coalescing

These operators are frequently used together when working with optional object properties.

Example:

```javascript
const user = {
  profile: {
    name: "Alice"
  }
};

const city = user?.profile?.city ?? "Unknown";

console.log(city);
```

Output:

```text
Unknown
```

Another example:

```javascript
const settings = {
  appearance: {
    theme: "dark"
  }
};

const theme = settings?.appearance?.theme ?? "light";

console.log(theme);
```

Output:

```text
dark
```

This combination is particularly useful when handling API responses, configuration objects, and user preferences.

# 🗁 BigInt

ES2020 introduced the BigInt primitive type.

BigInt represents integers larger than the maximum safe integer supported by JavaScript's Number type.

The maximum safe integer is:

```javascript
Number.MAX_SAFE_INTEGER;
```

Output:

```text
9007199254740991
```

Numbers larger than this limit may lose integer precision.

Example:

```javascript
const number = 9007199254740993;

console.log(number);
```

Output:

```text
9007199254740992
```

The value is not represented exactly.

**Creating BigInt values**

There are two common ways to create BigInt values.

Using the `n` suffix:

```javascript
const largeNumber = 9007199254740993n;

console.log(largeNumber);
```

Using the `BigInt()` function:

```javascript
const largeNumber = BigInt("9007199254740993");

console.log(largeNumber);
```

Both examples represent the exact integer.

**BigInt arithmetic**

BigInt supports arithmetic operations such as addition, subtraction, multiplication, division, and exponentiation.

```javascript
const first = 10000000000000000n;
const second = 20000000000000000n;

console.log(first + second);
console.log(first * second);
console.log(second - first);
```

**Division behavior**

BigInt division truncates the fractional part.

```javascript
const result = 10n / 3n;

console.log(result); // 3n
```

**Important BigInt limitations**

* BigInt cannot be mixed directly with Number in arithmetic operations.
* BigInt does not support decimal fractions.
* BigInt division truncates toward zero.
* BigInt cannot be serialized directly using the default `JSON.stringify()` behavior.

Example of incompatible arithmetic:

```javascript
const first = 10n;
const second = 5;

console.log(first + second); // TypeError
```

Convert explicitly when mixing numeric types:

```javascript
const first = 10n;
const second = 5;

console.log(first + BigInt(second)); // 15n
```

Converting BigInt to Number can lose precision when the value exceeds the safe integer range.

# 🗁 Dynamic Import

ES2020 standardized dynamic imports using the `import()` function-like syntax.

Dynamic import allows JavaScript modules to be loaded when needed instead of being loaded through static import declarations.

Unlike static imports, dynamic imports can be used inside expressions and control-flow statements.

**Syntax**

```javascript
import(moduleSpecifier);
```

Dynamic import returns a Promise that fulfills with the module namespace object.

Example:

```javascript
async function loadModule() {
  const module = await import("./math.js");

  console.log(module.add(10, 20));
}

loadModule();
```

Example module:

```javascript
// math.js

export function add(a, b) {
  return a + b;
}
```

**Using dynamic import with then()**

```javascript
import("./math.js")
  .then(module => {
    console.log(module.add(10, 20));
  })
  .catch(error => {
    console.error("Module loading failed:", error);
  });
```

**Conditional module loading**

```javascript
async function loadFeature(enabled) {
  if (enabled) {
    const module = await import("./feature.js");

    module.initialize();
  }
}
```

**Practical use cases**

* Lazy loading application features.
* Loading modules based on user actions.
* Splitting application bundles.
* Loading optional dependencies.
* Reducing the initial JavaScript payload.

Dynamic import is commonly used by modern frontend frameworks and bundlers to implement code splitting.

# 🗁 Promise.allSettled()

ES2020 introduced `Promise.allSettled()`.

It accepts an iterable of promises and returns a Promise that fulfills after every input promise has settled.

A promise is settled when it either fulfills or rejects.

Unlike `Promise.all()`, `Promise.allSettled()` does not reject simply because one of its input promises rejects.

**Syntax**

```javascript
Promise.allSettled(iterable);
```

Example:

```javascript
const promises = [
  Promise.resolve("Task 1 completed"),
  Promise.reject(new Error("Task 2 failed")),
  Promise.resolve("Task 3 completed")
];

Promise.allSettled(promises).then(results => {
  console.log(results);
});
```

Output:

```javascript
[
  {
    status: "fulfilled",
    value: "Task 1 completed"
  },
  {
    status: "rejected",
    reason: Error: Task 2 failed
  },
  {
    status: "fulfilled",
    value: "Task 3 completed"
  }
]
```

Each result contains a `status` property.

Fulfilled results contain a `value` property.

Rejected results contain a `reason` property.

**Processing results**

```javascript
const tasks = [
  Promise.resolve(100),
  Promise.reject("Request failed"),
  Promise.resolve(300)
];

async function processTasks() {
  const results = await Promise.allSettled(tasks);

  results.forEach((result, index) => {
    if (result.status === "fulfilled") {
      console.log(`Task ${index + 1}:`, result.value);
    } else {
      console.error(`Task ${index + 1}:`, result.reason);
    }
  });
}

processTasks();
```

**Promise.all() vs Promise.allSettled()**

| Promise.all() | Promise.allSettled() |
| --- | --- |
| Fulfills when all inputs fulfill | Fulfills when all inputs settle |
| Rejects when an input rejects | Does not reject because an input rejects |
| Returns fulfillment values | Returns settlement result objects |
| Useful when all operations must succeed | Useful when every operation's outcome matters |

# 🗁 String.prototype.matchAll()

ES2020 introduced `String.prototype.matchAll()`.

It returns an iterator containing all matches of a regular expression, including capturing groups.

Unlike `match()`, it provides detailed information about each match.

**Syntax**

```javascript
string.matchAll(regexp);
```

The regular expression must have the global (`g`) flag.

Example:

```javascript
const text = "JavaScript is great. JavaScript is flexible.";

const matches = text.matchAll(/JavaScript/g);

for (const match of matches) {
  console.log(match[0]);
  console.log(match.index);
}
```

Output:

```text
JavaScript
0
JavaScript
21
```

**Accessing capture groups**

```javascript
const text = "User: Alice, Age: 25";

const pattern = /User: (\w+), Age: (\d+)/g;

const matches = text.matchAll(pattern);

for (const match of matches) {
  console.log(match[1]);
  console.log(match[2]);
}
```

Output:

```text
Alice
25
```

**Using named capture groups**

```javascript
const text = "2026-11-14";

const pattern = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/g;

const matches = text.matchAll(pattern);

for (const match of matches) {
  console.log(match.groups.year);
  console.log(match.groups.month);
  console.log(match.groups.day);
}
```

Output:

```text
2026
11
14
```

The returned iterator can be consumed using `for...of` or converted into an array.

```javascript
const text = "cat dog cat";

const matches = [...text.matchAll(/cat/g)];

console.log(matches.length); // 2
```

# 🗁 globalThis

ES2020 introduced `globalThis`, providing a standard way to access the global object across different JavaScript environments.

Before `globalThis`, accessing the global object often required environment-specific references.

Examples:

```javascript
window; // Browser
global; // Node.js
self;   // Web Workers
```

With `globalThis`:

```javascript
console.log(globalThis);
```

The same identifier works across standard JavaScript environments.

**Adding a global property**

```javascript
globalThis.applicationName = "My Application";

console.log(globalThis.applicationName);
```

Output:

```text
My Application
```

**Checking the environment**

```javascript
if (typeof window !== "undefined") {
  console.log("Running in a browser");
} else if (typeof process !== "undefined") {
  console.log("Running in a Node.js environment");
}
```

`globalThis` provides access to the global object, but it does not make browser-specific APIs available in Node.js or Node.js-specific APIs available in browsers.

# 🗁 import.meta

ES2020 introduced `import.meta`, which exposes metadata about the currently executing JavaScript module.

It is available in ECMAScript modules.

Example:

```javascript
console.log(import.meta);
```

The metadata object is host-defined, so its properties depend on the JavaScript environment.

In browsers and Node.js, `import.meta.url` provides the URL of the current module.

Example:

```javascript
console.log(import.meta.url);
```

A module can use this information to determine its own location.

**Practical example:**

```javascript
const currentModuleUrl = import.meta.url;

const configUrl = new URL("./config.json", currentModuleUrl);

console.log(configUrl.href);
```

This creates a URL relative to the current module.

`import.meta` is particularly useful for module-relative file and resource handling.

# 🗁 for-in Property Enumeration Ordering

ES2020 standardized the property enumeration order used by the `for...in` statement.

The ordering generally follows these rules for each object in the prototype chain:

* Own enumerable string-keyed properties are considered.
* Integer-index-like string keys are visited in ascending numeric order.
* Other string keys are visited in property creation order.
* Inherited enumerable string-keyed properties are considered after the object's own properties.
* A property name is not visited more than once.

Example:

```javascript
const user = {
  name: "Alice",
  10: "Ten",
  2: "Two",
  role: "Developer"
};

for (const key in user) {
  console.log(key);
}
```

Output:

```text
2
10
name
role
```

For reliable enumeration of an object's own enumerable properties, prefer `Object.keys()`, `Object.values()`, or `Object.entries()` when they match the requirement.

# 🗁 export * as Namespace

ES2020 introduced the ability to re-export all named exports from another module under a namespace.

This syntax is useful for organizing module exports.

**Example module:**

```javascript
// math.js

export function add(a, b) {
  return a + b;
}

export function subtract(a, b) {
  return a - b;
}
```

**Namespace re-export:**

```javascript
// index.js

export * as math from "./math.js";
```

**Importing the namespace:**

```javascript
import { math } from "./index.js";

console.log(math.add(10, 5));
console.log(math.subtract(10, 5));
```

Output:

```text
15
5
```

This approach provides a convenient way to group related exports.

# 🗁 Practical Example: Combining ES2020 Features

The following example combines optional chaining, nullish coalescing, dynamic imports, and `Promise.allSettled()`.

```javascript
async function loadUserData(userId) {
  try {
    const [userModule, settingsModule] = await Promise.all([
      import("./user-service.js"),
      import("./settings-service.js")
    ]);

    const results = await Promise.allSettled([
      userModule.getUser(userId),
      settingsModule.getSettings(userId)
    ]);

    const userResult = results[0];
    const settingsResult = results[1];

    const user =
      userResult.status === "fulfilled"
        ? userResult.value
        : null;

    const settings =
      settingsResult.status === "fulfilled"
        ? settingsResult.value
        : null;

    return {
      name: user?.profile?.name ?? "Guest",
      theme: settings?.appearance?.theme ?? "light"
    };
  } catch (error) {
    console.error("Failed to load modules:", error);

    return {
      name: "Guest",
      theme: "light"
    };
  }
}

loadUserData(101).then(console.log);
```

Features used:

* Dynamic import to load modules when needed.
* `Promise.all()` to load independent modules concurrently.
* `Promise.allSettled()` to handle individual operation outcomes.
* Optional chaining to safely access nested properties.
* Nullish coalescing to provide fallback values.

# 🗁 Browser and Runtime Compatibility

ES2020 features are supported by modern JavaScript engines.

Older browsers and runtime environments may require transpilation or polyfills.

Important considerations:

* Optional chaining and nullish coalescing require syntax support or transpilation.
* BigInt requires native runtime support and cannot be fully replaced by ordinary Number arithmetic.
* Dynamic import requires module-loading support.
* `Promise.allSettled()` may require a polyfill in older environments.
* `matchAll()` may require a polyfill.
* `globalThis` may require a compatibility solution in older engines.
* `import.meta` is available in ECMAScript modules, not ordinary scripts.
* BigInt serialization requires an explicit conversion strategy when using JSON.

A transpiler can transform supported syntax, but runtime APIs and built-in types may still require compatibility solutions.

# 🗁 Best Practices

* Use optional chaining when intermediate properties may be missing.
* Use nullish coalescing when only `null` and `undefined` should trigger a fallback.
* Prefer `??` over `||` when valid values such as `0`, `false`, or an empty string must be preserved.
* Use BigInt for integers that exceed the safe integer range.
* Avoid mixing BigInt and Number without explicit conversion.
* Use dynamic imports for lazy loading and code splitting.
* Use `Promise.allSettled()` when every asynchronous operation's outcome matters.
* Use `Promise.all()` when all operations must succeed.
* Use `matchAll()` when all regular expression matches and capture groups are required.
* Use `globalThis` for environment-independent access to the global object.
* Use `import.meta.url` for module-relative resource resolution.
* Use namespace re-exports to organize related module exports.
