# ECMAScript 2025 (ES16)

ECMAScript 2025, commonly known as ES16, is the sixteenth edition of the ECMAScript language specification.

It was finalized in June 2025 and introduced improvements to iterators, sets, regular expressions, promises, typed arrays, and module loading.

ES2025 focuses on making data processing more expressive, improving collection operations, and providing better tools for asynchronous and Unicode-aware programming.

# 🗁 What Is ECMAScript 2025?

ECMAScript 2025 is an annual update to the JavaScript language specification.

Important terminology:

* **ECMAScript:** The standardized specification that defines JavaScript.
* **ES16:** The informal name for ECMAScript 2025.
* **ES2025:** The official edition name.
* **TC39:** The committee responsible for evolving ECMAScript.

# 🗁 Major ES2025 Features

| Feature | Description |
| --- | --- |
| Iterator helpers | Provides methods for transforming and consuming iterators |
| `Iterator.from()` | Converts an iterable or iterator into an iterator with helper methods |
| Set methods | Adds mathematical set operations such as union, intersection, and difference |
| `RegExp.escape()` | Safely escapes strings for use as literal regular expression patterns |
| `Promise.try()` | Executes a callback and returns a promise for its result |
| `Float16Array` | Provides typed-array support for 16-bit floating-point values |
| `Math.f16round()` | Rounds a number to the nearest representable 16-bit floating-point value |
| Import attributes | Provides metadata for module imports, such as JSON module types |
| Duplicate named capture groups | Allows the same capture group name in mutually exclusive alternatives |
| Regular expression modifiers | Supports scoped case-insensitive and other modifier behavior within patterns |

# 🗁 Iterator Helpers

ES2025 introduced iterator helper methods.

They allow developers to transform, filter, and consume iterator values without manually implementing iterator loops.

Iterator helpers use lazy evaluation. This means values are generally processed only when the iterator is consumed.

Important iterator helper methods include:

| Method | Description |
| --- | --- |
| `map()` | Transforms each yielded value |
| `filter()` | Keeps values that satisfy a condition |
| `flatMap()` | Maps each value to an iterable and flattens the results |
| `take()` | Takes a specified number of values |
| `drop()` | Skips a specified number of values |
| `reduce()` | Combines iterator values into one result |
| `toArray()` | Collects iterator values into an array |
| `forEach()` | Executes a callback for each value |
| `some()` | Checks whether at least one value satisfies a condition |
| `every()` | Checks whether all values satisfy a condition |
| `find()` | Returns the first value satisfying a condition |

# 🗁 Iterator.from()

`Iterator.from()` converts an iterable or iterator into an iterator that supports iterator helper methods.

**Syntax**

```javascript
Iterator.from(iterableOrIterator);
```

Example:

```javascript
const numbers = [10, 20, 30, 40];

const iterator = Iterator.from(numbers);

console.log(iterator.toArray());
```

Output:

```text
[10, 20, 30, 40]
```

**Using an existing iterator:**

```javascript
function* generateNumbers() {
  yield 10;
  yield 20;
  yield 30;
}

const iterator = Iterator.from(generateNumbers());

console.log(iterator.next());
console.log(iterator.next());
```

Output:

```javascript
{ value: 10, done: false }
{ value: 20, done: false }
```

`Iterator.from()` is particularly useful when working with custom iterators that do not inherit the built-in iterator helper methods.

# 🗁 Iterator.map()

`map()` transforms each value produced by an iterator.

Example:

```javascript
const numbers = Iterator.from([1, 2, 3, 4]);

const doubled = numbers.map(number => number * 2);

console.log(doubled.toArray());
```

Output:

```text
[2, 4, 6, 8]
```

The transformation is lazy. The callback is executed as values are consumed.

**Example with objects:**

```javascript
const users = [
  { id: 1, name: "Alice" },
  { id: 2, name: "Bob" },
  { id: 3, name: "Charlie" }
];

const names = Iterator.from(users)
  .map(user => user.name);

console.log(names.toArray());
```

Output:

```text
["Alice", "Bob", "Charlie"]
```

# 🗁 Iterator.filter()

`filter()` returns an iterator containing only values that satisfy a condition.

Example:

```javascript
const numbers = Iterator.from([1, 2, 3, 4, 5, 6]);

const evenNumbers = numbers.filter(
  number => number % 2 === 0
);

console.log(evenNumbers.toArray());
```

Output:

```text
[2, 4, 6]
```

**Combining map() and filter():**

```javascript
const numbers = Iterator.from([1, 2, 3, 4, 5, 6]);

const result = numbers
  .filter(number => number > 2)
  .map(number => number * 10)
  .toArray();

console.log(result);
```

Output:

```text
[30, 40, 50, 60]
```

The operations are evaluated as the final iterator is consumed.

# 🗁 Iterator.flatMap()

`flatMap()` transforms each iterator value into an iterable and flattens the resulting values into a single iterator.

Example:

```javascript
const numbers = Iterator.from([1, 2, 3]);

const result = numbers.flatMap(number => [
  number,
  number * 10
]);

console.log(result.toArray());
```

Output:

```text
[1, 10, 2, 20, 3, 30]
```

This is useful when each input value produces multiple output values.

# 🗁 Iterator.take()

`take()` creates an iterator containing at most the specified number of values.

Example:

```javascript
const numbers = Iterator.from([10, 20, 30, 40, 50]);

const result = numbers.take(3);

console.log(result.toArray());
```

Output:

```text
[10, 20, 30]
```

If the source iterator contains fewer values than requested, `take()` returns all available values.

# 🗁 Iterator.drop()

`drop()` skips a specified number of values and returns an iterator containing the remaining values.

Example:

```javascript
const numbers = Iterator.from([10, 20, 30, 40, 50]);

const result = numbers.drop(2);

console.log(result.toArray());
```

Output:

```text
[30, 40, 50]
```

# 🗁 Iterator.reduce()

`reduce()` combines iterator values into a single result.

Example:

```javascript
const numbers = Iterator.from([1, 2, 3, 4, 5]);

const total = numbers.reduce(
  (sum, number) => sum + number,
  0
);

console.log(total);
```

Output:

```text
15
```

The callback receives the accumulated value and the current iterator value.

# 🗁 Iterator.toArray()

`toArray()` consumes an iterator and collects its remaining values into an array.

Example:

```javascript
const numbers = Iterator.from([10, 20, 30]);

const result = numbers.toArray();

console.log(result);
```

Output:

```text
[10, 20, 30]
```

Because iterators are generally consumable, calling `toArray()` exhausts the iterator.

# 🗁 Iterator.some(), every(), and find()

These methods allow developers to perform common checks and searches on iterator values.

**some():**

```javascript
const numbers = Iterator.from([1, 3, 5, 8]);

const hasEvenNumber = numbers.some(
  number => number % 2 === 0
);

console.log(hasEvenNumber);
```

Output:

```text
true
```

**every():**

```javascript
const numbers = Iterator.from([2, 4, 6, 8]);

const allEven = numbers.every(
  number => number % 2 === 0
);

console.log(allEven);
```

Output:

```text
true
```

**find():**

```javascript
const numbers = Iterator.from([10, 20, 30, 40]);

const result = numbers.find(
  number => number > 25
);

console.log(result);
```

Output:

```text
30
```

These methods stop consuming values once their result is determined.

# 🗁 Iterator.forEach()

`forEach()` executes a callback for every value produced by an iterator.

Example:

```javascript
const numbers = Iterator.from([10, 20, 30]);

numbers.forEach(number => {
  console.log(number);
});
```

Output:

```text
10
20
30
```

Unlike `map()`, `forEach()` is intended for side effects rather than producing a transformed iterator.

# 🗁 Set Methods

ES2025 introduced several methods for performing mathematical set operations.

These methods make it easier to compare and combine collections of unique values.

Important methods:

| Method | Description |
| --- | --- |
| `union()` | Returns elements present in either set |
| `intersection()` | Returns elements present in both sets |
| `difference()` | Returns elements present in the first set but not the second |
| `symmetricDifference()` | Returns elements present in either set, but not both |
| `isSubsetOf()` | Checks whether every element of one set exists in another |
| `isSupersetOf()` | Checks whether a set contains every element of another set |
| `isDisjointFrom()` | Checks whether two sets have no common elements |

# 🗁 Set.union()

`union()` returns a new Set containing all unique elements from both sets.

Example:

```javascript
const frontend = new Set([
  "JavaScript",
  "TypeScript",
  "HTML"
]);

const backend = new Set([
  "Node.js",
  "Python",
  "JavaScript"
]);

const technologies = frontend.union(backend);

console.log(technologies);
```

Output:

```text
Set(5) {
  "JavaScript",
  "TypeScript",
  "HTML",
  "Node.js",
  "Python"
}
```

Duplicate values appear only once.

# 🗁 Set.intersection()

`intersection()` returns a new Set containing elements shared by both sets.

Example:

```javascript
const frontend = new Set([
  "JavaScript",
  "TypeScript",
  "HTML"
]);

const backend = new Set([
  "Node.js",
  "Python",
  "JavaScript"
]);

const common = frontend.intersection(backend);

console.log(common);
```

Output:

```text
Set(1) {
  "JavaScript"
}
```

# 🗁 Set.difference()

`difference()` returns elements present in the first set but absent from the second.

Example:

```javascript
const frontend = new Set([
  "JavaScript",
  "TypeScript",
  "HTML"
]);

const backend = new Set([
  "Node.js",
  "Python",
  "JavaScript"
]);

const frontendOnly = frontend.difference(backend);

console.log(frontendOnly);
```

Output:

```text
Set(2) {
  "TypeScript",
  "HTML"
}
```

The operation is directional. Reversing the sets can produce a different result.

# 🗁 Set.symmetricDifference()

`symmetricDifference()` returns elements that exist in exactly one of the two sets.

Elements shared by both sets are excluded.

Example:

```javascript
const first = new Set([1, 2, 3, 4]);

const second = new Set([3, 4, 5, 6]);

const result = first.symmetricDifference(second);

console.log(result);
```

Output:

```text
Set(4) { 1, 2, 5, 6 }
```

# 🗁 Set.isSubsetOf()

`isSubsetOf()` checks whether every element of one set exists in another set.

Example:

```javascript
const required = new Set([
  "JavaScript",
  "HTML"
]);

const available = new Set([
  "JavaScript",
  "TypeScript",
  "HTML",
  "CSS"
]);

console.log(required.isSubsetOf(available));
```

Output:

```text
true
```

Every element in `required` exists in `available`.

# 🗁 Set.isSupersetOf()

`isSupersetOf()` checks whether a set contains every element of another set.

Example:

```javascript
const available = new Set([
  "JavaScript",
  "TypeScript",
  "HTML",
  "CSS"
]);

const required = new Set([
  "JavaScript",
  "HTML"
]);

console.log(available.isSupersetOf(required));
```

Output:

```text
true
```

# 🗁 Set.isDisjointFrom()

`isDisjointFrom()` checks whether two sets have no common elements.

Example:

```javascript
const frontend = new Set([
  "JavaScript",
  "HTML",
  "CSS"
]);

const backend = new Set([
  "Python",
  "Java",
  "PHP"
]);

console.log(frontend.isDisjointFrom(backend));
```

Output:

```text
true
```

If the sets share at least one element, the method returns `false`.

# 🗁 RegExp.escape()

ES2025 introduced `RegExp.escape()`.

It safely escapes a string so it can be used as a literal pattern inside a regular expression.

This is especially useful when constructing regular expressions from user-provided or dynamically generated strings.

Example:

```javascript
const searchText = "price: $100";

const escaped = RegExp.escape(searchText);

const pattern = new RegExp(escaped);

console.log(pattern.test("The price: $100 is correct"));
```

Output:

```text
true
```

Without escaping, characters such as `$`, `.`, `*`, `+`, and `?` can have special meanings in regular expressions.

**Example with dynamic search:**

```javascript
function createSearchPattern(searchText) {
  return new RegExp(RegExp.escape(searchText), "i");
}

const text = "JavaScript is powerful";

const pattern = createSearchPattern("JavaScript");

console.log(pattern.test(text));
```

Output:

```text
true
```

`RegExp.escape()` handles regular expression syntax and other characters that need escaping for safe literal matching.

It is preferable to manually implementing regular expression escaping.

# 🗁 Promise.try()

ES2025 introduced `Promise.try()`.

It executes a callback and returns a promise that fulfills with the callback's return value or rejects if the callback throws an error.

**Syntax**

```javascript
Promise.try(callback);
```

Example:

```javascript
const promise = Promise.try(() => {
  return "Operation completed";
});

promise.then(console.log);
```

Output:

```text
Operation completed
```

**Handling synchronous errors:**

```javascript
const promise = Promise.try(() => {
  throw new Error("Something went wrong");
});

promise.catch(error => {
  console.log(error.message);
});
```

Output:

```text
Something went wrong
```

**Handling synchronous and asynchronous results:**

```javascript
function loadData() {
  return Promise.try(() => {
    if (Math.random() > 0.5) {
      return "Data loaded";
    }

    throw new Error("Loading failed");
  });
}

loadData()
  .then(console.log)
  .catch(error => console.log(error.message));
```

The callback can return an ordinary value, a promise, or throw an error.

`Promise.try()` converts these outcomes into a promise-based flow.

It is useful when an operation may fail synchronously or asynchronously but should always be handled through promise chaining.

# 🗁 Float16Array

ES2025 introduced `Float16Array`.

It is a typed array that stores values using 16-bit floating-point representation.

Traditional `Float32Array` stores values using 32-bit floating-point representation, while `Float64Array` uses 64-bit representation.

Example:

```javascript
const values = new Float16Array([
  1.5,
  2.25,
  3.75
]);

console.log(values);
console.log(values[0]);
```

Output:

```text
Float16Array(3) [1.5, 2.25, 3.75]
1.5
```

**Comparing floating-point typed arrays:**

| Typed Array | Element Size | Precision |
| --- | ---: | --- |
| `Float16Array` | 16 bits | Lower |
| `Float32Array` | 32 bits | Medium |
| `Float64Array` | 64 bits | Higher |

Float16 values use less memory but have a smaller range and lower precision.

They are useful in applications involving graphics, machine learning, and binary data formats that support half-precision floating-point values.

# 🗁 Math.f16round()

ES2025 introduced `Math.f16round()`.

It rounds a number to the nearest value representable by the IEEE 754 binary16 floating-point format.

Example:

```javascript
const value = 1.337;

console.log(Math.f16round(value));
```

Output:

```text
1.3369140625
```

The result differs from the original number because not every JavaScript number can be represented exactly using 16-bit floating-point precision.

**Comparing rounding methods:**

```javascript
const value = 1.337;

console.log(Math.f16round(value));
console.log(Math.fround(value));
```

The first result uses binary16 precision, while the second uses binary32 precision.

`Math.f16round()` is useful when working with `Float16Array` or other systems that require half-precision floating-point values.

# 🗁 Import Attributes

ES2025 standardized import attributes.

They allow developers to provide additional metadata when importing modules.

The `with` keyword introduces import attributes.

**Static import example:**

```javascript
import config from "./config.json" with {
  type: "json"
};

console.log(config);
```

The `type: "json"` attribute identifies the imported resource as JSON.

**Dynamic import example:**

```javascript
const module = await import("./config.json", {
  with: {
    type: "json"
  }
});

console.log(module.default);
```

Import attributes are useful when a module loader needs information about the type or handling of an imported resource.

**Import attributes vs import assertions:**

Older experimental syntax used the `assert` keyword:

```javascript
import config from "./config.json" assert {
  type: "json"
};
```

The standardized syntax uses `with`:

```javascript
import config from "./config.json" with {
  type: "json"
};
```

Use the standardized `with` syntax for current JavaScript code.

# 🗁 Duplicate Named Capture Groups

ES2025 relaxed regular expression rules for named capture groups.

Previously, a named capture group could not be declared more than once in the same regular expression.

ES2025 allows the same name to appear in mutually exclusive alternatives.

Example:

```javascript
const pattern = /(?<value>\d+)-(?<unit>kg)|(?<value>\d+)-(?<unit>lb)/;

const result = pattern.exec("25-kg");

console.log(result.groups.value);
console.log(result.groups.unit);
```

Output:

```text
25
kg
```

The alternatives are mutually exclusive, so only one `value` group and one `unit` group participate in a successful match.

This feature is useful when multiple pattern alternatives share the same logical structure.

# 🗁 Regular Expression Modifiers

ES2025 introduced inline modifier groups in regular expressions.

They allow selected matching behavior to be enabled or disabled within part of a pattern.

The supported modifiers are:

* `i`: Case-insensitive matching.
* `m`: Multiline matching.
* `s`: Dot-all matching.

The syntax uses `(?ims-ims:...)`, where modifiers before `-` are enabled and modifiers after `-` are disabled within the group.

Example:

```javascript
const pattern = /Java(?i:Script)/;

console.log(pattern.test("JavaScript"));
console.log(pattern.test("JavaSCRIPT"));
console.log(pattern.test("JAVASCRIPT"));
```

Output:

```text
true
true
false
```

The `i` modifier applies only inside the group.

This feature is useful when a regular expression requires different matching behavior in different sections of the same pattern.

# 🗁 Practical Example: Processing Data with ES2025

The following example combines iterator helpers and Set methods to process application data.

```javascript
const users = [
  { id: 1, name: "Alice", active: true, role: "admin" },
  { id: 2, name: "Bob", active: false, role: "user" },
  { id: 3, name: "Charlie", active: true, role: "user" },
  { id: 4, name: "David", active: true, role: "admin" }
];

// Process users with iterator helpers.
const activeNames = Iterator.from(users)
  .filter(user => user.active)
  .map(user => user.name)
  .toArray();

console.log(activeNames);

// Compare role collections.
const requiredRoles = new Set(["admin", "user"]);

const availableRoles = new Set([
  "admin",
  "user",
  "moderator"
]);

console.log(requiredRoles.isSubsetOf(availableRoles));

// Combine two role collections.
const additionalRoles = new Set([
  "moderator",
  "editor"
]);

console.log(
  availableRoles.union(additionalRoles)
);
```

This example demonstrates lazy iterator processing and mathematical set operations in a practical application.

# 🗁 Browser and Runtime Compatibility

ES2025 features require compatible JavaScript engines.

Support can vary across browsers, Node.js versions, and other JavaScript runtimes.

Important considerations:

* Iterator helpers require support for the built-in Iterator API.
* Set methods require modern Set implementation support.
* `RegExp.escape()` requires ES2025 regular expression support.
* `Promise.try()` requires updated Promise implementation support.
* `Float16Array` and `Math.f16round()` require half-precision floating-point support.
* Import attributes require compatible module loaders.
* Duplicate named capture groups and inline modifiers require updated regular expression engines.

A transpiler may transform some syntax, but it cannot automatically provide every missing runtime API.

Always verify the target environment when using newly standardized features.

# 🗁 Best Practices

* Use iterator helpers when processing iterable data through lazy transformations.
* Use `Iterator.from()` when an existing iterator needs access to helper methods.
* Remember that iterators are consumable and generally cannot be restarted.
* Use `toArray()` when a materialized array is required.
* Use Set methods instead of manually implementing common mathematical set operations.
* Use `RegExp.escape()` when embedding dynamic text into regular expressions.
* Use `Promise.try()` when synchronous and asynchronous outcomes should share one promise-based flow.
* Use `Float16Array` when reduced precision and memory usage are acceptable.
* Use `Math.f16round()` when binary16 precision is required.
* Use import attributes to identify imported resource types.
* Use duplicate named capture groups when mutually exclusive alternatives share logical capture names.
* Use inline regular expression modifiers when different sections require different matching behavior.
