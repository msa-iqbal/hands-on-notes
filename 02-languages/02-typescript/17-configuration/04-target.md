# TypeScript Target

The `target` compiler option determines which version of JavaScript TypeScript generates when compiling `.ts` files into `.js` files.

It controls the JavaScript language features that remain in the compiled output and which features TypeScript transforms into older JavaScript equivalents.

# 🗁 What Is `target`?

TypeScript supports modern JavaScript syntax, but not every runtime environment supports every JavaScript feature.

The `target` option tells the TypeScript compiler which JavaScript version your application must support.

For example:

```json
{
  "compilerOptions": {
    "target": "ES5"
  }
}
```

This instructs TypeScript to generate JavaScript compatible with ECMAScript 5 where transformations are supported.

A modern configuration might use:

```json
{
  "compilerOptions": {
    "target": "ES2022"
  }
}
```

This allows modern JavaScript syntax to remain in the compiled output when it is supported by the selected target.

# 🗁 Available Target Values

TypeScript supports several ECMAScript targets.

Common values include:

| Target | Description |
| --- | --- |
| `ES3` | Very old JavaScript standard |
| `ES5` | Older JavaScript standard |
| `ES2015` | ES6 |
| `ES2016` | ECMAScript 2016 |
| `ES2017` | ECMAScript 2017 |
| `ES2018` | ECMAScript 2018 |
| `ES2019` | ECMAScript 2019 |
| `ES2020` | ECMAScript 2020 |
| `ES2021` | ECMAScript 2021 |
| `ES2022` | ECMAScript 2022 |
| `ES2023` | ECMAScript 2023 |
| `ES2024` | ECMAScript 2024 |
| `ESNext` | Latest ECMAScript features supported by the installed TypeScript version |

`ES3` is deprecated. Available target values depend on the TypeScript compiler version.

# 🗁 Configuring Target

Configure the target inside `compilerOptions` in `tsconfig.json`.

```json
{
  "compilerOptions": {
    "target": "ES2022"
  }
}
```

You can also specify it directly through the command line:

```bash
tsc index.ts --target ES2022
```

The command-line option overrides the corresponding configuration value.

# 🗁 How Target Changes Compiled JavaScript

Consider the following TypeScript code:

```typescript
const greet = (name: string): string => {
  return `Hello, ${name}!`;
};

console.log(greet("Alice"));
```

With an ES2015 target, the arrow function and template literal can remain:

```javascript
const greet = (name) => {
    return `Hello, ${name}!`;
};

console.log(greet("Alice"));
```

With an ES5 target, TypeScript transforms these supported language features:

```javascript
var greet = function (name) {
    return "Hello, ".concat(name, "!");
};

console.log(greet("Alice"));
```

The TypeScript compiler removes type annotations and transforms syntax according to the selected target.

# 🗁 Target Does Not Add Runtime Features

An important distinction is that `target` controls JavaScript syntax transformation. It does not automatically provide missing JavaScript APIs.

For example:

```typescript
const users = ["Alice", "Bob", "Charlie"];

const result = users.includes("Alice");

console.log(result);
```

The `Array.prototype.includes()` method is a runtime API.

Compiling this code with an older target does not automatically implement `includes()` for environments that lack it.

You may need:

* A JavaScript polyfill.
* A compatible runtime environment.
* A library that provides the required functionality.

# 🗁 Target and Lib

The `target` and `lib` compiler options are related but serve different purposes.

| Option | Responsibility |
| --- | --- |
| `target` | Determines the JavaScript syntax generated by the compiler |
| `lib` | Determines which built-in JavaScript APIs and type definitions TypeScript recognizes |

Example:

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "lib": ["ES2020", "DOM"]
  }
}
```

This configuration:

* Generates JavaScript targeting ES2020.
* Provides TypeScript definitions for ES2020 APIs.
* Includes browser APIs such as `document`, `window`, and `fetch` through the DOM library.

Remember that including a library in `lib` does not install or polyfill its runtime APIs.

# 🗁 Target and Downlevel Iteration

Some JavaScript iteration behavior depends on the selected target.

Consider:

```typescript
const values = new Set([10, 20, 30]);

for (const value of values) {
  console.log(value);
}
```

When targeting older JavaScript versions, certain iteration patterns may require additional compiler transformations.

The `downlevelIteration` option enables more complete iteration transformations for older targets:

```json
{
  "compilerOptions": {
    "target": "ES5",
    "downlevelIteration": true
  }
}
```

This can generate helper code that uses the iterator protocol when available.

However, the runtime must still provide the required iterator functionality or appropriate polyfills.

# 🗁 Choosing the Right Target

Choose a target based on the JavaScript environments where your application will run.

| Environment | Typical target considerations |
| --- | --- |
| Modern browsers | A modern ECMAScript target |
| Node.js applications | A target supported by the deployed Node.js version |
| Legacy browsers | An older target with necessary polyfills |
| Modern frontend applications | A target aligned with the project's browser support policy |
| Libraries | A target appropriate for the consumers of the library |

For modern applications, `ES2022` or another suitable recent target is often a reasonable starting point.

The correct choice depends on the actual runtime support requirements.

# 🗁 Practical Configuration

A modern Node.js-oriented configuration might look like this:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/**/*.ts"],
  "exclude": ["node_modules", "dist"]
}
```

For a browser application:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "strict": true,
    "outDir": "./dist"
  },
  "include": ["src"]
}
```

These are starting points. The appropriate module settings and runtime compatibility requirements depend on the project.

# 🗁 Important Considerations

* `target` does not determine the module system. Use the `module` option for that.
* A newer target generally preserves more modern JavaScript syntax.
* An older target may require additional transformations and helper code.
* TypeScript does not automatically polyfill missing runtime APIs.
* The `lib` option controls available API type definitions.
* `ESNext` can produce output that depends on features supported by newer runtimes.
* Build tools such as Vite, esbuild, and Babel may perform additional transformations independently of TypeScript.

# 🗁 Summary

The `target` option determines the ECMAScript version of the JavaScript output generated by TypeScript.

It is important for:

* Runtime compatibility.
* JavaScript syntax transformation.
* Supporting older environments.
* Controlling the language features preserved in compiled output.

Choose a target based on the actual environments that will execute your application.
