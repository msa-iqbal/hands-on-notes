# Software Architecture

Practical, structured notes for understanding and applying **software architecture principles and architectural patterns** to design maintainable, scalable, testable, and loosely coupled software systems.

## Structure

The notes progress from **architecture fundamentals → layered architecture → client-server → three-tier → hexagonal architecture → clean architecture → onion architecture → event-driven architecture → architecture principles**.

The first section establishes the purpose of software architecture, architectural responsibilities, quality attributes, and design trade-offs. Layered, client-server, and three-tier architectures then introduce common structural approaches for organizing application responsibilities and system boundaries.

Hexagonal, Clean, and Onion architectures focus on dependency direction, domain isolation, separation of concerns, and reducing coupling between business logic and external infrastructure. These approaches provide different ways to structure maintainable and testable applications.

Event-driven architecture introduces asynchronous communication, events, producers, consumers, and messaging infrastructure for distributed systems. The final section brings these concepts together through general principles for evaluating and designing software architectures.

Each topic is separated into focused notes for easier learning, reference, practical use, and expansion.
