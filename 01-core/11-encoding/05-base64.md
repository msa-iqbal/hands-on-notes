# Base64

Base64 is a binary-to-text encoding scheme that converts binary data into a sequence of printable ASCII characters.

It is commonly used when binary data needs to be represented in text-based systems, such as:

* Email attachments.
* HTTP requests and responses.
* JSON payloads.
* Data URLs.
* Authentication headers.
* Configuration files.
* Data exchange between applications.

Base64 makes binary data easier to transport through systems designed primarily for text.

However, **Base64 is not encryption, compression, or a security mechanism.** Anyone who has the encoded data can decode it without a secret key.

# 🗁 What Is Base64?

Base64 converts groups of binary bits into characters selected from a 64-character alphabet.

The standard Base64 alphabet contains:

* 26 uppercase letters: `A–Z`.
* 26 lowercase letters: `a–z`.
* 10 digits: `0–9`.
* Plus sign: `+`.
* Forward slash: `/`.

The padding character is:

```text
=
```

The complete alphabet is:

```text
ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/
```

Each Base64 character represents exactly 6 bits of data.

Since:

```text
2^6 = 64
```

there are 64 possible values for each Base64 symbol.

# 🗁 Why Base64 Is Needed

Computers store all data as binary.

However, some systems are designed to handle text rather than arbitrary binary bytes.

For example, an email message or a JSON document is primarily text-based.

If raw binary data is inserted directly into such a system, certain byte values may be interpreted incorrectly, modified, or rejected.

Base64 converts arbitrary bytes into a restricted set of printable characters.

Example:

Original text:

```text
Hello
```

Base64 representation:

```text
SGVsbG8=
```

The encoded result can be transported as ordinary text.

# 🗁 How Base64 Works

Base64 processes input in groups of three bytes.

Each byte contains 8 bits.

Therefore:

```text
3 bytes × 8 bits = 24 bits
```

Those 24 bits are divided into four groups of 6 bits.

Each 6-bit group maps to one Base64 alphabet character.

```text
3 bytes
   |
   v
24 bits
   |
   v
4 groups of 6 bits
   |
   v
4 Base64 characters
```

Therefore:

```text
3 input bytes = 4 Base64 characters
```

If the input does not contain a complete group of three bytes, padding is added.

# 🗁 Base64 Encoding Example

Consider the input:

```text
Man
```

Convert each character into its ASCII byte:

| Character | ASCII Decimal | Binary |
| --- | ---: | --- |
| M | 77 | `01001101` |
| a | 97 | `01100001` |
| n | 110 | `01101110` |

Combine the binary values:

```text
01001101 01100001 01101110
```

Divide the 24 bits into four groups of 6 bits:

```text
010011 010110 000101 101110
```

Convert each group into a decimal index:

```text
19 22 5 46
```

Look up the Base64 alphabet:

```text
19 = T
22 = W
5  = F
46 = u
```

Final result:

```text
Man = TWFu
```

# 🗁 Base64 Padding

Base64 requires input to be processed in groups of three bytes.

When the input contains fewer than three bytes in the final group, padding is added using `=`.

There are three possible situations:

| Input Bytes | Base64 Characters | Padding |
| --- | --- | --- |
| 3 bytes | 4 | None |
| 2 bytes | 4 | 1 `=` |
| 1 byte | 4 | 2 `=` |

Example:

```text
Input:  M
Output: TQ==
```

Example:

```text
Input:  Ma
Output: TWE=
```

Example:

```text
Input:  Man
Output: TWFu
```

Padding indicates that the final Base64 group contains fewer than three original bytes.

Some Base64 variants allow padding to be omitted, but standard Base64 commonly includes it.

# 🗁 Base64 Size Overhead

Base64 increases the size of encoded data.

Every three input bytes produce four Base64 characters.

The approximate encoded size is:

```text
Encoded size = 4 × ceil(input bytes / 3)
```

For large input data, the overhead is approximately 33.33%.

Example:

| Original Size | Approximate Base64 Size |
| ---: | ---: |
| 3 bytes | 4 characters |
| 30 bytes | 40 characters |
| 300 bytes | 400 characters |
| 3 KB | 4 KB |
| 30 KB | 40 KB |

This overhead makes Base64 less efficient than sending binary data directly when the transport system supports binary content.

# 🗁 Base64 Is Not Encryption

Base64 is an encoding format, not an encryption algorithm.

Anyone can decode Base64 without a password or secret key.

Example:

```text
Encoded:
SGVsbG8=

Decoded:
Hello
```

Base64 provides:

* Text-safe representation of binary data.
* A standardized encoding format.
* Convenient data transport.

Base64 does not provide:

* Confidentiality.
* Authentication.
* Integrity protection.
* Access control.

Never use Base64 alone to protect passwords, API keys, tokens, or confidential information.

# 🗁 Standard Base64 vs URL-Safe Base64

Standard Base64 uses two characters that have special meanings in URLs:

```text
+
/
```

The padding character is:

```text
=
```

These characters can require special handling when Base64 is placed inside URLs.

Base64url is a URL-safe variant that changes the alphabet:

| Standard Base64 | Base64url |
| --- | --- |
| `+` | `-` |
| `/` | `_` |
| `=` | Usually omitted |

Example:

Standard Base64:

```text
+/8=
```

Base64url:

```text
-_8
```

Base64url is commonly used in:

* JSON Web Tokens (JWT).
* URL-safe identifiers.
* Web application tokens.
* Query parameters.
* Cryptographic protocol representations.

Base64url is not identical to standard Base64, even though both use the same general encoding principle.

# 🗁 MIME Base64

MIME stands for Multipurpose Internet Mail Extensions.

Historically, email systems needed a reliable way to transfer binary attachments through text-oriented email infrastructure.

MIME defines Base64 transfer encoding for this purpose.

MIME Base64 commonly wraps encoded output into lines of up to 76 characters.

Example:

```text
Content-Transfer-Encoding: base64

SGVsbG8gV29ybGQ=
```

Modern applications may use MIME Base64 when generating email attachments or handling MIME message bodies.

# 🗁 Data URLs

A Data URL embeds data directly inside a URL.

Its general structure is:

```text
data:[<media-type>][;base64],<data>
```

Example:

```text
data:text/plain;base64,SGVsbG8=
```

A browser can interpret this as Base64-encoded plain text.

For an image:

```html
<img
    src="data:image/png;base64,iVBORw0KGgo..."
    alt="Embedded image"
/>
```

Data URLs are useful for:

* Small embedded images.
* Inline resources.
* Small application assets.
* Certain standalone HTML documents.

However, embedding large files as Base64 increases document size and can make caching and content management less efficient.

# 🗁 Base64 in JavaScript

JavaScript provides `btoa()` and `atob()` in browser environments.

* `btoa()` encodes a binary string into Base64.
* `atob()` decodes Base64 into a binary string.

Example:

```javascript
const encoded = btoa("Hello");

console.log(encoded);
// SGVsbG8=
```

Decode:

```javascript
const decoded = atob("SGVsbG8=");

console.log(decoded);
// Hello
```

These functions work with binary strings whose character values are in the Latin-1 range (0–255).

They do not directly accept arbitrary Unicode strings.

# 🗁 Base64 with Unicode in JavaScript

Consider:

```javascript
btoa("বাংলা");
```

This throws an error because the characters cannot be represented directly as a Latin-1 binary string.

The correct approach is to convert the string into UTF-8 bytes first.

Use `TextEncoder` and `TextDecoder`.

Encoding:

```javascript
const text = "বাংলা 😀";

const bytes = new TextEncoder().encode(text);

let binary = "";

for (const byte of bytes) {
    binary += String.fromCharCode(byte);
}

const encoded = btoa(binary);

console.log(encoded);
```

Decoding:

```javascript
const encoded = btoa("Hello");

const binary = atob(encoded);

const bytes = Uint8Array.from(
    binary,
    character => character.charCodeAt(0)
);

const decoded = new TextDecoder("utf-8").decode(bytes);

console.log(decoded);
// Hello
```

For reusable functionality:

```javascript
function encodeBase64(text) {
    const bytes = new TextEncoder().encode(text);

    let binary = "";

    for (const byte of bytes) {
        binary += String.fromCharCode(byte);
    }

    return btoa(binary);
}

function decodeBase64(encoded) {
    const binary = atob(encoded);

    const bytes = Uint8Array.from(
        binary,
        character => character.charCodeAt(0)
    );

    return new TextDecoder("utf-8").decode(bytes);
}

const encoded = encodeBase64("বাংলা 😀");

console.log(encoded);
console.log(decodeBase64(encoded));
```

This approach handles Unicode correctly by encoding the text as UTF-8 before applying Base64.

# 🗁 Base64 in Node.js

Node.js provides the `Buffer` API.

It is generally the simplest way to encode and decode Base64 in Node.js.

Encoding:

```javascript
const text = "Hello World";

const encoded = Buffer
    .from(text, "utf8")
    .toString("base64");

console.log(encoded);
// SGVsbG8gV29ybGQ=
```

Decoding:

```javascript
const encoded = "SGVsbG8gV29ybGQ=";

const decoded = Buffer
    .from(encoded, "base64")
    .toString("utf8");

console.log(decoded);
// Hello World
```

Unicode example:

```javascript
const text = "বাংলা 😀";

const encoded = Buffer
    .from(text, "utf8")
    .toString("base64");

const decoded = Buffer
    .from(encoded, "base64")
    .toString("utf8");

console.log(encoded);
console.log(decoded);
```

Node.js also supports Base64url:

```javascript
const text = "Hello World";

const encoded = Buffer
    .from(text)
    .toString("base64url");

console.log(encoded);
```

# 🗁 Base64 in Python

Python provides the built-in `base64` module.

Import:

```python
import base64
```

Encoding:

```python
text = "Hello World"

encoded = base64.b64encode(
    text.encode("utf-8")
)

print(encoded)
# b'SGVsbG8gV29ybGQ='
```

Decoding:

```python
encoded = b"SGVsbG8gV29ybGQ="

decoded = base64.b64decode(encoded)

print(decoded.decode("utf-8"))
# Hello World
```

# 🗁 Base64 with Unicode in Python

Python strings support Unicode, but the Base64 module works with bytes.

Therefore, encode the string into UTF-8 bytes before applying Base64.

Example:

```python
import base64

text = "বাংলা 😀"

encoded = base64.b64encode(
    text.encode("utf-8")
)

decoded = base64.b64decode(encoded).decode("utf-8")

print("Encoded:", encoded.decode("ascii"))
print("Decoded:", decoded)
```

# 🗁 URL-Safe Base64 in Python

Python provides dedicated functions for URL-safe Base64.

Encoding:

```python
import base64

text = "Hello World"

encoded = base64.urlsafe_b64encode(
    text.encode("utf-8")
)

print(encoded)
```

Decoding:

```python
decoded = base64.urlsafe_b64decode(encoded)

print(decoded.decode("utf-8"))
```

The URL-safe alphabet replaces:

* `+` with `-`.
* `/` with `_`.

Python's URL-safe encoding functions retain padding unless you explicitly remove it.

# 🗁 Base64 from the Command Line

Linux systems commonly provide the `base64` command.

Encode a string:

```bash
echo -n "Hello World" | base64
```

Output:

```text
SGVsbG8gV29ybGQ=
```

Decode:

```bash
echo "SGVsbG8gV29ybGQ=" | base64 --decode
```

Output:

```text
Hello World
```

Encode a file:

```bash
base64 image.png > image.b64
```

Decode a file:

```bash
base64 --decode image.b64 > decoded-image.png
```

The `-n` option in `echo` prevents adding a newline to the input.

Without it, the newline may also be included in the encoded data.

# 🗁 Base64 in HTTP Authentication

HTTP Basic Authentication uses Base64 to represent a username and password pair.

The general structure is:

```text
Authorization: Basic <base64-credentials>
```

For example, the credentials:

```text
username:password
```

Can be Base64-encoded:

```text
dXNlcm5hbWU6cGFzc3dvcmQ=
```

The HTTP header becomes:

```http
Authorization: Basic dXNlcm5hbWU6cGFzc3dvcmQ=
```

Base64 does not make these credentials secret. Basic Authentication should be used over HTTPS to protect credentials during transport.

# 🗁 Base64 in JWT

JSON Web Tokens (JWTs) commonly use Base64url encoding.

A JWT has three dot-separated parts:

```text
header.payload.signature
```

Each part uses Base64url representation, with padding generally omitted.

Example structure:

```text
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.
eyJzdWIiOiIxMjM0NTY3ODkwIn0
.
<signature>
```

The header and payload can be decoded and read by anyone who obtains the token.

The signature is used to verify integrity and authenticity.

Base64url encoding does not encrypt JWT contents.

# 🗁 Base64 Validation and Common Errors

Base64 input must follow the rules of the selected Base64 variant.

Common problems include:

**Invalid characters**

Standard Base64 does not use arbitrary punctuation or whitespace as alphabet characters.

Some decoders accept whitespace for convenience, while strict decoders may reject it.

**Incorrect padding**

Standard Base64 normally uses `=` padding when the final input group contains one or two bytes.

**Wrong variant**

Base64url uses `-` and `_` instead of `+` and `/`.

Using the wrong decoder or format assumptions can cause errors.

**Incorrect text decoding**

Base64 decoding produces bytes, not automatically meaningful text.

If the original data was UTF-8 text, decode the bytes using UTF-8.

If the original data was an image, PDF, or another binary format, preserve the bytes rather than interpreting them as text.

**Double encoding**

Encoding already Base64-encoded data again creates another Base64 layer.

This is sometimes intentional, but often indicates an unnecessary conversion.

# 🗁 Practical Examples

**Encode and decode a string in JavaScript**

```javascript
const original = "Hello World";

const encoded = btoa(original);
const decoded = atob(encoded);

console.log(encoded);
console.log(decoded);
```

**Encode and decode Unicode in Node.js**

```javascript
const original = "বাংলা 😀";

const encoded = Buffer
    .from(original, "utf8")
    .toString("base64");

const decoded = Buffer
    .from(encoded, "base64")
    .toString("utf8");

console.log(encoded);
console.log(decoded);
```

**Encode and decode a file in Python**

```python
import base64

with open("image.png", "rb") as file:
    binary_data = file.read()

encoded = base64.b64encode(binary_data)

with open("image.b64", "wb") as file:
    file.write(encoded)

decoded = base64.b64decode(encoded)

with open("decoded-image.png", "wb") as file:
    file.write(decoded)
```

**Calculate Base64 output length**

```python
import math

input_size = 1024

encoded_size = 4 * math.ceil(input_size / 3)

print("Input size:", input_size)
print("Base64 size:", encoded_size)
```

# 🗁 Best Practices

* Remember that Base64 is encoding, not encryption.
* Encode text into UTF-8 bytes before applying Base64.
* Decode Base64 into bytes before interpreting the original content.
* Use Base64url when data must safely fit into URL-oriented formats.
* Use standard Base64 for applications that explicitly require its alphabet.
* Avoid Base64 for large files when binary transport is available.
* Do not expose secrets merely because they are Base64-encoded.
* Validate untrusted Base64 input.
* Handle padding according to the selected Base64 variant.
* Preserve binary data when processing images, documents, and other files.
* Avoid accidental double encoding.
* Use HTTPS when transmitting sensitive information.

# 🗁 Summary

Base64 is a binary-to-text encoding scheme that represents binary data using a 64-character alphabet.

Its main characteristics include:

* Each Base64 character represents 6 bits.
* Three input bytes produce four Base64 characters.
* Padding uses `=` when the final input group is incomplete.
* Encoded data is approximately 33.33% larger for large inputs.
* Standard Base64 uses `+` and `/`.
* Base64url replaces them with `-` and `_`.
* JavaScript, Node.js, and Python provide built-in Base64 support.
* Base64 is not encryption and does not provide confidentiality.

Understanding Base64 is useful when working with APIs, email attachments, authentication formats, binary data, and web applications.
