# UTF-8

UTF-8 (Unicode Transformation Format – 8-bit) is a variable-width character encoding used to represent Unicode code points as bytes.

It is the most widely used character encoding on the web and is supported by modern operating systems, programming languages, databases, browsers, and communication protocols.

UTF-8 uses between **1 and 4 bytes** to represent a Unicode scalar value.

Its main characteristics include:

* Supports all Unicode scalar values.
* Uses 1–4 bytes per Unicode scalar value.
* Is backward-compatible with ASCII.
* Does not require byte-order detection.
* Is efficient for text containing many Latin characters.
* Is widely used for files, websites, APIs, and databases.

# 🗁 What Is UTF-8?

UTF-8 is an encoding that converts Unicode scalar values into sequences of bytes.

For example, the Unicode character `A` has the code point:

```text
U+0041
```

Its UTF-8 representation is:

```text
41
```

The Bengali character `অ` has the code point:

```text
U+0985
```

Its UTF-8 representation is:

```text
E0 A6 85
```

The emoji `😀` has the code point:

```text
U+1F600
```

Its UTF-8 representation is:

```text
F0 9F 98 80
```

The character remains the same. UTF-8 determines how its code point is represented as bytes.

# 🗁 UTF-8 Byte Length

UTF-8 uses different numbers of bytes depending on the Unicode scalar value.

| UTF-8 Length | Unicode Range | Byte Pattern |
| --- | --- | --- |
| 1 byte | `U+0000–U+007F` | `0xxxxxxx` |
| 2 bytes | `U+0080–U+07FF` | `110xxxxx 10xxxxxx` |
| 3 bytes | `U+0800–U+FFFF`, excluding surrogates | `1110xxxx 10xxxxxx 10xxxxxx` |
| 4 bytes | `U+10000–U+10FFFF` | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` |

The `x` positions contain bits from the Unicode code point.

The leading bits identify the sequence length and continuation bytes.

# 🗁 One-Byte UTF-8 Characters

Characters in the range `U+0000–U+007F` use one byte.

Their UTF-8 representation is identical to ASCII.

Examples:

| Character | Unicode | UTF-8 |
| --- | --- | --- |
| `A` | `U+0041` | `41` |
| `B` | `U+0042` | `42` |
| `a` | `U+0061` | `61` |
| `0` | `U+0030` | `30` |
| Space | `U+0020` | `20` |

The byte pattern is:

```text
0xxxxxxx
```

Because ASCII uses only seven bits, UTF-8 can preserve ASCII data without changing its byte representation.

# 🗁 Two-Byte UTF-8 Characters

Unicode scalar values from `U+0080` through `U+07FF` use two bytes.

The byte pattern is:

```text
110xxxxx 10xxxxxx
```

Example: the character `é`.

Unicode code point:

```text
U+00E9
```

Binary representation:

```text
00000 11101001
```

Divide the bits into the UTF-8 payload groups:

```text
00011 101001
```

Insert the UTF-8 prefix bits:

```text
11000011 10101001
```

Convert to hexadecimal:

```text
C3 A9
```

Therefore:

```text
é = C3 A9
```

# 🗁 Three-Byte UTF-8 Characters

Unicode scalar values from `U+0800` through `U+FFFF`, excluding surrogate code points, use three bytes.

The byte pattern is:

```text
1110xxxx 10xxxxxx 10xxxxxx
```

Example: the Bengali character `অ`.

Unicode code point:

```text
U+0985
```

Binary representation:

```text
0000 1001 1000 0101
```

Divide into three groups:

```text
0000 100110 000101
```

Insert the UTF-8 prefix bits:

```text
11100000 10100110 10000101
```

Convert to hexadecimal:

```text
E0 A6 85
```

Therefore:

```text
অ = E0 A6 85
```

# 🗁 Four-Byte UTF-8 Characters

Unicode scalar values from `U+10000` through `U+10FFFF` use four bytes.

The byte pattern is:

```text
11110xxx 10xxxxxx 10xxxxxx 10xxxxxx
```

Example: the emoji `😀`.

Unicode code point:

```text
U+1F600
```

Binary representation:

```text
000 011111 011000 000000
```

Insert the UTF-8 prefix bits:

```text
11110000 10011111 10011000 10000000
```

Convert to hexadecimal:

```text
F0 9F 98 80
```

Therefore:

```text
😀 = F0 9F 98 80
```

# 🗁 UTF-8 Continuation Bytes

In multi-byte UTF-8 sequences, continuation bytes always begin with:

```text
10
```

Examples:

```text
110xxxxx 10xxxxxx
1110xxxx 10xxxxxx 10xxxxxx
11110xxx 10xxxxxx 10xxxxxx 10xxxxxx
```

The first byte identifies the sequence length.

The remaining bytes contain continuation data.

This structure allows UTF-8 decoders to identify character boundaries and detect many malformed sequences.

# 🗁 UTF-8 and ASCII Compatibility

UTF-8 is backward-compatible with ASCII.

ASCII characters use exactly the same byte values in UTF-8.

For example:

```text
ASCII:  Hello
UTF-8:  48 65 6C 6C 6F
```

Both representations are identical at the byte level.

However, characters outside ASCII require multiple bytes.

For example:

```text
Hello
```

Uses 5 bytes in UTF-8.

```text
বাংলা
```

Uses 15 bytes in UTF-8.

The number of bytes is not necessarily equal to the number of characters.

# 🗁 UTF-8 Byte Length vs String Length

One of the most important UTF-8 concepts is the difference between character count and byte count.

Consider:

```text
Aঅ😀
```

Its Unicode code points are:

```text
A       U+0041
অ       U+0985
😀      U+1F600
```

Its UTF-8 representation is:

```text
41 E0 A6 85 F0 9F 98 80
```

The total byte count is:

```text
1 + 3 + 4 = 8 bytes
```

But it contains only three Unicode code points.

| Character | UTF-8 Bytes | Byte Count |
| --- | --- | ---: |
| `A` | `41` | 1 |
| `অ` | `E0 A6 85` | 3 |
| `😀` | `F0 9F 98 80` | 4 |
| Total | `41 E0 A6 85 F0 9F 98 80` | 8 |

Always distinguish between:

* String length.
* Unicode code point count.
* Grapheme cluster count.
* Encoded byte length.

# 🗁 UTF-8 in JavaScript

JavaScript strings use UTF-16 internally, but the `TextEncoder` API can convert strings into UTF-8 bytes.

Example:

```javascript
const text = "Hello";

const encoder = new TextEncoder();
const bytes = encoder.encode(text);

console.log(bytes);
// Uint8Array(5) [72, 101, 108, 108, 111]

console.log(bytes.length);
// 5
```

For multilingual text:

```javascript
const text = "Hello অ 😀";

const encoder = new TextEncoder();
const bytes = encoder.encode(text);

console.log(bytes);

console.log("UTF-8 byte length:", bytes.length);
```

The output is a `Uint8Array` containing the encoded bytes.

Convert bytes to hexadecimal:

```javascript
const text = "অ";

const bytes = new TextEncoder().encode(text);

const hex = [...bytes]
    .map(byte => byte.toString(16).padStart(2, "0"))
    .join(" ");

console.log(hex);
// e0 a6 85
```

# 🗁 UTF-8 Decoding in JavaScript

Use `TextDecoder` to convert UTF-8 bytes back into a JavaScript string.

Example:

```javascript
const bytes = new Uint8Array([
    0xE0,
    0xA6,
    0x85
]);

const decoder = new TextDecoder("utf-8");

const text = decoder.decode(bytes);

console.log(text);
// অ
```

You can also use `TextEncoder` and `TextDecoder` together:

```javascript
const original = "Hello অ 😀";

const encoder = new TextEncoder();
const decoder = new TextDecoder("utf-8");

const bytes = encoder.encode(original);
const decoded = decoder.decode(bytes);

console.log(decoded);
// Hello অ 😀

console.log(original === decoded);
// true
```

# 🗁 UTF-8 in Python

Python provides UTF-8 support through the built-in string encoding and decoding methods.

Use `encode()` to convert a string into bytes:

```python
text = "Hello"

encoded = text.encode("utf-8")

print(encoded)
# b'Hello'

print(len(encoded))
# 5
```

For multilingual text:

```python
text = "Hello অ 😀"

encoded = text.encode("utf-8")

print(encoded)
print(len(encoded))
```

Convert bytes to hexadecimal:

```python
text = "অ"

encoded = text.encode("utf-8")

print(encoded.hex())
# e0a685
```

# 🗁 UTF-8 Decoding in Python

Use `decode()` to convert UTF-8 bytes back into a string.

Example:

```python
data = b"\xe0\xa6\x85"

text = data.decode("utf-8")

print(text)
# অ
```

Encoding and decoding together:

```python
original = "Hello অ 😀"

encoded = original.encode("utf-8")
decoded = encoded.decode("utf-8")

print(decoded)
# Hello অ 😀

print(original == decoded)
# True
```

# 🗁 UTF-8 Validation

Not every arbitrary byte sequence represents valid UTF-8.

A valid UTF-8 sequence must follow the encoding rules.

Important validation requirements include:

* Continuation bytes must have the `10xxxxxx` pattern.
* Leading bytes must identify a valid sequence length.
* Overlong encodings must be rejected.
* Surrogate code points must not be encoded.
* Code points above `U+10FFFF` must be rejected.
* Incomplete multi-byte sequences must be rejected.

# 🗁 Overlong Encoding

An overlong encoding represents a code point using more bytes than necessary.

For example, the character `A` should use:

```text
41
```

It must not be represented using an unnecessarily long sequence.

Overlong sequences are invalid UTF-8.

Rejecting them is important because inconsistent decoding can create security vulnerabilities in systems that validate or filter byte sequences.

# 🗁 Invalid UTF-8 Sequences

Examples of malformed UTF-8 include:

```text
C0 AF
```

This is an invalid overlong sequence.

```text
E0 A6
```

This is incomplete because the third byte is missing.

```text
F5 80 80 80
```

This is invalid because UTF-8 cannot represent code points above `U+10FFFF`.

Strict decoders should reject malformed sequences rather than silently treating them as valid text.

# 🗁 Handling Invalid UTF-8 in JavaScript

By default, `TextDecoder` replaces malformed sequences with the Unicode replacement character:

```text
U+FFFD
```

Example:

```javascript
const invalidBytes = new Uint8Array([
    0xE0,
    0xA6
]);

const decoder = new TextDecoder("utf-8");

console.log(decoder.decode(invalidBytes));
// Replacement character
```

To reject malformed input, use fatal mode:

```javascript
const decoder = new TextDecoder("utf-8", {
    fatal: true
});

try {
    const text = decoder.decode(invalidBytes);
    console.log(text);
} catch (error) {
    console.error("Invalid UTF-8 data");
}
```

# 🗁 Handling Invalid UTF-8 in Python

Python's default UTF-8 decoding is strict.

Example:

```python
invalid_bytes = b"\xe0\xa6"

try:
    text = invalid_bytes.decode("utf-8")
except UnicodeDecodeError:
    print("Invalid UTF-8 data")
```

You can also choose an error-handling strategy.

Replace invalid sequences:

```python
text = invalid_bytes.decode("utf-8", errors="replace")

print(text)
```

Ignore invalid sequences:

```python
text = invalid_bytes.decode("utf-8", errors="ignore")
```

Ignoring invalid bytes can cause data loss, so it should only be used when that behavior is intentional.

# 🗁 UTF-8 BOM

BOM stands for Byte Order Mark.

The UTF-8 BOM is the byte sequence:

```text
EF BB BF
```

It represents the Unicode character `U+FEFF` at the beginning of a file.

Unlike UTF-16 and UTF-32, UTF-8 does not have byte-order ambiguity because its byte representation is independent of machine endianness.

Therefore, a UTF-8 BOM is not needed to determine byte order.

Some applications use it as a signature indicating that a file is UTF-8 encoded.

However, not all software expects or handles it consistently.

For example, a BOM at the beginning of a CSV file can cause problems with applications that interpret it as part of the first column name.

Python example:

```python
with open("data.txt", "w", encoding="utf-8-sig") as file:
    file.write("Hello")
```

The `utf-8-sig` encoding writes a BOM when encoding and recognizes and removes it when decoding.

Without the BOM:

```python
with open("data.txt", "w", encoding="utf-8") as file:
    file.write("Hello")
```

For most modern UTF-8 applications, plain UTF-8 without a BOM is a good default.

# 🗁 UTF-8 in Text Files

UTF-8 is commonly used for text files.

Examples include:

* Markdown files.
* HTML files.
* JavaScript files.
* Python files.
* JSON files.
* YAML files.
* Configuration files.
* Documentation.

Python example:

```python
text = "Hello অ 😀"

with open("notes.txt", "w", encoding="utf-8") as file:
    file.write(text)
```

Reading:

```python
with open("notes.txt", "r", encoding="utf-8") as file:
    content = file.read()

print(content)
```

Specifying the encoding explicitly avoids relying on platform-dependent default encodings.

# 🗁 UTF-8 in HTML

HTML documents can declare UTF-8 using a character encoding declaration.

Example:

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>UTF-8 Example</title>
</head>
<body>
    <h1>Hello অ 😀</h1>
</body>
</html>
```

The declaration tells the browser to interpret the document as UTF-8.

It should appear near the beginning of the document's head section.

# 🗁 UTF-8 in HTTP

HTTP responses can specify their character encoding through the `Content-Type` header.

Example:

```http
Content-Type: text/html; charset=utf-8
```

For JSON, modern interoperable JSON exchange uses UTF-8.

Example:

```http
Content-Type: application/json
```

The `charset` parameter is not required for JSON.

UTF-8 is the required encoding for JSON exchanged between systems that are not part of a closed ecosystem.

# 🗁 UTF-8 in JSON

JSON supports Unicode text.

Example:

```json
{
  "name": "Muhammad",
  "language": "বাংলা",
  "emoji": "😀"
}
```

When a JSON document is encoded as UTF-8, these characters are stored as their corresponding UTF-8 byte sequences.

JSON can also represent Unicode characters using escape sequences.

Example:

```json
{
  "message": "\u0985"
}
```

After parsing, the value represents:

```text
অ
```

JSON escape sequences and UTF-8 are different concepts:

* JSON escapes represent characters within JSON syntax.
* UTF-8 represents the JSON document as bytes.

# 🗁 UTF-8 in Databases

Databases must support the characters your application intends to store.

For example, MySQL provides `utf8mb4` as its full UTF-8-compatible character set.

Historically, MySQL's `utf8` character set supported only up to three bytes per character, so it could not represent supplementary-plane characters such as many emoji.

Use:

```sql
CREATE DATABASE application_db
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
```

For a table:

```sql
CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(255)
)
CHARACTER SET utf8mb4;
```

The exact collation should be selected according to the database version and comparison requirements.

# 🗁 UTF-8 vs UTF-16 vs UTF-32

These are different Unicode encoding forms.

| Feature | UTF-8 | UTF-16 | UTF-32 |
| --- | --- | --- | --- |
| Unit size | 8 bits | 16 bits | 32 bits |
| Variable width | Yes | Yes | No |
| Minimum size | 1 byte | 2 bytes | 4 bytes |
| Maximum size | 4 bytes | 4 bytes | 4 bytes |
| ASCII-compatible | Yes | No | No |
| Byte-order concerns | No | Yes, for byte serialization | Yes, for byte serialization |
| Typical usage | Web and data exchange | Some programming environments and APIs | Specialized internal processing |

UTF-8 is generally the preferred choice for web communication and interoperable text files.

UTF-16 is used by JavaScript strings and several other platforms.

UTF-32 offers fixed-width code units but requires more storage for many common characters.

# 🗁 Advantages of UTF-8

* Supports every Unicode scalar value.
* Preserves ASCII byte compatibility.
* Efficient for English and other Latin-based text.
* Widely supported by modern software.
* Does not require byte-order detection.
* Works well for web applications and APIs.
* Can represent multilingual text and emoji.
* Is suitable for source code and configuration files.

# 🗁 Trade-offs of UTF-8

* Characters require different numbers of bytes.
* Byte offsets do not necessarily correspond to character positions.
* Some languages require more bytes per character than ASCII.
* Random access to a character by byte position requires additional decoding logic.
* Incorrect decoding can produce corrupted text.
* Systems that assume one byte per character can fail with multilingual input.

# 🗁 Troubleshooting Mojibake

Mojibake is corrupted text produced when bytes are decoded using the wrong character encoding.

For example, the UTF-8 bytes for:

```text
বাংলা
```

may display incorrectly if another encoding is used to interpret them.

Common symptoms include:

```text
Ã©
```

instead of:

```text
é
```

Or:

```text
ðŸ˜€
```

instead of:

```text
😀
```

Common causes:

* A file is saved as UTF-8 but read using another encoding.
* An HTTP response declares an incorrect charset.
* A database connection uses an incompatible character set.
* Bytes are decoded more than once.
* Data is converted between encodings incorrectly.

Troubleshooting steps:

* Inspect the original byte sequence.
* Identify the encoding used when the data was created.
* Verify the decoding configuration.
* Check HTTP response headers.
* Check database, table, and connection character sets.
* Avoid repeatedly converting already-decoded text.
* Preserve the original bytes when investigating corruption.

# 🗁 Practical Examples

**Calculate UTF-8 byte length in JavaScript**

```javascript
const text = "Hello অ 😀";

const byteLength = new TextEncoder().encode(text).length;

console.log(byteLength);
```

**Calculate UTF-8 byte length in Python**

```python
text = "Hello অ 😀"

byte_length = len(text.encode("utf-8"))

print(byte_length)
```

**Inspect UTF-8 bytes in Python**

```python
text = "Hello অ 😀"

for byte in text.encode("utf-8"):
    print(f"{byte:02X}")
```

**Convert hexadecimal UTF-8 bytes back to text in Python**

```python
hex_data = "E0 A6 85"

data = bytes.fromhex(hex_data)

text = data.decode("utf-8")

print(text)
# অ
```

**Validate UTF-8 bytes in Python**

```python
data = b"\xe0\xa6\x85"

try:
    decoded = data.decode("utf-8")
    print("Valid UTF-8:", decoded)
except UnicodeDecodeError:
    print("Invalid UTF-8")
```

# 🗁 Best Practices

* Use UTF-8 as the default encoding for text files and web applications.
* Specify `encoding="utf-8"` when reading and writing files in Python.
* Use `TextEncoder` and `TextDecoder` when converting JavaScript strings and byte arrays.
* Treat encoded data as bytes rather than assuming one byte equals one character.
* Validate untrusted byte sequences before processing them.
* Use strict decoding when malformed input must be rejected.
* Avoid unnecessary UTF-8 BOM insertion.
* Declare UTF-8 correctly in HTML documents.
* Use appropriate database character sets, such as MySQL `utf8mb4`.
* Keep HTTP and application encoding configurations consistent.
* Avoid repeated or incorrect encoding conversions.
* Test multilingual text, combining marks, and supplementary-plane characters.
