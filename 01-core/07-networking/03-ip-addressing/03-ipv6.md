# IPv6 (Internet Protocol Version 6)

**IPv6 (Internet Protocol Version 6)** is the next-generation Internet Protocol designed to address the limitations of IPv4, particularly its limited address space.

IPv6 uses 128-bit addresses, providing an enormous number of unique addresses for network interfaces.

An IPv6 address is represented using hexadecimal notation, with eight groups of 16 bits separated by colons.

Example:

```text
2001:0db8:0000:0000:0000:ff00:0042:8329
```

IPv6 provides several improvements over IPv4:

* A significantly larger address space.
* Simplified base-header structure.
* Stateless Address Autoconfiguration (SLAAC).
* Native multicast and anycast support.
* No broadcast addressing.
* More efficient routing and address aggregation.
* Extension headers for optional functionality.
* Improved support for end-to-end connectivity.

IPv6 operates at Layer 3 (Network Layer) of the OSI model.

# 🗁 What Is IPv6?

IPv6 is the sixth version of the Internet Protocol. It provides logical addressing and packet delivery across interconnected networks.

Unlike IPv4, which uses 32-bit addresses, IPv6 uses 128-bit addresses.

Example IPv6 address:

```text
2001:db8:1234:5678:0000:0000:0000:0001
```

IPv6 addresses are represented using eight hexadecimal groups called hextets.

Each hextet contains 16 bits.

\[
8 \times 16 = 128 \text{ bits}
\]

IPv6 supports communication between network interfaces through routing, multicast, and other network-layer mechanisms.

# 🗁 Why Was IPv6 Introduced?

IPv4 provides approximately 4.3 billion theoretical address values.

The growth of the Internet, mobile devices, cloud infrastructure, IoT devices, and connected services increased demand for IP addresses.

Several mechanisms helped extend IPv4 availability, including:

* Private IP addressing.
* Network Address Translation (NAT).
* Carrier-Grade NAT (CGNAT).
* Classless Inter-Domain Routing (CIDR).

However, these mechanisms do not eliminate IPv4's fundamental address-space limitation.

IPv6 was introduced to provide a much larger address space and improve the overall Internet addressing architecture.

Important motivations include:

* Address-space expansion.
* More efficient address allocation.
* Improved route aggregation.
* Simplified packet-header processing.
* Stateless address autoconfiguration.
* Native multicast and anycast support.
* Improved support for end-to-end communication.

# 🗁 IPv6 Address Structure

An IPv6 address contains exactly **128 bits**.

It is divided into eight groups of 16 bits, with each group represented using hexadecimal notation.

Example:

```text
2001:0db8:0000:0000:0000:ff00:0042:8329
```

Address structure:

| Hextet | Value |
| --- | --- |
| First | `2001` |
| Second | `0db8` |
| Third | `0000` |
| Fourth | `0000` |
| Fifth | `0000` |
| Sixth | `ff00` |
| Seventh | `0042` |
| Eighth | `8329` |

Each hexadecimal digit represents four bits.

Therefore:

\[
4 \times 4 = 16 \text{ bits per hextet}
\]

And:

\[
8 \times 16 = 128 \text{ bits}
\]

The theoretical IPv6 address space contains:

\[
2^{128}
\]

Approximately:

\[
3.4 \times 10^{38}
\]

possible address values.

# 🗁 Binary Representation

IPv6 addresses use hexadecimal notation because representing 128 bits in binary would be difficult to read and manage.

Each hexadecimal digit represents four binary bits.

| Hexadecimal | Binary |
| --- | --- |
| 0 | 0000 |
| 1 | 0001 |
| 2 | 0010 |
| 3 | 0011 |
| 4 | 0100 |
| 5 | 0101 |
| 6 | 0110 |
| 7 | 0111 |
| 8 | 1000 |
| 9 | 1001 |
| A | 1010 |
| B | 1011 |
| C | 1100 |
| D | 1101 |
| E | 1110 |
| F | 1111 |

Example:

```text
IPv6 Hextet: 2001

2 = 0010
0 = 0000
0 = 0000
1 = 0001
```

Binary representation:

```text
0010000000000001
```

An entire IPv6 address contains 128 binary bits.

# 🗁 IPv6 Address Compression

IPv6 addresses can be shortened using two standard compression rules.

**Omitting Leading Zeros**

Leading zeros inside any hextet can be omitted.

Example:

```text
Original:
2001:0db8:0000:0000:0000:ff00:0042:8329

Compressed:
2001:db8:0:0:0:ff00:42:8329
```

Only leading zeros can be removed.

Trailing zeros cannot be removed using this rule.

**Replacing Consecutive Zero Hextets**

One continuous sequence of one or more all-zero hextets can be replaced with `::`.

Example:

```text
Original:
2001:0db8:0000:0000:0000:ff00:0042:8329

Compressed:
2001:db8::ff00:42:8329
```

The `::` notation can replace a sequence of consecutive zero hextets only once in an address.

Using it multiple times would make the original address ambiguous.

**Example of Full Compression**

```text
Original:
2001:0db8:0000:0000:0000:0000:0000:0001

Compressed:
2001:db8::1
```

**Important Compression Rules**

* Leading zeros within a hextet may be removed.
* All-zero hextets can be compressed using `::`.
* Use `::` only once in an address.
* Do not remove trailing zeros using the leading-zero rule.
* IPv6 addresses should be written in lowercase hexadecimal for consistent documentation.

# 🗁 IPv6 Address Prefix

IPv6 uses prefix notation to identify network portions of an address.

The prefix length indicates how many leading bits belong to the network prefix.

Example:

```text
2001:db8:1234:5678::1/64
```

Here:

* IPv6 address: `2001:db8:1234:5678::1`
* Prefix length: `/64`
* Network prefix: `2001:db8:1234:5678::/64`
* Interface identifier: Remaining 64 bits.

A `/64` prefix is commonly used for IPv6 subnets.

Example:

```text
2001:db8:1234:5678:0000:0000:0000:0001
|------------------------|------------------------|
       64-bit prefix             64-bit interface identifier
```

IPv6 supports different prefix lengths depending on the addressing and routing requirements.

Common examples:

| Prefix | Typical Purpose |
| --- | --- |
| `/32` | Common ISP allocation |
| `/48` | Common organizational allocation |
| `/56` | Common customer-site allocation |
| `/64` | Typical LAN subnet |
| `/128` | Single IPv6 address route or host address |

These are common allocation patterns, not mandatory sizes for every network.

# 🗁 IPv6 Address Types

IPv6 defines several address types for different communication requirements.

The primary types are:

* Unicast.
* Multicast.
* Anycast.

IPv6 does not use broadcast addressing.

| Address Type | Communication Pattern | Purpose |
| --- | --- | --- |
| Unicast | One-to-one | Communication with a specific interface |
| Multicast | One-to-many group | Communication with multiple group members |
| Anycast | One-to-nearest | Delivery to one member of an anycast group |

# 🗁 Special IPv6 Addresses

IPv6 reserves several addresses and prefixes for special purposes.

| Address / Prefix | Purpose |
| --- | --- |
| `::` | Unspecified address |
| `::1` | Loopback address |
| `::/128` | Unspecified address prefix |
| `::ffff:0:0/96` | IPv4-mapped IPv6 address range |
| `fe80::/10` | Link-local unicast |
| `fc00::/7` | Unique local address |
| `ff00::/8` | Multicast |
| `2000::/3` | Global unicast allocation range |
| `2001:db8::/32` | Documentation and examples |
| `64:ff9b::/96` | Well-Known Prefix for IPv4/IPv6 translation |

# 🗁 Global Unicast Address

A **Global Unicast Address (GUA)** is an IPv6 address intended for globally routable communication.

Global unicast addresses generally belong to:

```text
2000::/3
```

Example:

```text
2001:4860:4860::8888
```

This is a globally assigned IPv6 address associated with Google's public DNS service.

A global unicast address is similar in purpose to a public IPv4 address.

Global unicast addresses are used for communication across different networks and the public Internet.

# 🗁 Link-Local Address

A **Link-Local Address (LLA)** is used for communication within a single network link.

The IPv6 link-local range is:

```text
fe80::/10
```

Example:

```text
fe80::1
```

Link-local addresses are automatically configured on IPv6-enabled interfaces in normal IPv6 operation.

They are used for:

* Neighbor Discovery Protocol.
* Router Discovery.
* Address resolution.
* Communication between directly connected IPv6 neighbors.

Link-local addresses are not forwarded by routers.

A link-local address may exist alongside global unicast and unique local addresses on the same interface.

**Important:** A link-local address is only meaningful within its link. When using it with command-line tools, a zone identifier may be necessary to identify the interface.

Example:

```bash
ping -6 fe80::1%eth0
```

Here, `%eth0` identifies the outgoing interface.

# 🗁 Unique Local Address

A **Unique Local Address (ULA)** is intended for private communication within organizations, homes, and other local networks.

The unique local address range is:

```text
fc00::/7
```

In practical deployments, locally assigned ULAs generally use the `fd00::/8` portion.

Example:

```text
fd12:3456:789a::1
```

ULAs are not intended to be globally routed across the public Internet.

They are useful for:

* Internal organizational networks.
* Home networks.
* Private infrastructure.
* Communication between internal services.
* Networks that require stable internal addressing.

ULAs are conceptually similar to RFC 1918 private IPv4 addresses, although their addressing architecture is different.

# 🗁 Multicast Address

IPv6 multicast addresses identify a group of network interfaces.

The multicast address range is:

```text
ff00::/8
```

A packet sent to an IPv6 multicast address is delivered to the interfaces that have joined the corresponding multicast group.

Examples:

| Address | Purpose |
| --- | --- |
| `ff02::1` | All IPv6 nodes on the local link |
| `ff02::2` | All IPv6 routers on the local link |
| `ff02::1:ff00:0/104` | Solicited-node multicast address range |
| `ff05::1:3` | All DHCP servers and relay agents in a site scope |

IPv6 uses multicast extensively for network discovery and control operations.

Unlike IPv4, IPv6 does not use broadcast addresses.

# 🗁 Anycast Address

An **Anycast Address** is assigned to multiple network interfaces.

Packets sent to an anycast address are routed to one member of the group, typically the nearest according to the routing protocol's path selection.

Example:

```text
                 Client
                    |
                    |
              Anycast Address
                 /     \
                /       \
          Server A     Server B
```

Anycast is commonly used in:

* DNS infrastructure.
* Content delivery networks.
* Distributed services.
* Globally distributed network infrastructure.

Anycast addresses are allocated from unicast address space. The routing configuration and deployment determine their anycast behavior.

# 🗁 IPv6 Packet Structure

An IPv6 packet consists of a fixed-size base header followed by optional extension headers and an upper-layer payload.

```text
+--------------------------------------+
|          IPv6 Base Header            |
|              40 Bytes                |
+--------------------------------------+
|       Optional Extension Headers    |
+--------------------------------------+
|                                      |
|             Payload                  |
|                                      |
+--------------------------------------+
```

The IPv6 base header is always 40 bytes.

It contains the following fields:

| Field | Size | Description |
| --- | ---: | --- |
| Version | 4 bits | Identifies IPv6; value is 6 |
| Traffic Class | 8 bits | Supports traffic classification and congestion notification |
| Flow Label | 20 bits | Identifies packets belonging to a flow |
| Payload Length | 16 bits | Length of everything after the base header |
| Next Header | 8 bits | Identifies the next header or upper-layer protocol |
| Hop Limit | 8 bits | Limits packet lifetime |
| Source Address | 128 bits | Source IPv6 address |
| Destination Address | 128 bits | Destination IPv6 address |

**Important Differences from IPv4**

* IPv6 has a fixed 40-byte base header.
* IPv6 does not include a header checksum.
* IPv6 does not contain a router fragmentation mechanism in its base header.
* Optional information is carried through extension headers.
* The TTL field is replaced by Hop Limit.
* The Protocol field is replaced by Next Header.

# 🗁 IPv6 Extension Headers

IPv6 uses extension headers to support optional network-layer functionality.

These headers are placed between the IPv6 base header and the upper-layer payload.

Common extension headers include:

| Extension Header | Purpose |
| --- | --- |
| Hop-by-Hop Options | Carries information that must be examined by nodes along the path |
| Routing | Supports routing-related information |
| Fragment | Carries source-generated fragmentation information |
| Destination Options | Carries options processed by the destination |
| Authentication Header (AH) | Provides IPsec authentication and integrity |
| Encapsulating Security Payload (ESP) | Provides IPsec confidentiality and related security services |

Example packet structure:

```text
IPv6 Base Header
       |
       v
Hop-by-Hop Options
       |
       v
Routing Header
       |
       v
TCP Header
       |
       v
Application Data
```

Not every IPv6 packet contains extension headers.

The Next Header field identifies the next header in the chain.

# 🗁 IPv6 Neighbor Discovery Protocol

**Neighbor Discovery Protocol (NDP)** is a collection of IPv6 mechanisms used to discover neighboring devices and routers on a local link.

NDP operates through ICMPv6 messages.

It replaces and extends several functions traditionally performed by ARP in IPv4 networks.

NDP supports:

* Router Discovery.
* Neighbor Discovery.
* Address Resolution.
* Neighbor Unreachability Detection.
* Duplicate Address Detection.
* Redirect messages.

Important ICMPv6 message types include:

| Message | Type | Purpose |
| --- | ---: | --- |
| Router Solicitation | 133 | Requests router advertisements |
| Router Advertisement | 134 | Announces router and network configuration information |
| Neighbor Solicitation | 135 | Resolves neighbor addresses and supports duplicate-address detection |
| Neighbor Advertisement | 136 | Responds to neighbor solicitations |
| Redirect | 137 | Informs a host of a better next-hop router |

Example:

```text
Host A
   |
   | Neighbor Solicitation
   v
Solicited-Node Multicast Address
   |
   | Neighbor Advertisement
   v
Host B
```

NDP is essential for normal IPv6 operation.

# 🗁 IPv6 Address Configuration

IPv6 supports multiple methods for assigning addresses and configuring network interfaces.

The major methods include:

* Manual configuration.
* Stateless Address Autoconfiguration (SLAAC).
* Dynamic Host Configuration Protocol for IPv6 (DHCPv6).

**Manual Configuration**

An administrator can manually configure an IPv6 address and prefix.

Example:

```text
Address: 2001:db8:1:1::10/64
Gateway: fe80::1
```

Manual configuration is commonly used for servers, network infrastructure, and controlled environments.

**Stateless Address Autoconfiguration (SLAAC)**

SLAAC allows IPv6 hosts to configure addresses automatically using information received through Router Advertisement messages.

A simplified process:

```text
IPv6 Host
    |
    | Router Solicitation
    v
IPv6 Router
    |
    | Router Advertisement
    | Prefix Information
    v
IPv6 Host
    |
    v
Creates IPv6 Address
    |
    v
Performs Duplicate Address Detection
```

SLAAC allows a host to obtain network prefix information without requiring a DHCPv6 server.

**DHCPv6**

DHCPv6 provides additional IPv6 configuration capabilities.

It can assign IPv6 addresses and provide other configuration information, depending on the deployment.

DHCPv6 supports two major operational models:

* Stateful DHCPv6: The server assigns and tracks IPv6 addresses.
* Stateless DHCPv6: The host obtains its address through SLAAC but can receive additional configuration through DHCPv6.

The router's Router Advertisement flags help hosts determine which configuration mechanisms are available.

# 🗁 IPv6 Fragmentation

IPv6 handles fragmentation differently from IPv4.

**Routers do not fragment IPv6 packets.**

If a packet is larger than the outgoing link's MTU, a router discards it and typically sends an ICMPv6 Packet Too Big message to the source.

The source can then adjust the packet size.

If fragmentation is necessary, the source host can fragment the packet using an IPv6 Fragment extension header.

```text
Original IPv6 Packet
         |
         v
Source Host Fragmentation
         |
     +---+---+
     |       |
     v       v
Fragment 1  Fragment 2
     |       |
     +---+---+
         |
         v
      Destination
         |
         v
    Reassembly
```

**Path MTU Discovery**

Path MTU Discovery helps determine the maximum packet size that can travel across an entire network path without fragmentation.

IPv6 relies on ICMPv6 Packet Too Big messages to support this process.

The default minimum IPv6 link MTU is 1280 bytes.

# 🗁 IPv6 vs IPv4

| Feature | IPv4 | IPv6 |
| --- | --- | --- |
| Address Size | 32 bits | 128 bits |
| Address Format | Dotted decimal | Colon-separated hexadecimal |
| Example | `192.168.1.10` | `2001:db8::10` |
| Address Space | Approximately 4.3 billion values | Approximately 3.4 × 10³⁸ values |
| Header Size | Variable, 20–60 bytes | Fixed, 40-byte base header |
| Header Checksum | Present | Not present |
| Broadcast | Supported | Not supported |
| Multicast | Supported | Supported |
| Anycast | Supported through routing configuration | Supported |
| Address Resolution | ARP on Ethernet | NDP |
| Fragmentation | Source and routers, when permitted | Source only |
| TTL / Hop Limit | TTL | Hop Limit |
| Configuration | Manual or DHCP | Manual, SLAAC, or DHCPv6 |
| Private Addressing | RFC 1918 | Unique Local Addresses |
| IPsec Support | Supported | Supported |

Both IPv4 and IPv6 can operate simultaneously using dual-stack networking.

# 🗁 Practical Linux Commands

Ubuntu and other Linux distributions provide several commands for inspecting and troubleshooting IPv6 configuration.

**Display IPv6 Addresses**

```bash
ip -6 address show
```

**Display All Network Addresses**

```bash
ip address show
```

**Display IPv6 Routing Table**

```bash
ip -6 route show
```

**Display IPv6 Default Gateway**

```bash
ip -6 route show default
```

**Display IPv6 Neighbor Table**

```bash
ip -6 neigh show
```

**Test IPv6 Connectivity**

```bash
ping -6 -c 4 2001:4860:4860::8888
```

**Test IPv6 Loopback**

```bash
ping -6 -c 4 ::1
```

**Trace an IPv6 Route**

```bash
traceroute -6 2001:4860:4860::8888
```

**Inspect an IPv6 Routing Decision**

```bash
ip -6 route get 2001:4860:4860::8888
```

**Display Listening IPv6 Sockets**

```bash
ss -6 -tuln
```

**Display IPv6 Interface Information**

```bash
ip -6 addr show dev eth0
```

Replace `eth0` with the actual interface name on your system.

# 🗁 Common Misconceptions

| Misconception | Correct Explanation |
| --- | --- |
| IPv6 uses 64-bit addresses. | IPv6 addresses contain 128 bits. |
| IPv6 is simply IPv4 with longer addresses. | IPv6 also changes packet headers, addressing, neighbor discovery, and fragmentation behavior. |
| IPv6 supports broadcast. | IPv6 does not use broadcast; it uses multicast for group communication. |
| IPv6 always requires DHCPv6. | IPv6 can use SLAAC without DHCPv6. |
| IPv6 eliminates the need for firewalls. | IPv6 networks still require appropriate firewall policies. |
| IPv6 routers fragment packets. | IPv6 routers do not fragment packets. Only the source can fragment them. |
| Every IPv6 address is globally routable. | IPv6 includes link-local, unique local, multicast, loopback, and other special-purpose addresses. |
| IPv6 does not support NAT. | NAT mechanisms can be used with IPv6, although address conservation generally does not require NAT. |
| `::` can appear multiple times in an address. | The zero-compression notation `::` can appear only once. |
| IPv6 does not use ICMP. | ICMPv6 is essential for IPv6 diagnostics, error reporting, and Neighbor Discovery. |

# 🗁 Best Practices

* Use `/64` prefixes for ordinary IPv6 LAN subnets unless a specific design requires otherwise.
* Use global unicast addresses for globally reachable services.
* Use unique local addresses for internal network communication where appropriate.
* Allow required ICMPv6 traffic, especially Neighbor Discovery and Packet Too Big messages.
* Configure IPv6 firewall policies rather than assuming IPv4 firewall rules cover IPv6.
* Use SLAAC, DHCPv6, or manual configuration according to network requirements.
* Monitor IPv6 routing and neighbor information.
* Avoid unnecessary NAT66 deployment.
* Maintain accurate IPv6 address and prefix documentation.
* Plan DNS records for IPv6-enabled services.
* Support dual-stack networking where IPv4 compatibility is required.
* Test Path MTU Discovery to prevent packet-size-related connectivity problems.

IPv6 is a 128-bit network-layer addressing protocol designed to support modern Internet communication.

# 🗁 Interview Questions

**What is IPv6?**

IPv6 is the sixth version of the Internet Protocol. It uses 128-bit addresses to identify network interfaces and deliver packets across networks.

**How many bits are in an IPv6 address?**

An IPv6 address contains 128 bits.

**How many hexadecimal groups are in a complete IPv6 address?**

A complete IPv6 address contains eight groups of 16 bits each.

**How many possible IPv6 address values exist?**

IPv6 provides \(2^{128}\) possible address values.

**What is an IPv6 hextet?**

A hextet is a 16-bit section of an IPv6 address represented using up to four hexadecimal digits.

**What is the purpose of `::` in IPv6?**

The `::` notation compresses one consecutive sequence of zero-valued hextets.

**Can `::` be used more than once in an IPv6 address?**

No. It can be used only once because multiple occurrences would make the address ambiguous.

**What is a link-local IPv6 address?**

A link-local address is used for communication within a single network link. Its prefix is `fe80::/10`.

**What is a unique local IPv6 address?**

A unique local address is intended for private communication within local networks. Its prefix is `fc00::/7`.

**What is the difference between global unicast and link-local addresses?**

Global unicast addresses are intended for globally routable communication, while link-local addresses are limited to a single network link.

**Does IPv6 support broadcast?**

No. IPv6 uses multicast instead of broadcast.

**What is NDP?**

Neighbor Discovery Protocol is an IPv6 mechanism that supports neighbor discovery, address resolution, router discovery, and duplicate address detection.

**What is SLAAC?**

Stateless Address Autoconfiguration allows IPv6 hosts to automatically configure addresses using information received through Router Advertisement messages.

**What is the difference between SLAAC and DHCPv6?**

SLAAC allows hosts to generate their own addresses using advertised prefixes, while DHCPv6 provides additional address and configuration assignment capabilities.

**Can IPv6 routers fragment packets?**

No. IPv6 routers do not fragment packets. Fragmentation is performed by the source host when necessary.

**What is the minimum IPv6 MTU?**

The minimum IPv6 link MTU is 1280 bytes.

**Why is ICMPv6 important?**

ICMPv6 supports error reporting, diagnostics, Neighbor Discovery, and other essential IPv6 functions.
