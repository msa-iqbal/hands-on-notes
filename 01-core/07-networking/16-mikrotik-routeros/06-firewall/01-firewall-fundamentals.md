# Firewall Fundamentals

A firewall is a network security mechanism that monitors and controls incoming and outgoing network traffic according to predefined security policies.

In MikroTik RouterOS, the firewall provides tools for filtering packets, managing connections, controlling network access, protecting router services, and implementing traffic security policies.

RouterOS firewall functionality is particularly important in enterprise networks, multi-WAN environments, and ISP infrastructure.

# 🗁 What Is a Firewall?

A firewall examines network traffic and determines whether packets should be accepted, dropped, rejected, or processed according to configured rules.

A firewall can control traffic based on several packet and connection attributes:

* Source IP address.
* Destination IP address.
* Source port.
* Destination port.
* IP protocol.
* Incoming interface.
* Outgoing interface.
* Connection state.
* Connection tracking status.
* Address lists.
* Packet characteristics.

For example, a firewall can allow LAN devices to access the internet while blocking unsolicited incoming connections from the WAN.

# 🗁 Why Firewalls Are Important

Firewalls provide an important security boundary between trusted and untrusted networks.

Common firewall objectives include:

* Preventing unauthorized network access.
* Protecting router management services.
* Controlling communication between LAN and WAN.
* Restricting access between network segments.
* Allowing only required application services.
* Blocking unwanted or suspicious traffic.
* Limiting access to specific IP addresses and ports.
* Protecting internal servers.
* Controlling traffic between customers in ISP networks.

A properly designed firewall follows the principle of least privilege: allow only the traffic required for legitimate network operations.

# 🗁 MikroTik RouterOS Firewall Architecture

RouterOS provides several firewall facilities that work together to process and control network traffic.

The major components include:

| Component | Purpose |
| --- | --- |
| Filter | Accepts, drops, or rejects packets |
| NAT | Translates source or destination addresses |
| Mangle | Marks packets and connections for advanced processing |
| Raw | Processes packets before connection tracking |
| Connection Tracking | Maintains connection state and NAT information |
| Address Lists | Groups IP addresses for reusable firewall matching |

These components serve different purposes but can interact during packet processing.

# 🗁 Firewall Filter

The firewall filter is responsible for allowing or blocking network packets.

RouterOS provides three primary filter chains:

| Chain | Purpose |
| --- | --- |
| `input` | Controls packets destined for the router itself |
| `forward` | Controls packets passing through the router |
| `output` | Controls packets generated by the router |

Example:

```routeros
/ip/firewall/filter
add chain=input protocol=icmp action=accept comment="Allow ICMP to Router"
```

This rule allows ICMP packets destined for the router.

Another example:

```routeros
/ip/firewall/filter
add chain=forward src-address=192.168.10.0/24 action=accept comment="Allow LAN Forwarding"
```

This rule allows matching packets from the specified source network to continue through the forward chain, subject to the remaining firewall policy.

# 🗁 Network Address Translation

Network Address Translation (NAT) modifies IP address information in packets.

RouterOS provides two commonly used NAT chains:

| Chain | Purpose |
| --- | --- |
| `srcnat` | Modifies source addresses |
| `dstnat` | Modifies destination addresses |

Common NAT actions include:

* `src-nat`: Replaces the source address with a specified address.
* `masquerade`: Uses the current address of the outgoing interface.
* `dst-nat`: Replaces the destination address and optionally the destination port.
* `redirect`: Redirects matching traffic to a service on the router.

Example Source NAT:

```routeros
/ip/firewall/nat
add chain=srcnat out-interface=ether1 action=masquerade comment="Internet Access"
```

Example Destination NAT:

```routeros
/ip/firewall/nat
add chain=dstnat in-interface=ether1 protocol=tcp dst-port=80 action=dst-nat to-addresses=192.168.10.10 to-ports=80 comment="Forward HTTP"
```

NAT and firewall filtering have different responsibilities. NAT changes packet addressing, while filter rules determine whether traffic is permitted.

# 🗁 Connection Tracking

Connection tracking maintains information about network connections passing through the router.

It allows RouterOS to identify whether packets belong to:

* New connections.
* Established connections.
* Related connections.
* Invalid connections.
* Untracked connections.

Connection tracking is important for stateful firewall policies and NAT.

For example:

```routeros
/ip/firewall/filter
add chain=forward connection-state=established,related action=accept comment="Allow Established and Related"
```

This rule accepts packets belonging to established connections and connections related to existing tracked sessions.

Connection tracking also maintains NAT translations so that response packets can be associated with the original connection.

# 🗁 Raw Firewall

The Raw firewall processes packets before connection tracking.

It is commonly used to drop unwanted traffic early, before the router spends resources maintaining connection-tracking information for those packets.

The Raw firewall provides two primary chains:

| Chain | Purpose |
| --- | --- |
| `prerouting` | Processes incoming packets before routing and connection tracking |
| `output` | Processes packets generated by the router before connection tracking |

Example:

```routeros
/ip/firewall/raw
add chain=prerouting src-address=198.51.100.50 action=drop comment="Drop Unwanted Source"
```

This rule drops packets from the specified source address in the Raw prerouting chain.

Because Raw processing occurs before connection tracking, connection-state matchers are not available there.

# 🗁 Mangle Firewall

Mangle is used for specialized packet and connection processing.

It can mark packets, connections, and routing decisions for advanced network configurations.

Common uses include:

* Policy-based routing.
* Multi-WAN load balancing.
* Traffic classification.
* QoS configuration.
* Connection marking.
* Packet marking.
* Routing marking.

Example:

```routeros
/ip/firewall/mangle
add chain=prerouting src-address=192.168.10.0/24 action=mark-connection new-connection-mark=LAN-CONNECTION passthrough=yes comment="Mark LAN Connections"
```

This rule marks matching connections originating from the specified LAN network.

Mangle is especially useful in advanced routing and traffic-management scenarios.

# 🗁 Firewall Packet Processing Overview

A packet can pass through different firewall facilities depending on its origin and destination.

A simplified processing overview is:

```text
Incoming Packet
       |
       v
    Raw
       |
       v
Connection Tracking
       |
       v
   Mangle
       |
       v
 Destination NAT
       |
       v
    Routing
       |
       +---------------------+
       |                     |
       v                     v
   Input Chain          Forward Chain
       |                     |
       v                     v
      Router              Destination
       |                     |
       v                     v
    Output Chain        Source NAT
       |                     |
       v                     v
  Outgoing Packet       Outgoing Packet
```

This diagram is a simplified conceptual representation. The exact path depends on whether traffic is destined for the router, forwarded through it, or generated locally. RouterOS also has additional processing hooks and stages.

# 🗁 Stateful vs Stateless Firewall

Firewall filtering can be implemented using either stateless or stateful approaches.

| Feature | Stateless Firewall | Stateful Firewall |
| --- | --- | --- |
| Connection awareness | Does not maintain connection state | Tracks connections |
| Packet evaluation | Evaluates individual packets | Uses connection information |
| Return traffic | Usually requires explicit rules | Can recognize established traffic |
| Complexity | Simpler for basic filtering | More flexible for connection-based policies |
| Resource usage | Generally lower | Requires connection-tracking resources |

RouterOS supports stateful firewall configurations through connection tracking.

Example:

```routeros
/ip/firewall/filter
add chain=input connection-state=established,related action=accept
add chain=input connection-state=invalid action=drop
```

This allows established and related traffic while dropping packets identified as invalid.

# 🗁 Firewall Rule Processing

RouterOS evaluates firewall rules in their configured order within a chain.

When a packet matches a rule, the configured action determines what happens next.

Common actions include:

| Action | Description |
| --- | --- |
| `accept` | Allows the packet |
| `drop` | Silently discards the packet |
| `reject` | Discards the packet and sends a rejection response |
| `log` | Logs matching packets |
| `jump` | Transfers processing to another chain |
| `return` | Returns processing to the calling chain |
| `passthrough` | Continues processing without terminating the current rule evaluation |

Rule order is critical because an earlier matching terminal action can prevent later rules from being evaluated.

For example:

```routeros
/ip/firewall/filter
add chain=input src-address=192.168.10.0/24 action=accept comment="Allow LAN"
add chain=input action=drop comment="Drop Other Input"
```

The first rule allows traffic from the specified LAN network. The second rule drops other traffic reaching the input chain.

# 🗁 Default Firewall Policy

A secure firewall design normally follows a default-deny approach.

This means:

* Allow required traffic explicitly.
* Drop traffic that is not authorized.
* Accept established and related connections where appropriate.
* Drop invalid connections.
* Restrict router management access.
* Permit only required forwarding between networks.

A basic example of a stateful firewall policy is:

```routeros
/ip/firewall/filter
add chain=input connection-state=established,related action=accept comment="Allow Established and Related Input"
add chain=input connection-state=invalid action=drop comment="Drop Invalid Input"
add chain=input in-interface-list=LAN action=accept comment="Allow LAN Access"
add chain=input action=drop comment="Drop Other Input"

add chain=forward connection-state=established,related action=accept comment="Allow Established and Related Forward"
add chain=forward connection-state=invalid action=drop comment="Drop Invalid Forward"
add chain=forward in-interface-list=LAN out-interface-list=WAN action=accept comment="Allow LAN to WAN"
add chain=forward action=drop comment="Drop Other Forwarded Traffic"
```

This is a starting example, not a complete universal firewall configuration. A production firewall must account for required management protocols, VPNs, routing protocols, inter-VLAN traffic, published services, and other network requirements.

# 🗁 Interface Lists and Firewall Policies

Interface lists allow firewall rules to reference groups of interfaces instead of individual interface names.

For example, a router can have multiple WAN interfaces and multiple LAN interfaces.

Create interface lists:

```routeros
/interface/list
add name=WAN
add name=LAN
```

Add interfaces:

```routeros
/interface/list/member
add list=WAN interface=ether1
add list=LAN interface=ether2
```

Use the lists in firewall rules:

```routeros
/ip/firewall/filter
add chain=forward in-interface-list=LAN out-interface-list=WAN action=accept comment="Allow LAN to WAN"
```

This approach simplifies firewall management when interfaces change or additional WAN and LAN interfaces are introduced.

# 🗁 Firewall Address Lists

Address lists group IP addresses or network ranges under reusable names.

They are useful for:

* Trusted administrator addresses.
* Blocked source addresses.
* Customer network groups.
* Management access restrictions.
* Application access policies.

Example:

```routeros
/ip/firewall/address-list
add list=trusted-admins address=192.168.10.50 comment="Administrator Workstation"
add list=trusted-admins address=198.51.100.25 comment="Remote Administrator"
```

Use the address list in a firewall rule:

```routeros
/ip/firewall/filter
add chain=input src-address-list=trusted-admins action=accept comment="Allow Trusted Administrators"
```

Address lists make it easier to reuse the same group of addresses across multiple firewall rules.

# 🗁 Firewall Logging

Firewall logging helps administrators investigate network activity and troubleshoot blocked connections.

Example:

```routeros
/ip/firewall/filter
add chain=input in-interface-list=WAN action=drop log=yes log-prefix="WAN-DROP: " comment="Log Dropped WAN Traffic"
```

Matching packets are logged before being dropped.

View the router log:

```routeros
/log/print
```

Filter firewall-related log entries:

```routeros
/log/print where message~"WAN-DROP"
```

Logging should be applied selectively. Excessive logging can consume router resources and make important events difficult to identify.

# 🗁 Practical Example

Consider a small office network with one WAN connection and one LAN network.

**Network topology:**

```text
                 Internet
                     |
                     |
                  ether1
                     |
              MikroTik Router
                     |
                  ether2
                     |
              LAN: 192.168.10.0/24
                     |
             +-------+-------+
             |               |
           PC-01           PC-02
       192.168.10.10   192.168.10.20
```

Requirements:

* Allow LAN devices to access the internet.
* Allow established and related connections.
* Allow LAN administrators to access the router.
* Block unsolicited WAN access to router services.
* Drop invalid connections.
* Block unauthorized forwarding traffic.

Create interface lists:

```routeros
/interface/list
add name=WAN
add name=LAN
```

Add interfaces:

```routeros
/interface/list/member
add list=WAN interface=ether1
add list=LAN interface=ether2
```

Configure the firewall filter:

```routeros
/ip/firewall/filter
add chain=input connection-state=established,related action=accept comment="Allow Established and Related Input"
add chain=input connection-state=invalid action=drop comment="Drop Invalid Input"
add chain=input protocol=icmp action=accept comment="Allow ICMP"
add chain=input in-interface-list=LAN action=accept comment="Allow LAN Management"
add chain=input in-interface-list=WAN action=drop comment="Drop WAN Input"

add chain=forward connection-state=established,related action=accept comment="Allow Established and Related Forward"
add chain=forward connection-state=invalid action=drop comment="Drop Invalid Forward"
add chain=forward in-interface-list=LAN out-interface-list=WAN action=accept comment="Allow LAN to WAN"
add chain=forward action=drop comment="Drop Other Forwarded Traffic"
```

The rules should be integrated with the router's existing firewall configuration. Verify interface-list membership and rule order before applying them to a live router.

# 🗁 Important Considerations

* RouterOS firewall rules are evaluated in order within each chain.
* The `input` chain protects services running on the router.
* The `forward` chain controls traffic passing through the router.
* The `output` chain controls traffic generated by the router.
* Connection tracking enables stateful firewall behavior and NAT.
* Raw rules process packets before connection tracking.
* Mangle rules support advanced packet and routing decisions.
* NAT modifies packet addressing but does not replace firewall filtering.
* Interface lists simplify firewall policies.
* Address lists provide reusable groups of IP addresses.
* Logging should be selective to avoid unnecessary resource consumption.
* Firewall policies should follow least privilege and default-deny principles.
* Router management access should be restricted to trusted networks and administrators.

# 🗁 Summary

The MikroTik RouterOS firewall provides several tools for controlling and securing network traffic.

The Filter facility allows or blocks packets, NAT translates addresses, Connection Tracking maintains connection state, Raw processes packets before connection tracking, Mangle supports advanced packet marking, and Address Lists provide reusable groups of IP addresses.

Understanding these components establishes the foundation for building secure RouterOS firewall policies, protecting router services, controlling forwarded traffic, and managing complex network environments.
