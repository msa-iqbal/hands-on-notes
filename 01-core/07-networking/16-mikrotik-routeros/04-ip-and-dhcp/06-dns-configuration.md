# DNS Configuration in MikroTik RouterOS

DNS (Domain Name System) translates human-readable domain names into IP addresses.

For example, when a user accesses `google.com`, DNS helps identify the IP address associated with that domain.

In MikroTik RouterOS, DNS configuration allows the router to:

* Use external DNS servers to resolve domain names.
* Provide DNS resolution to LAN clients.
* Cache DNS responses to improve performance.
* Receive DNS server information from DHCP or other upstream services.
* Configure static DNS records for local devices.
* Control which clients can use the router as a DNS resolver.

DNS is an essential service for home networks, business networks, and ISP environments.

# 🗁 Understanding DNS

Computers communicate using IP addresses, but users generally prefer domain names.

DNS provides the mapping between domain names and IP addresses.

Example:

```text
Domain Name: google.com

DNS Resolution:

google.com
     |
     v
DNS Resolver
     |
     v
IP Address
     |
     v
Server Connection
```

Example DNS record:

```text
google.com -> 142.250.x.x
```

The actual IP address can vary depending on location, DNS provider, and network conditions.

# 🗁 How DNS Resolution Works

When a client requests a domain name, the DNS resolver searches for the corresponding DNS record.

A simplified DNS resolution process:

```text
             LAN Client
                 |
                 | DNS Query
                 v
          MikroTik Router
             DNS Cache
                 |
          Cache Miss?
                 |
                 v
          Upstream DNS Server
                 |
                 v
          DNS Response
                 |
                 v
          MikroTik Router
                 |
                 v
             LAN Client
```

If the requested record is already cached, the router may respond without contacting an upstream DNS server.

If the record is not cached, the router forwards the query to its configured upstream DNS server.

# 🗁 DNS Components

| Component | Description |
| --- | --- |
| DNS Client | Sends DNS queries |
| DNS Resolver | Processes DNS requests |
| Recursive Resolver | Finds answers on behalf of clients |
| Root DNS Server | Directs queries toward top-level domains |
| TLD DNS Server | Provides information about a domain's authoritative servers |
| Authoritative DNS Server | Provides DNS records for a domain |
| DNS Cache | Temporarily stores DNS responses |

A MikroTik router commonly operates as a DNS caching resolver for its LAN clients while forwarding queries to upstream DNS resolvers.

# 🗁 DNS Configuration Menu

RouterOS manages DNS settings through:

```routeros
/ip dns
```

Display current DNS configuration:

```routeros
/ip dns print
```

Important properties include:

| Property | Purpose |
| --- | --- |
| `servers` | Configures upstream DNS servers |
| `dynamic-servers` | Displays dynamically learned DNS servers |
| `allow-remote-requests` | Allows remote clients to use the router as a DNS resolver |
| `cache-size` | Configures DNS cache capacity |
| `cache-used` | Displays current cache usage |
| `max-udp-packet-size` | Configures the maximum DNS UDP packet size |
| `query-server-timeout` | Controls upstream DNS query timeout |
| `query-total-timeout` | Controls total DNS query timeout |

Available properties can vary by RouterOS version.

# 🗁 Configure Upstream DNS Servers

Upstream DNS servers are responsible for resolving domain names outside the router's local DNS records.

Popular public DNS resolvers include:

| Provider | IPv4 Address |
| --- | --- |
| Cloudflare DNS | 1.1.1.1 |
| Cloudflare Secondary | 1.0.0.1 |
| Google DNS | 8.8.8.8 |
| Google Secondary | 8.8.4.4 |
| Quad9 DNS | 9.9.9.9 |
| Quad9 Secondary | 149.112.112.112 |

Configure Cloudflare and Google DNS:

```routeros
/ip dns
set servers=1.1.1.1,8.8.8.8
```

Verify:

```routeros
/ip dns print
```

The router will use the configured upstream servers when resolving DNS queries.

# 🗁 Configure Multiple DNS Servers

RouterOS supports multiple upstream DNS servers.

Example:

```routeros
/ip dns
set servers=1.1.1.1,1.0.0.1,8.8.8.8,8.8.4.4
```

Multiple servers provide alternative resolvers when one is unavailable.

RouterOS manages queries according to its resolver behavior. A list of DNS servers should not be treated as a strict primary-and-backup failover policy.

# 🗁 Enable DNS Requests from LAN Clients

By default, the router can resolve DNS queries generated by its own services.

To allow LAN clients to use the MikroTik router as their DNS resolver, enable remote requests:

```routeros
/ip dns
set allow-remote-requests=yes
```

Example network:

```text
                Internet
                   |
             Upstream DNS
                   |
             MikroTik Router
              192.168.10.1
                   |
               bridge-LAN
                   |
            +------+------+
            |      |      |
           PC   Laptop  Phone
```

Configure LAN clients to use:

```text
DNS Server: 192.168.10.1
```

The router receives DNS queries from LAN clients and forwards them to its configured upstream DNS servers.

# 🗁 Configure DHCP to Provide MikroTik as DNS Server

When the MikroTik router provides DHCP services, configure the DHCP network to advertise the router's LAN address as the DNS server.

Example:

```routeros
/ip dhcp-server network
set [find address=192.168.10.0/24] dns-server=192.168.10.1
```

The DHCP clients will receive:

```text
IP Address:     192.168.10.x
Gateway:        192.168.10.1
DNS Server:     192.168.10.1
```

Ensure that the router's DNS service is configured with upstream DNS servers and `allow-remote-requests=yes`.

# 🗁 DNS Cache

A DNS cache temporarily stores DNS responses.

When a client requests a previously resolved domain, the router may return the cached response instead of sending another query upstream.

Benefits include:

* Reduced repeated DNS queries.
* Faster responses for cached records.
* Reduced upstream DNS traffic.
* Improved efficiency for frequently accessed domains.

Display DNS cache entries:

```routeros
/ip dns cache print
```

Display detailed cache information:

```routeros
/ip dns cache print detail
```

# 🗁 Flush DNS Cache

Sometimes cached DNS records need to be cleared.

For example:

* A domain's IP address has changed.
* A DNS record was cached incorrectly.
* DNS troubleshooting is required.
* A local DNS configuration has changed.

Clear the DNS cache:

```routeros
/ip dns cache flush
```

Verify:

```routeros
/ip dns cache print
```

The router will request fresh DNS information when needed.

# 🗁 Configure DNS Cache Size

RouterOS allows administrators to configure the amount of memory allocated to DNS caching.

Example:

```routeros
/ip dns
set cache-size=4096KiB
```

Inspect the cache configuration:

```routeros
/ip dns print
```

The appropriate cache size depends on available router memory and network requirements.

Increasing cache size does not automatically improve DNS performance in every environment.

# 🗁 Configure Static DNS Records

Static DNS records allow administrators to define local domain-to-address mappings.

This is useful for internal servers, printers, NAS devices, and network management systems.

Example network:

```text
Development Server: 192.168.10.10
File Server:        192.168.10.20
Printer:            192.168.10.30
```

Create static DNS records:

```routeros
/ip dns static
add name=dev.local address=192.168.10.10

add name=files.local address=192.168.10.20

add name=printer.local address=192.168.10.30
```

Clients using the MikroTik router as their DNS resolver can resolve these names.

Example:

```bash
ping dev.local
ping files.local
ping printer.local
```

For larger internal networks, use a domain namespace reserved for private use, such as a subdomain of an organization-controlled domain. The `.local` namespace is commonly used by multicast DNS and can create name-resolution conflicts.

# 🗁 Configure a DNS Record with a Comment

Comments help identify the purpose of static DNS records.

Example:

```routeros
/ip dns static
add name=nas.example.internal address=192.168.10.50 comment="Office NAS"
```

Display static DNS records:

```routeros
/ip dns static print
```

# 🗁 Configure DNS CNAME Records

A CNAME record creates an alias for another DNS name.

Example:

```routeros
/ip dns static
add name=files.example.internal type=CNAME cname=nas.example.internal
```

In this example, `files.example.internal` is an alias for `nas.example.internal`.

A CNAME record points to another hostname rather than directly storing an IPv4 address.

# 🗁 Configure DNS Forwarding

DNS forwarding means sending DNS queries to another DNS resolver.

In RouterOS, configure upstream DNS servers:

```routeros
/ip dns
set servers=1.1.1.1,8.8.8.8
```

When a client sends a DNS query to the MikroTik router:

1. RouterOS checks its static DNS records.
2. RouterOS checks its DNS cache.
3. If no suitable answer is available, it forwards the query upstream.
4. RouterOS returns the response to the client.

This provides centralized DNS resolution for LAN clients.

# 🗁 Configure DNS from DHCP Client

An upstream DHCP server can provide DNS server addresses to a MikroTik DHCP client.

Enable peer DNS:

```routeros
/ip dhcp-client
set [find interface=ether1] use-peer-dns=yes
```

Inspect DNS configuration:

```routeros
/ip dns print
```

Disable peer DNS when manually configured DNS servers should be used:

```routeros
/ip dhcp-client
set [find interface=ether1] use-peer-dns=no
```

Then configure DNS manually:

```routeros
/ip dns
set servers=1.1.1.1,8.8.8.8
```

# 🗁 Configure DNS over HTTPS

DNS over HTTPS (DoH) sends DNS queries through encrypted HTTPS connections instead of traditional unencrypted DNS transport.

RouterOS supports DNS over HTTPS through the `use-doh-server` property.

Example:

```routeros
/ip dns
set use-doh-server=https://cloudflare-dns.com/dns-query verify-doh-cert=yes
```

Configure the DoH server hostname to resolve before enabling DoH. A bootstrap DNS server may be required for initial hostname resolution.

For example, configure a conventional DNS server temporarily or retain a working bootstrap resolver as appropriate for the RouterOS configuration.

Inspect the DNS configuration:

```routeros
/ip dns print
```

DoH requires:

* Working Internet connectivity.
* Correct system time.
* Valid certificate verification.
* Reachability of the DoH endpoint.
* Successful hostname resolution during initial setup.

Certificate verification should remain enabled in production configurations.

# 🗁 DNS over HTTPS vs Traditional DNS

| Feature | Traditional DNS | DNS over HTTPS |
| --- | --- | --- |
| Common transport | UDP/TCP | HTTPS over TCP |
| Standard port | 53 | 443 |
| Encryption | Usually unencrypted | Encrypted |
| Privacy | DNS queries may be observable | Protects queries between client and DoH resolver |
| Network compatibility | Widely supported | Requires HTTPS connectivity |

DoH encrypts the connection to the selected resolver, but it does not hide all network activity or guarantee anonymity.

# 🗁 Configure DNS for Multiple VLANs

A MikroTik router can provide DNS resolution to multiple VLANs.

Example:

```text
                  MikroTik Router
                   DNS Resolver
                         |
              +----------+----------+
              |                     |
           VLAN 10               VLAN 20
         192.168.10.0/24       192.168.20.0/24
              |                     |
           Clients                Clients
```

Configure DHCP network DNS settings:

```routeros
/ip dhcp-server network
set [find address=192.168.10.0/24] dns-server=192.168.10.1

set [find address=192.168.20.0/24] dns-server=192.168.20.1
```

Both VLANs can use the router as their DNS resolver.

The router's firewall must allow DNS traffic from the intended VLAN interfaces.

# 🗁 DNS Firewall Configuration

When `allow-remote-requests=yes` is enabled, RouterOS accepts DNS requests from remote clients.

Protect the resolver by allowing DNS traffic only from trusted networks.

Example:

```routeros
/ip firewall filter
add chain=input action=accept protocol=udp dst-port=53 in-interface=bridge-LAN comment="Allow LAN DNS UDP"

add chain=input action=accept protocol=tcp dst-port=53 in-interface=bridge-LAN comment="Allow LAN DNS TCP"
```

These rules must be placed before any rule that drops the corresponding traffic.

For multiple trusted VLANs, create appropriate rules for each interface or use an interface list.

Do not expose the router's DNS resolver to the public Internet unless the service is intentionally designed and secured for that purpose.

# 🗁 DNS Troubleshooting

**Domain names cannot be resolved**

Possible causes:

* Incorrect upstream DNS servers.
* DNS requests blocked by firewall.
* No Internet connectivity.
* DNS server unavailable.
* Incorrect client DNS configuration.

Check:

```routeros
/ip dns print
/ip dns cache print
/ping 1.1.1.1
/ping google.com
```

**Router can resolve domains but LAN clients cannot**

Possible causes:

* `allow-remote-requests` is disabled.
* DHCP provides an incorrect DNS address.
* Firewall blocks DNS traffic.
* Clients have an old DHCP lease.

Check:

```routeros
/ip dns print
/ip dhcp-server network print detail
/ip firewall filter print
```

**DNS resolution is slow**

Possible causes:

* Upstream DNS server latency.
* Packet loss.
* Network congestion.
* Unresponsive DNS resolver.
* Incorrect routing.

Check upstream connectivity and test alternative DNS resolvers.

**Static DNS record does not resolve**

Possible causes:

* Incorrect hostname.
* Incorrect record type.
* Client uses a different DNS server.
* Existing cached response.
* Incorrect static record configuration.

Check:

```routeros
/ip dns static print detail
/ip dns cache print
```

Flush the cache if necessary:

```routeros
/ip dns cache flush
```

**DNS over HTTPS does not work**

Possible causes:

* Incorrect DoH endpoint.
* Certificate verification failure.
* Incorrect system date and time.
* Bootstrap DNS resolution failure.
* HTTPS connectivity blocked.

Check:

```routeros
/system clock print
/ip dns print detail
/ping cloudflare-dns.com
```

# 🗁 DNS Testing Commands

From a Linux client, use:

```bash
nslookup google.com
```

Or:

```bash
dig google.com
```

Query a specific DNS server:

```bash
dig @192.168.10.1 google.com
```

Query a specific record type:

```bash
dig google.com A
dig google.com AAAA
dig google.com MX
dig google.com NS
```

On RouterOS, test DNS resolution using:

```routeros
:put [:resolve google.com]
```

The command attempts to resolve the specified hostname and display its resolved address.

# 🗁 Best Practices

* Use reliable upstream DNS resolvers.
* Configure the router as the DNS server for LAN clients when centralized resolution is required.
* Enable `allow-remote-requests` only when needed.
* Restrict DNS access to trusted interfaces.
* Use static DNS records for important internal devices.
* Monitor DNS cache usage.
* Flush DNS cache when troubleshooting stale records.
* Configure DNS separately for different VLANs when required.
* Use DNS over HTTPS when encrypted resolver communication is part of the network design.
* Maintain correct system time for certificate validation.
* Avoid exposing an unrestricted DNS resolver to the Internet.
