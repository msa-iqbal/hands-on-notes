# MTCSE — MikroTik Certified Security Engineer

MTCSE stands for **MikroTik Certified Security Engineer**. It is a MikroTik certification track focused on securing network infrastructure and protecting RouterOS-based networks against unauthorized access, malicious traffic, and common network attacks.

Network security is not limited to configuring firewall rules. A secure network requires multiple layers of protection, including:

* Secure router administration.
* Firewall filtering and traffic control.
* Authentication and authorization.
* Secure remote access.
* Layer two protection.
* Wireless security.
* Logging and monitoring.
* Backup and recovery procedures.

MikroTik RouterOS provides several features for implementing these protections. Understanding how these features interact is essential for designing and maintaining secure networks.

# 🗁 Learning Objectives

After studying this roadmap, you should be able to:

* Understand fundamental network security principles.

* Harden MikroTik RouterOS devices.

* Configure stateful firewall filtering.
* Use address lists for traffic control and threat mitigation.
* Understand Layer two security mechanisms.
* Configure authentication and access restrictions.
* Implement secure VPN connections.
* Protect wireless networks.
* Analyze RouterOS logs and security events.
* Develop practical security auditing procedures.
* Build and troubleshoot secure MikroTik network environments.

# 🗁 Network Security Fundamentals

### 🖆 Core Security Principles

Understand the following security principles:

| Principle | Description |
| --- | --- |
| Confidentiality | Prevent unauthorized access to information. |
| Integrity | Protect information from unauthorized modification. |
| Availability | Keep network services accessible when required. |
| Authentication | Verify the identity of a user or device. |
| Authorization | Determine what an authenticated identity can access. |
| Accountability | Record activities so actions can be traced. |
| Least Privilege | Give users and systems only the permissions they need. |
| Defense in Depth | Apply multiple independent security controls. |

### 🖆 Common Network Threats

Study common threats that affect routers, switches, servers, and network clients:

* Unauthorized administrative access.
* Password guessing and brute-force attacks.
* Port scanning and service enumeration.
* Denial-of-Service attacks.
* Distributed Denial-of-Service attacks.
* IP address spoofing.
* ARP spoofing and poisoning.
* DNS spoofing and manipulation.
* Man-in-the-Middle attacks.
* Malware and botnet communication.
* Rogue DHCP servers.
* VLAN hopping.
* Session hijacking.
* Traffic interception.

### 🖆 Attack Surface

An attack surface is the collection of interfaces, services, applications, and network paths through which an attacker may attempt to access a system.

Examples include:

* SSH and WinBox management services.
* WebFig and API services.
* Open VPN ports.
* Exposed DNS services.
* Unrestricted management interfaces.
* Unnecessary listening services.
* Misconfigured firewall rules.
* Unprotected wireless networks.

Reducing the attack surface is one of the first steps in securing a network device.

# 🗁 RouterOS Service Hardening

### 🖆 Management Services

RouterOS provides several management services:

| Service | Default Port | Purpose |
| --- | ---: | --- |
| FTP | TCP 21 | File transfer |
| SSH | TCP 22 | Secure command-line access |
| Telnet | TCP 23 | Unencrypted command-line access |
| HTTP | TCP 80 | Web management |
| HTTPS | TCP 443 | Encrypted web management |
| WinBox | TCP 8291 | RouterOS graphical management |
| API | TCP 8728 | RouterOS API |
| API-SSL | TCP 8729 | Encrypted RouterOS API |

Disable services that are not required.

### 🖆 Disable Unnecessary Services

Example:

```routeros
/ip service
set ftp disabled=yes
set telnet disabled=yes
set www disabled=yes
set api disabled=yes
```

Keep only the management services required by your environment.

### 🖆 Restrict Management Access

Limit management services to trusted administration networks.

```routeros
/ip service
set ssh address=192.168.10.0/24
set winbox address=192.168.10.0/24
set www-ssl address=192.168.10.0/24
```

The allowed addresses should represent your actual management subnet.

Service-level restrictions should be combined with firewall rules. Neither control should be treated as a replacement for the other.

### 🖆 Secure Administrative Accounts

Follow these practices:

* Avoid using shared administrator accounts.
* Create individual accounts for administrators.
* Use strong, unique passwords.
* Assign the minimum required permissions.
* Disable unused accounts.
* Remove or disable default accounts when appropriate.
* Avoid exposing management services to the public internet.

Example:

```routeros
/user add name=network-admin group=full password="Use-A-Strong-Unique-Password"
```

For production environments, use an appropriate secure credential-management process rather than placing real passwords in scripts or shared documentation.

### 🖆 Secure Router Identity and Software

* Set a meaningful router identity.
* Keep RouterOS updated.
* Use stable and supported RouterOS releases.
* Update RouterBOOT firmware when appropriate.
* Review release notes before upgrades.
* Remove unnecessary packages when supported and appropriate.
* Restrict physical access to router hardware.

Useful commands:

```routeros
/system identity print
/system package print
/system resource print
/system routerboard print
/system routerboard print
```

# 🗁 Firewall Security

### 🖆 Firewall Fundamentals

A firewall controls network traffic according to defined security policies.

RouterOS firewall filtering can protect:

* The router itself.
* Internal network segments.
* Servers and infrastructure services.
* Users accessing external networks.
* Publicly exposed services.

### 🖆 Input Chain Security

The input chain protects the router itself.

A typical secure input policy should:

* Accept established and related connections.
* Drop invalid connections.
* Permit management from trusted networks.
* Permit required infrastructure traffic.
* Allow necessary ICMP traffic.
* Drop unauthorized access.

Example policy for a router with a trusted management subnet:

```routeros
/ip firewall filter
add chain=input action=accept connection-state=established,related comment="Accept established and related"
add chain=input action=drop connection-state=invalid comment="Drop invalid connections"
add chain=input action=accept protocol=icmp comment="Allow ICMP"
add chain=input action=accept src-address=192.168.10.0/24 comment="Allow management subnet"
add chain=input action=drop comment="Drop all other router access"
```

This is an illustrative policy. Before applying a final drop rule, ensure that all required management, routing, VPN, and infrastructure traffic is explicitly permitted.

### 🖆 Forward Chain Security

The forward chain controls traffic passing through the router.

Example:

```routeros
/ip firewall filter
add chain=forward action=accept connection-state=established,related comment="Accept established and related"
add chain=forward action=drop connection-state=invalid comment="Drop invalid connections"
add chain=forward action=accept src-address=192.168.10.0/24 out-interface-list=WAN comment="Allow trusted LAN to WAN"
add chain=forward action=drop comment="Drop other forwarded traffic"
```

Adapt this policy to your routing, VLAN, server, and inter-network requirements.

### 🖆 Output Chain Security

The output chain controls traffic generated by the router.

Examples of router-generated traffic include:

* DNS queries.
* NTP requests.
* RouterOS update checks.
* Syslog messages.
* Monitoring traffic.
* VPN traffic.

A restrictive output policy can improve security, but it requires careful planning to avoid breaking essential router functions.

### 🖆 Firewall Rule Ordering

RouterOS firewall rules are processed in order.

Important considerations:

* Put frequently matched rules where they can be evaluated efficiently.
* Accept established and related traffic early.
* Drop invalid connections.
* Place specific exceptions before general drop rules.
* Use comments to explain each rule.
* Review counters to identify unused or unexpected rules.

### 🖆 Raw Table

The raw table processes packets before connection tracking.

It can be used to:

* Drop unwanted traffic early.
* Exclude selected traffic from connection tracking.
* Reduce connection-tracking workload in suitable scenarios.

Example:

```routeros
/ip firewall raw
add chain=prerouting action=drop src-address=198.51.100.50 comment="Block unwanted source before connection tracking"
```

Use real, verified addresses in production policies.

### 🖆 ICMP Security

ICMP is necessary for several network functions, including diagnostics and error reporting.

Do not blindly block all ICMP traffic.

Understand:

* Echo request and reply.
* Destination unreachable.
* Time exceeded.
* Fragmentation-needed messages.
* IPv6 Packet Too Big messages.

Use controlled ICMP policies that preserve necessary network operation.

# 🗁 Connection Tracking and Stateful Filtering

### 🖆 Connection Tracking Fundamentals

Connection tracking maintains information about network connections.

RouterOS identifies connection states such as:

| State | Description |
| --- | --- |
| New | A packet starting a new connection. |
| Established | Traffic belonging to an established connection. |
| Related | Traffic associated with an existing connection. |
| Invalid | Traffic that cannot be associated with a valid connection. |
| Untracked | Traffic excluded from connection tracking. |

### 🖆 Stateful Firewall Filtering

A stateful firewall evaluates traffic using connection information rather than treating every packet as an entirely independent event.

A common policy is:

```routeros
/ip firewall filter
add chain=input action=accept connection-state=established,related
add chain=input action=drop connection-state=invalid
```

### 🖆 Connection Tracking Configuration

Inspect connection-tracking settings:

```routeros
/ip firewall connection tracking print
```

Inspect active connections:

```routeros
/ip firewall connection print
```

Understand:

* TCP connection tracking.
* UDP connection tracking.
* Connection timeouts.
* Connection table capacity.
* NAT interaction.
* FastTrack interaction.

### 🖆 FastTrack Considerations

FastTrack improves forwarding performance for supported traffic.

However, FastTrack can bypass some firewall processing, queues, accounting, and other features for eligible packets.

Before enabling FastTrack, understand how it interacts with:

* Queue trees and simple queues.
* Traffic accounting.
* Packet marking.
* IPsec policies.
* Monitoring requirements.
* Connection tracking.

# 🗁 Address Lists and Dynamic Blocking

### 🖆 Address List Fundamentals

Address lists group IP addresses and networks for reuse in firewall rules.

Example:

```routeros
/ip firewall address-list
add list=trusted-admins address=192.168.10.0/24
add list=blocked-hosts address=198.51.100.50
```

Use an address list in a firewall rule:

```routeros
/ip firewall filter
add chain=input action=accept src-address-list=trusted-admins comment="Allow trusted administrators"
add chain=input action=drop src-address-list=blocked-hosts comment="Drop blocked hosts"
```

### 🖆 Dynamic Address Lists

Dynamic address-list entries can be created with a timeout.

Example:

```routeros
/ip firewall address-list
add list=temporary-block address=198.51.100.50 timeout=1h
```

Dynamic lists are useful for:

* Temporary blocking.
* Automated security policies.
* Brute-force mitigation.
* Suspicious-source tracking.

### 🖆 Brute-Force Mitigation

Understand how to build a controlled firewall policy that detects repeated unauthorized connection attempts.

A practical design should:

* Identify the protected service.
* Track repeated attempts.
* Apply temporary blocking.
* Avoid blocking trusted administration addresses.
* Log relevant events.
* Include a recovery procedure.

Do not copy arbitrary brute-force scripts without understanding their matching conditions and possible false positives.

Layer two attacks can affect communication within the same broadcast domain.

Study:

* MAC address spoofing.
* MAC table flooding.
* ARP spoofing.
* ARP poisoning.
* Rogue DHCP servers.
* DHCP starvation.
* VLAN hopping.
* Broadcast storms.

### 🖆 Bridge Security

Understand RouterOS bridge features and their security implications.

Study:

* Bridge firewall.
* Bridge port settings.
* Port isolation.
* Horizon.
* VLAN filtering.
* DHCP snooping.
* ARP inspection.
* Bridge protocol handling.

### 🖆 VLAN Security

VLANs provide logical network separation, but VLAN configuration must be correct.

Security practices:

* Use explicit VLAN membership.
* Avoid unnecessary trunk ports.
* Restrict allowed VLANs on trunks.
* Configure access ports for the intended VLAN.
* Avoid using the default VLAN for sensitive management traffic.
* Secure unused switch ports.
* Validate native and untagged VLAN behavior.

### 🖆 DHCP Snooping

DHCP snooping helps protect a network from unauthorized DHCP servers.

Understand the distinction between trusted and untrusted ports.

In supported RouterOS bridge configurations, DHCP snooping can help restrict DHCP server messages to trusted paths.

### 🖆 ARP Security

Study:

* Static ARP entries.
* Reply-only ARP behavior.
* DHCP-to-ARP integration.
* ARP inspection concepts.
* Detection of conflicting IP-to-MAC mappings.

Understand the operational trade-offs before enforcing static or restrictive ARP policies.

# 🗁 Authentication and Access Control

### 🖆 Authentication Fundamentals

Authentication verifies the identity of a user or device.

Common authentication methods include:

* Local username and password.
* SSH public-key authentication.
* RADIUS authentication.
* Certificate-based authentication.
* Multi-factor authentication through supported external systems.

### 🖆 RouterOS User Groups

RouterOS user groups determine administrative permissions.

Inspect users and groups:

```routeros
/user print
/user group print
```

Create a restricted group:

```routeros
/user group add name=read-only policy=read,winbox,ssh
```

Create an account:

```routeros
/user add name=monitor-admin group=read-only password="Use-A-Strong-Unique-Password"
```

Assign only the permissions required for each role.

### 🖆 RADIUS Authentication

RADIUS provides centralized authentication, authorization, and accounting.

It can be used with supported RouterOS services, including:

* PPP.
* HotSpot.
* Wireless authentication.
* Router administrative login.

Example of a RADIUS server configuration:

```routeros
/radius add service=ppp,hotspot address=192.168.10.20 secret="Replace-With-A-Strong-Shared-Secret"
```

For administrative login, configure the relevant service and enable RADIUS authentication according to the RouterOS version and deployment requirements.

### 🖆 AAA

AAA represents:

* **Authentication:** Who are you?
* **Authorization:** What are you allowed to do?
* **Accounting:** What actions or usage should be recorded?

Understand how AAA supports centralized access management and auditing.

# 🗁 VPN and Secure Remote Access

### 🖆 VPN Security Fundamentals

A Virtual Private Network provides protected communication over an untrusted network.

Common use cases:

* Site-to-site connectivity.
* Remote employee access.
* Secure administration.
* Branch-office connectivity.
* Secure infrastructure management.

### 🖆 IPsec

Study IPsec architecture and configuration concepts:

* Security Associations.
* Internet Key Exchange.
* Authentication.
* Encryption.
* Integrity protection.
* Transport mode.
* Tunnel mode.
* Phase one and phase two concepts.
* Proposal and policy matching.
* NAT Traversal.

Understand the difference between IKE and ESP.

### 🖆 WireGuard

WireGuard provides encrypted VPN communication using public-key cryptography.

Study:

* Private and public keys.
* Peer configuration.
* Allowed addresses.
* Endpoint configuration.
* Persistent keepalive.
* Routing requirements.
* Firewall requirements.

Example interface configuration:

```routeros
/interface wireguard add name=wg-secure listen-port=13231
```

Inspect the interface public key:

```routeros
/interface wireguard print detail
```

Add a peer using the remote peer's public key and appropriate addressing:

```routeros
/interface wireguard peers add interface=wg-secure public-key="REMOTE_PUBLIC_KEY" allowed-address=10.20.0.2/32
```

A working VPN also requires correct IP addressing, routing, and firewall policies.

### 🖆 Secure Management Through VPN

A recommended architecture is to expose a VPN endpoint rather than exposing WinBox, SSH, or WebFig directly to the public internet.

After establishing the VPN:

* Restrict management to VPN address ranges.
* Use individual administrator accounts.
* Enable secure management protocols.
* Log administrative access.
* Review VPN peer configurations regularly.

# 🗁 NAT and Security Considerations

### 🖆 NAT Fundamentals

Network Address Translation modifies IP addressing information as traffic passes through a router.

Understand:

* Source NAT.
* Destination NAT.
* Masquerade.
* Port forwarding.
* Connection tracking.
* NAT and firewall interaction.

### 🖆 Port Forwarding Security

Port forwarding exposes an internal service through a public-facing address.

Example:

```routeros
/ip firewall nat
add chain=dstnat action=dst-nat protocol=tcp dst-port=8443 in-interface-list=WAN to-addresses=192.168.20.10 to-ports=443
```

Add a corresponding forward-chain policy that permits only the intended traffic.

Security considerations:

* Expose only necessary services.
* Restrict source addresses where possible.
* Use encrypted application protocols.
* Keep the destination server updated.
* Monitor access attempts.
* Avoid exposing administrative interfaces unnecessarily.

### 🖆 CGNAT Security

Carrier-Grade NAT commonly uses the shared address space:

```text
100.64.0.0/10
```

Understand how CGNAT affects:

* Inbound connectivity.
* Port forwarding.
* Customer isolation.
* Logging and attribution.
* Abuse investigation.
* VPN connectivity.

CGNAT is an addressing and translation mechanism, not a replacement for firewall security.

# 🗁 RouterOS Backup and Recovery

### 🖆 Configuration Backup

RouterOS provides binary backups and text-based configuration exports.

Binary backup:

```routeros
/system backup save name=router-backup
```

Configuration export:

```routeros
/export file=router-config
```

Understand their differences:

| Backup Type | Characteristics |
| --- | --- |
| Binary backup | Restores device configuration in a binary format and is generally intended for the same device or compatible environment. |
| Text export | Produces readable configuration commands that can be reviewed and adapted. |

### 🖆 Backup Security

Protect backup files because they may contain sensitive configuration information.

Recommended practices:

* Store backups in restricted locations.
* Encrypt backup storage where appropriate.
* Limit access to backup files.
* Keep off-device copies.
* Maintain multiple recovery points.
* Test restoration procedures.
* Avoid storing credentials in publicly accessible repositories.

### 🖆 Recovery Planning

Prepare procedures for:

* Router configuration corruption.
* Failed RouterOS upgrades.
* Lost administrative credentials.
* Hardware failure.
* Accidental firewall lockout.
* Unauthorized configuration changes.

Understand Safe Mode and out-of-band management as tools for reducing configuration risk.
