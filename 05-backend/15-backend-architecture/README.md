# Backend Architecture

Practical, structured notes for designing **maintainable, scalable, and resilient backend architectures**.

## Contents

|#|Topic|What You'll Learn|
|---|---|---|
|01|Project Structure|Folder organization, module boundaries, responsibilities, naming, and project organization|
|02|Layered Architecture|Presentation, application, domain, infrastructure layers, responsibilities, and dependency flow|
|03|Clean Architecture|Use cases, entities, boundaries, dependency direction, and framework independence|
|04|Hexagonal Architecture|Ports, adapters, boundaries, dependency inversion, and external integrations|
|05|Dependency Inversion|Dependency direction, abstractions, interfaces, inversion of control, and loose coupling|
|06|Modular Monolith|Module boundaries, internal APIs, shared code, dependencies, and modular monolith patterns|
|07|Microservices|Service boundaries, communication, data ownership, deployment, and distributed-system concerns|
|08|Domain-Driven Design|Domains, subdomains, bounded contexts, entities, value objects, aggregates, and domain services|

## Structure

The notes progress from **project organization → layered architecture → Clean and Hexagonal Architecture → dependency inversion → modular monoliths → microservices → Domain-Driven Design**.

Each topic is separated into focused notes for easier learning, reference, and expansion.

## Focus

- Backend project structure
- Layered architecture
- Clean Architecture
- Hexagonal Architecture
- Dependency inversion
- Module boundaries and coupling
- Modular monoliths
- Microservices architecture
- Domain-Driven Design
- Scalable and maintainable backend systems

## Goal

> Learn backend architecture systematically, design clear boundaries and dependencies, and build maintainable systems that can evolve as applications and teams grow.
