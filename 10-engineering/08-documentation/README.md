# Documentation

Practical, structured notes for understanding and creating **software documentation** that makes code, APIs, architectures, systems, and operational procedures easier to understand, use, maintain, and support.

## Structure

The notes progress from **documentation fundamentals → code documentation → API documentation → architecture documentation → README files → changelogs → runbooks → documentation best practices**.

The first section establishes the purpose, audience, types, and structure of software documentation. Code documentation then focuses on documenting source code, implementation details, comments, and docstrings.

API and architecture documentation cover two important forms of technical communication: describing how software interfaces are used and explaining how systems are structured and interact. README files then focus on providing clear entry points for projects and repositories.

Changelogs document how software evolves across releases, while runbooks provide practical operational procedures for deploying, maintaining, troubleshooting, and recovering systems.

The final section brings these concepts together through practices for keeping documentation clear, discoverable, consistent, maintainable, and synchronized with the software it describes.

Each topic is separated into focused notes for easier learning, reference, practical use, and expansion.
