# Code Review

Practical, structured notes for understanding and applying **code review practices** to improve code quality, maintainability, correctness, collaboration, and software development workflows.

## Structure

The notes progress from **code-review fundamentals → review workflow → review checklists → reviewing and discussing code → pull-request review → code-review best practices**.

The first section establishes the purpose and principles of code review. The workflow section then explains how to prepare, inspect, discuss, revise, and complete a review effectively.

Review checklists provide a structured way to evaluate correctness, readability, security, testing, performance, and maintainability. Reviewing code and giving feedback focus on analyzing changes and communicating actionable observations clearly.

Receiving feedback covers how to interpret review comments, respond to suggestions, and use reviews to improve implementation quality. Pull-request review then applies these practices to collaborative Git-based development workflows.

The final section consolidates practical practices for keeping reviews focused, consistent, efficient, and useful for both code quality and team collaboration.

Each topic is separated into focused notes for easier learning, reference, practical use, and expansion.
